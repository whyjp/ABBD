## Overview

`internal/screen` turns the `.abbd/` store into the blueprint a human reads. `Load` reads the store, `Build` derives a `Model`, and `Files` renders two files. `index.html` is one static page with no script. `graph.json` is the same data for tools. The CLI's `publish` (`cmd/abbd/screen.go`) saves them after every command marked `writes` (`setup`, `sync`, `record relation|unit|parent|fact|evidence`, `retract`, `migrate`, `understand`). `abbd status` reuses `Load` for its freshness verdicts. The package never writes the topology, and the fold boxes it invents never reach the store.

The overview draws each top-level module and feature as a box. A blue line runs from a user's chip on the bottom edge to the provider's chip on the top edge. One chip stands for the contracts that line carries, named when it is one and counted when it is more, and the contracts no line reaches fold into one `+N 계약` chip on the provider, and a thick orange `bypass` line marks a module dependency no contract carries. Two modules that depend on each other that way share one `mutual` line with a head at each end. A relation from a unit at any depth is lifted to the top-level unit that contains it. INFERRED couplings are drawn too, because sync rechecks their quotes. Only dead ones are dropped, and a drifted one is drawn like a live one. A small circle at a line's start marks a reader's or a human's relation, and a dashed line runs against the reading direction. Every top-level module and every unit that holds others has its own view. An overview box links to its view only when `viewOf` names one. A feature with no parts has none, so its box carries no link and its title offers no click. Everything is sorted before it is placed, so the same store always draws the same picture. `docs/blueprint-svg.md` states the drawing rules. `legible_test.go` measures them per line and channel, and `trace_test.go` traces every relation along the drawn ink for bends, crossings, phantom paths, unmarked splits and counts that belong to no single line.

## Key Concepts

- **`Input` / `Model`** (`screen.go`): `Input` is what `Load` reads. `Load` leaves `Tree`, the git snapshot, for the caller to fill. `Model` is what `Build` derives. It holds the unit catalogue, the `Overview`, `Links` between two contracts listed as text, one `Inside` per view, every live relation as `[]Line` for `graph.json`, and both freshness values.
- **`tree`** (`tree.go`): the parent tree the views follow. A unit whose parent is absent moves to the top level, so nothing present drops out. A unit with children and no live relations of its own is abstract, and its box draws its members' relations (`sources`).
- **`fold`** (`fold.go`): a cycle of three or more units in a view becomes one synthetic box, ID `<container>~N`, whose own view draws the cycle. It folds only a cycle that holds at most two thirds of the view, and never on the overview.
- **`overview`** (`overview.go`): the plan `planOverview` builds and the insides reuse. `top` lists the top-level units and the live relations between them. Each contract gets its `providers` and `users`, and each drawn edge keeps the stored relations it stands for and their origins.
- **`Drawing` / `Box` / `Port` / `Wire`** (`overview.go`): one SVG picture with its coordinates set. A `Box` is a top-level module or feature, an inside unit, a fold, or a contract no module provides. Its `Href` opens a view the page holds, and it stays empty when there is none. On the overview, `chipFor` makes one chip per set of contracts a drawn line carries, labelled with its one contract or with `계약 N개` joined by a no-break space so `shorten` keeps the word, and a module whose chips need more than `chipWrap` wraps them into at most two rows instead of widening, and the last row folds what does not fit into one "+N" `Port`. `Wire.Kind` is the CSS class. `Origin`, `Marks`, `Back`, `Both` and `Count` carry the origin circle, the dash, a `mutual` line's second head and a bus's ×N.
- **`arrange`** (`layout.go`): the layered layout. It breaks cycles for ranking only and sets each node above what it uses. It orders layers to cut crossings (`order2`), wraps a layer wider than the width budget (`wrap`) and pulls boxes toward their neighbours (`align`).
- **`route`** (`route.go`): orthogonal routing on that grid. A line crosses each gap on its own track and passes each row between two boxes, or beside the row where it is headed. Lines of one kind that leave one box share a departure trunk through every row two of them still pass. Lines of one kind that reach one box share an arrival bus, and boxes side by side in one row share one only when exactly the same places reach them. Lines that leave and reach one box edge share its slots. Each bus is drawn once with its line count. `place` then sizes each gap, with room beside each stub or drop that carries a count.
- **`junctions` / `anchor`** (`ink.go`): what the routed paths look like to a reader. `junctions` puts a `Dot` wherever ink of one colour goes three or more ways, and where a line crosses onto a trunk that runs past it. `anchor` sets each ×N beside its own stub or drop, on the side where the nearest other ink is farthest.
- **`Inside`** (`inside.go`): one view built by `(*overview).inside`. Its frame carries the contracts of the module or feature it opens and dashed ports for the modules it meets without one. It also holds `Units` with one sentence each, `Unwired` contracts kept off the frame, `Inferred` couplings with their quotes, `Up` and `Trail`, and the `Understanding`.
- **Freshness** (`screen.go`): `ActualFreshness` compares the working-tree snapshot with the synced fingerprint. `BlueprintFreshness` compares the rendered watermark with the inputs hash now.
- **`Understanding`** (`words.go`): a how text cut into `Block`s and `Span`s. It is marked `Stale` when the module's digest has moved. The template escapes it and never trusts its markup.
- **`page` / `Files`** (`page.go`): the embedded Korean template with its labels and tips. `Files` renders both files with the `inputs_hash` watermark.
