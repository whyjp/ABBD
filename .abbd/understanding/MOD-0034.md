## Overview

`internal/screen` turns the `.abbd/` store into the blueprint a human reads: `.abbd/blueprint/index.html`, a single static page with no script, and `.abbd/blueprint/graph.json`, the same data for tools. It only reads the store and never changes the topology. The `abbd` CLI calls it after every command that writes (`setup`, `sync`, `record relation|unit|fact`, `understand`), so the blueprint is always re-rendered from whatever the store holds now. `abbd status` also uses it, only to report freshness.

The page has two levels. The overview draws the top-level modules as boxes, the contracts between them as chips on the box edges, and lines for module-to-module use. A line through a contract is blue. A direct dependency that goes through no contract is a thick orange "bypass" line. Clicking a module opens its "inside": the units it contains, its contracts on a frame around them, the couplings a reader guessed, and the pstack how text stored for it. Everything is deterministic and sorted, so the same data always draws the same picture. The overview also depends only on top-level units and on extracted or human-stated relations, so a change inside a module or a recorded guess never moves an overview box. A human can compare two screenshots and trust that a moved box means the architecture changed.

## Key Concepts

- **`Input`** (`screen.go`): everything the screen reads. It holds the units, the project config, the sync state, the `.abbd` inputs hash, the watermark of the last rendered `graph.json`, the how texts by module, and each module's current code digest. `Tree` (a git snapshot of the working tree) is left for the caller to fill.
- **`Model`** (`screen.go`): what `Build` derives from `Input`. It holds the unit catalogue (`[]UnitRow`), the overview `Drawing`, one `Inside` per module, every live relation (`[]Line`, for `graph.json` only), and two freshness values.
- **`Drawing` / `Box` / `Port` / `Wire`** (`overview.go`): one SVG picture with its coordinates already worked out. A `Box` is a module or an inside unit. A `Port` is a contract chip on a box or frame edge: `Exit` (top) means provided, entry (bottom) means used. A `Wire` is an SVG path whose `Kind` becomes its CSS class (`contract`, `bypass`, `depends_on`, `consumes`, `provides`, plus `guess`).
- **`overview`** (`overview.go`): the plan the overview is laid out from. It holds the top-level modules and contracts, each contract's `providers` and `users`, and the computed `layout`. Insides are built from this same plan.
- **`Inside`** (`inside.go`): the second level for one module. It holds its drawing, its inside units with one responsibility sentence each, its `Unwired` contracts, its `Inferred` couplings with their quotes, and its `Understanding`.
- **`layout`** (`layout.go`): a small layered graph layout (Sugiyama-style). Users sit above what they use, rows are ordered to keep lines short, and lines are routed through the gaps between boxes.
- **Freshness**: there are two separate axes. `ActualFreshness` checks whether the store was synced from the working tree as it is now. `BlueprintFreshness` checks whether the rendered `graph.json` watermark matches the current `.abbd` inputs hash.
- **`Understanding` / `Block` / `Span`** (`words.go`): a how text cut into headings, list items and paragraphs, with `code` and **bold** spans. The template renders it as plain escaped text and never as markup.
