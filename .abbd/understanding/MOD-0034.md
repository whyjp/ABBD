## Overview

`internal/screen` turns the `.abbd/` store into the blueprint a human reads. `Load` reads the store, `Build` derives a `Model`, and `Files` renders two files. `index.html` is one static page with no script. `graph.json` holds the watermark, the unit rows, every live relation, the overview drawing and the full module views, for tools. The CLI's `publish` (`cmd/abbd/screen.go`) runs after every command marked `writes` (`setup`, `sync`, `record relation|unit|parent|fact|evidence`, `retract`, `migrate`, `understand`). It renders nothing for an empty store, and it saves `graph.json` after `index.html` because `graph.json` carries the watermark. `abbd status` reuses `Load`, through the same `screenInput`, for its freshness verdicts. The package imports `internal/model` and `internal/store`, never writes the topology, and draws no box the store lacks, apart from a focus view's twin.

The overview draws each top-level module and feature as a box, and a top-level contract no module provides as a loose box. A blue `contract` line runs from a user's chip on the bottom edge to the provider's chip on the top edge. One chip stands for the contracts that line carries, named when it is one and counted when it is more, and the contracts no line reaches fold into one `+N 계약` chip on the provider. A thick orange `bypass` line marks a module dependency no contract line already carries. Two modules that depend on each other that way share one `mutual` line with a head at each end. A relation from a unit at any depth is lifted to the top-level unit that contains it. INFERRED couplings are drawn too, because sync rechecks their quotes. Only dead ones are dropped, and a drifted one is drawn like a live one. A drawn edge counts as extracted when any relation under it is the script's, else stated, else inferred. A small circle at a line's start marks a reader's or a human's relation, a bundle of both is `mixed`, and a dashed line runs against the reading direction. Every top-level module and every unit that holds others has its own view, and a box links to one only when `viewOf` names it, so no link opens a missing section. A feature with no parts has none. Everything is sorted before it is placed, so the same store always draws the same picture. `docs/blueprint-svg.md` states the drawing rules. `legible_test.go` measures them per line and channel, and `trace_test.go` traces every relation along the drawn ink.

## Key Concepts

- **`Input` / `Model`** (`screen.go`): `Input` is what `Load` reads, including each module's understanding and its code digest now. `Load` leaves `Tree`, the git snapshot, for the caller to fill. `Model` is what `Build` derives. It holds the unit catalogue, the `Overview`, `Links` between two contracts listed as text, one `Inside` per view, the overview's `Focus` views, every live relation as `[]Line` for `graph.json` (`graph.go`), and both freshness values.
- **`tree`** (`tree.go`): the parent tree the views follow. A unit whose parent is absent moves to the top level, so nothing present drops out. A unit with children and no live relations of its own is abstract, and an inside box for it draws its members' relations (`sources`). `within` and `outside` say which child of a view, or which largest unit outside it, stands for an end.
- **`overview`** (`overview.go`): the plan `planOverview` builds and the insides reuse. `top` lists the top-level units and the live relations between them, with the stored relations and origins each drawn edge stands for. Each top-level contract gets its `providers` and `users`, and a module that provides a contract is not drawn as its user.
- **`Drawing` / `Box` / `Port` / `Wire`** (`overview.go`): one SVG picture with its coordinates set. A `Box` is a top-level module or feature, an inside unit, or a loose contract. Its `Href` opens a view the page holds, and it stays empty when there is none. On the overview, `chipFor` makes one chip per set of contracts a drawn line carries, labelled with its one contract or with `계약 N개` joined by a no-break space so `shorten` keeps the word. A module whose chips need more than `chipWrap` wraps them into at most two rows instead of widening, and the last row folds what does not fit into one "+N" `Port`. `settle` then moves a single unfolded row of chips over the x their lines run at. On an inside frame, two ports that land on one spot share a chip, and its `Keys` name every port it stands for. `Drawing.Relations` lists the pairs of places the view requested before routing, which the checker holds the ink to.
- **`arrange` / `layered`** (`layout.go`, `layered.go`): the layered layout. It orders nodes to leave few edges pointing back (Eades, Lin and Smyth), ranks without those edges, and sets each node above what it uses. A node nothing uses sits just above the highest thing it uses, and nodes with no line gather on a bottom layer. Each pair of places more than a row apart gets a `chain` of dummies. `order` sorts every row, chains included, and `wrap` splits a layer wider than the budget. `shed` takes the shortest chains out while the rows are still too wide with every chain crooked. `place` treats each box and each chain as one block, Brandes and Köpf style, keeps a chain crooked when it would swap sides with a straight one, and finds by halving how many of the longest chains stay straight within the budget. A focus view passes a `focusSeat`, so `seat` orders rows by the full view's x, `brick` deals a wide ring into interleaved rows, and `ring` packs each row around the focus on one vertical axis.
- **`route`** (`route.go`): orthogonal routing on that grid. A line crosses each gap on its own track and passes rows down its chain or between boxes. Lines of one kind that leave one box share a departure trunk through every row two of them still pass. Two or more lines of one kind into one box edge share an arrival bus, unless they all ride one departure bus into different boxes, and boxes in one row share one only when exactly the same places reach them. `viaX` keeps a step off a departure track between the two trunks, and `stepX` finds a step onto an arrival track at the nearest clear x. Each bus is drawn once with its line count, and `place` sizes each gap with room for the counts.
- **`junctions` / `anchor`** (`ink.go`): what the routed paths look like to a reader. `junctions` puts a `Dot` wherever ink of one colour goes three or more ways, and where a line crosses onto a trunk of its own kind that runs past it. `anchor` sets each ×N beside its own stub or drop, on the side where the nearest other ink is farthest.
- **`Inside`** (`inside.go`): one view built by `(*overview).inside`, within a 920 pixel budget against the overview's 1320. Its frame carries the module's contracts and dashed `← name` or `→ name` ports for units outside it met without one. Lines from outside units into inside units come in on top. A crowded side hands its least committed ports to the other side, and the frame never grows past the budget. It also holds `Units` with one sentence each, `Unwired` contracts kept off the frame and grouped by a first word that three or more share, `Inferred` couplings with an end in the module or a direct child, `Up` and `Trail`, and the `Understanding` of the module the view is for. Every top-level module and every unit that holds others has a view, so a nested module that holds units shows its text beside its own inside. One that holds none has no view, and `Build` puts its text on its `InsideUnit` in the parent's view, where the page folds it under the unit's entry.
- **`Focus`** (`focus.go`): a view cut from a dense one, which has more than two boxes and more than twice as many relations as boxes. Each module or feature box of a dense overview gets one, and each box of a dense inside. `planOverview` or `inside` plans the full view and keeps only the lines with an end at the focus and the boxes at their other ends, so a focus view never draws a line the full view lacks. A unit that both uses the focus and is used by it is drawn a second time below as a twin, ID `<unit>↓`, and `base` maps it back. Focus views take the overview's width. A focus view of an inside names its boxes by their last path segment. Focus views link each ring box to its own focus view, and stay out of `graph.json`. `Render` gives a copy of each full view to `linkFocus`, which makes each box that opens nothing else open its focus view. `centres` keeps the ring in the full view's order. `TestFocusViewsArePartialGraphsOfTheirView` and `TestFocusViewsKeepTheMapOfTheirView` hold both rules.
- **Freshness** (`screen.go`): `ActualFreshness` compares the working-tree snapshot with the synced fingerprint. `BlueprintFreshness` compares the rendered watermark with the inputs hash now. Either is `UNKNOWN` when a side is missing. `Files` sets the model's blueprint verdict to `CURRENT` before it renders, since the files it writes carry the current watermark.
- **`Understanding`** (`words.go`): a how text cut into `Block`s of headings, list items, paragraphs, pipe tables and fenced code, and `Span`s of plain, `code` and bold text. `blocks` reads the text through `narrative.Lines`, so the page splits it at the headings the readability report counts, and a `#` or `|` line inside a fence stays code. A fenced block becomes one block of kind `pre`, whose `Code` holds its lines as written. A table's `Rows` start with its header, drop the rule line and keep an escaped `\|` in its cell. It is marked `Stale` when its stored digest differs from `store.ModuleDigest`, which hashes the files of the module and of every unit under it at any depth, and the lines around the quotes they cite in other files. The template draws it through `howhead` and `howtext` in both places, and `howtext` draws its blocks with the `blocks` template the notes use too. It escapes the text and never trusts its markup.
- **`Note`** (`notes.go`): one slot note as the page shows it: its heading and key, `Stale` with the places that changed, its blocks and quotes, and for a decision the human's why and source. A note whose slot abbd does not know, or whose file is not where its slot's note belongs, shows nowhere. `placeNotes` runs last in `Build`. A module's notes go in its own `Inside`, or under its entry in its parent's inside when it has none. A contract's go in the inside of its home: the module it sits in when that module provides it, else the provider whose provides relation, its own or one of a unit inside it, rests on the strongest origin, so a reader's coupling never moves a contract away from the provider the code shows. A unit no inside shows keeps its notes on its row of the unit list.
- **`page` / `Files`** (`page.go`): the embedded Korean template with its origin and kind labels and hover tips. `Files` renders both files with the `inputs_hash` watermark.
- **Flows** (`flow.go`): `flows` derives one `FlowView` per stored flow. Steps are numbered by their place, consecutive steps on one unit share a `Lane`, a call shows only when `Step.Against` finds its relation, and a step is STALE when its code moved or `Against` finds a gap. `href` sends a click to the unit's own inside, else to the inside of the nearest unit holding it, else for a contract to its note home's inside. `linkFlows` lists on each inside the steps on the units it holds. `page.html` draws a flow as an HTML numbered list that wraps every line, and lists every flow by its question on the overview. A chip is as wide as its label (`chipWidth`), so no chip is cut.
