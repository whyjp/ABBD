### Overview

`internal/identity` decides which design-unit ID each freshly extracted unit gets. Every extraction (setup, `abbd mode on`, sync) produces units keyed only by the script's local `key`. `Reconcile(stored, renames, extraction, prior, highWater, guesses)` maps them onto the stored `MOD-0001`-style IDs, so approvals, ADRs and relations a human attached to an ID survive refactors. It is pure: no I/O, and its output does not depend on input order.

It first rewrites stored anchors through the git rename map (`applyRenames`). Then it builds every candidate pair of the same kind, sorts the pairs globally (identical anchor set first, then larger overlap, then smaller symmetric difference) and assigns them greedily. Matched units are updated by `merge`. Unmatched input mints a new ID above the per-kind high-water mark, and unmatched stored units are marked `Absent`. Parents and relations are then re-resolved from extraction keys to IDs.

### Key Concepts

- **Takeover rule**: a unit keeps a stored ID when they share two or more anchors (`ov >= 2`) or their anchor sets are identical. The abbd-setup skill tells agents the same rule, and it is why the skill asks for two or more anchors per unit.
- **HighWater**: the largest number ever minted per kind. A deleted ID is never reused.
- **Candidate**: a leftover anchor overlap between a new unit and a stored unit it did not take over. `internal/store` persists it as a merge candidate for a human to resolve.
- **Guesses**: `KeepGuesses` for a re-extraction by the script, which cannot see reader guesses, and `ReplaceGuesses` for setup, whose new supplement owns them. Under `ReplaceGuesses`, an undecided INFERRED purpose, relation or semantic unit the new supplement no longer makes is withdrawn.
- **merge**: the extraction owns anchors, signature, digest and evidence. A human-given or decided purpose or responsibility survives. A renamed EXTRACTED name that a human had confirmed drops back to unconfirmed.
- **Semantic unit**: a unit only a reader vouches for. `kept()` keeps it present across a re-extraction, so its evidence quotes decide whether it lives.
- **setRelations**: extracted relations of reported units are replaced wholesale. Other origins survive, and on duplicates the extracted edge wins.

### Gotchas

- One shared anchor is never enough to keep an ID. It only produces a Candidate. A refactor that rewrites all but one of a unit's files mints a new ID.
- `Reconcile` sorts input by kind and anchor list before pairing. Ties then break by stored index, so equal pairs still resolve deterministically.
- Units the extraction did not report keep their EXTRACTED relations until a human resolves them.
