## Overview

`cmd/abbd` is the ABBD command line. It is one `package main` that dispatches the verbs of its command table over the `.abbd/` directory, where a repository keeps its architecture topology. Humans and assistants run it from a shell, and the block that `abbd install` writes into `CLAUDE.md` points assistants to the `/abbd` skill for how to use it. The usage text calls the CLI a lever. It registers the project's extraction script and proves it deterministic. It keeps unit IDs stable across runs and checks every quoted piece of evidence against the working tree. It records what readers infer and what humans state, refreshes and retracts those claims, and converts an old-format state once. It stores pstack how's module texts, the notes in their slots, and the flows, stacks and tables readers draw, and answers `explain`, `path` and `impact` queries. It never judges, blocks, asks or records a decision. Even `diff --check` only exits 1 when a change reaches the boundary between modules, so a CI job can label the PR, and `status --check` only exits 1 when the state, the blueprint, a module text, a note, a flow's step, a stack's layer or a table's row is STALE or a quote drifted.

### The package is glue. The logic

The package is glue. The logic lives in `internal/`. `model` holds the writers and the precedence table that picks which claim shows, `identity` reconciles IDs, `evidence` checks quotes, `topology` answers queries and diffs, `screen` renders, `store` owns the on-disk format, `gitx` reads git, `extract` parses the script's JSON, `bootstrap` folds in the supplement, and `group` places a crowded level's units in the directories their code lives in. `cmd/abbd` parses argv against a declarative command table, decides which writer each record speaks for, wires those packages together in a fixed order, and prints results line by line. After every verb that writes, `run` calls `publish`, which renders every page of `.abbd/blueprint/` and `graph.json` through `screen.Files`, hands them to `store.SaveBlueprint` in one call, which removes any other file there, then records in the state's `Blueprint` the inputs hash it rendered them from and in `Rendered` the `store.HashRender` of the files it wrote. The tests read the blueprint through `blueprint()` in `helpers_test.go`, every page joined, so a check passes whichever page shows what it asks for. A check that a figure is linked asks for its own page, such as `href="flow-charge.html"`, and `graph()` reads `graph.json`, which holds the data and no drawing. The test binary doubles as the extraction script: run with no arguments, as a repository's extract command, it prints `ROOT.extraction.json` beside that repository, so the tests share no environment variable and run in parallel.

## Key Concepts

- **Command table** (`main.go`): the `commands` map. Each verb names its flags from `flagDefs`, its allowed positional counts, whether it takes `-- ARGV`, and whether it `writes`. `parse` joins the first two words to find verbs like `record unit`, and `parseInterspersed` accepts flags anywhere on the line. A usage error exits 64 and a failed verb exits 1.
- **Sync pipeline** (`main.go`): `syncActual` loads the stored units through `store.Writable`, which refuses an old-format state, then the candidates and the state. It snapshots the tree, reads git renames since the last fingerprint, and runs `identity.Reconcile`. It then runs `evidence.Checker.Apply` and `group.Fallback`, and saves units, candidates and state. It refuses an extraction with no units when units are already stored. After `sync` and `setup`, `attention` prints the drifted and dead evidence counts and each parent conflict.
- **Sync revision** (`main.go`): the revision a drifted item counts from. It stays `state.Revision` while the tree's fingerprint is unchanged, so committing `.abbd/` is no later revision, and becomes `gitx.Head` once the tree changes.
- **Writers** (`main.go`, `setup.go`): `sync` passes `identity.Sync`, so only the script's claims are replaced. `setup` passes `identity.Setup`, so the supplement's claims are replaced too and what `abbd record` wrote stays. A supplement unit that setup no longer reports stays when a human stated something about it, and setup prints it as `kept`.

### Determinism proof

- **Determinism proof** (`setup.go`): `deterministic` runs the script three times and demands identical output. The third run sets new `PYTHONHASHSEED` and `PERL_HASH_SEED` values. A mismatch reports the first differing line, and nothing is saved.
- **Record writer** (`record.go`): `writer` is `human` when `--source` is given and `reader` otherwise. Each writer's claim on an edge or a parent sits beside the others. `recordRelation` refuses a reader's claim on an edge a human stated, and one on an edge the script already claims. With `--phrase` on an edge that already shows, whoever's claim shows there, it stores only the writer's phrase note, which labels the line and is never a claim, and leaves every claim's evidence, via and origin as they were. On an edge that does not show yet it records the claim and the note. It refuses a reader's note that a human's mask hides, and a reader's claim on an edge a human's mask stands on, whatever its via, through `Unit.RelationMasked`, so neither a phrase nor a new via brings back a retracted coupling. It checks the phrase against the via of every claim on the edge, so a phrase on the script's edge cannot restate the script's via. `model.ValidatePhrase` checks the phrase at the command line. `recordParent` refuses a directory group that sync made and a placement that makes a unit its own ancestor. A human's parent stores the script's parent as `over`. When a higher claim still wins, `recordParent` prints where the unit stays.

### Live citation

- **Live citation** (`record.go`): `citations` parses each `PATH:LINES:QUOTE`, normalizes it with `extract.NormalizeEvidence`, and refuses a quote the file it names does not hold now. A unit from `record unit` has a reader's name and stays present until its evidence is dead. Its `--parent` must be a present module or feature, and becomes the reader's parent claim on the unit's own evidence.
- **Refresh and retract** (`record.go`): `refresh` serves `record evidence` on a unit, `ID.parent` or an edge. It replaces the evidence of the reader's claim there. When only the supplement's claim is there, it adds a reader's claim above it, and a supplement unit becomes the reader's. A refreshed unit that is absent comes back unless it was retracted. `retract` removes the writer's own claim on the target and masks each lower INFERRED claim on it, bound to that claim's content. On an edge that still shows after it, because the script's or a higher writer's claim holds it, it saves what it took, returns a `partial` error that says so, as in `retracted the phrase on X. The edge is the script's and stays`, and exits 1, and `run` still renders the blueprint for a `partial`. A run that can change nothing, including one on a target with no claim left, says the target is already retracted and succeeds. It fails only when the claim left is one it may not hide, such as the script's.

### Migrate

- **Migrate** (`migrate.go`): converts an old-format state once, with the supplement setup used (default `.abbd/extractor/supplement.json`) folded onto a fresh extraction. An INFERRED claim becomes the reader's when the supplement makes no claim on the same target, and a parent claim stays the supplement's only when the supplement places the unit in the same parent. A human's parent takes the extraction's script parent as its `over`, which the old format never stored. Every item but the script's that is not live now becomes dead with the reason `dead before migration`. A unit paired with a supplement unit keeps that unit's ref as `supplement_ref`, by which a later setup pairs it again. `ref_test.go` pins that a unit stored under the older `supplement_key` still pairs, and that a unit file spelling both with different refs fails `status`. It writes nothing when the present units, their parents, or the shown relations with their origins would change.

### Query resolution

- **Query resolution** (`query.go`): `find` takes a unit ID, a name, a file, a directory, a symbol or a phrase through `topology.Find`. A match that is not exact prints the best five with reasons. `explain` lists every parent claim when a unit has more than one, and marks each drifted or dead item. For a contract with entries it prints each entry's key, name, shape and need, with the units whose relations use it. `entries_test.go` and `fields_test.go` drive entries through `run` on a scratch repository, the second for a table's fields with their types, need, writers and readers: how sync stores them, the diff lines and the `--check` verdict for each kind of entry change, an entry's note and its row on the page, and the extraction's refusals. `impact` also seeds every other unit anchored at a queried path, and with `--features` prints `topology.ByFeature`: each feature the change reaches, what it holds that is reached, and the reached contracts it uses with the entries it names, then what no feature holds. `explain` names the entries each drawn link it lists uses, so a page's contracts read with the endpoints it calls; `byfeature_test.go` drives both, including a part of a page whose whole use of a contract keeps the page's use whole.

### Sentences

- **Sentences** (`understand.go`): `stampSentences` runs in the shared sync path before the units are saved. It keeps the stamp a module's or feature's purpose and responsibility carried while their words stay the same, and stamps a sentence no stamp covers against the code as it is now, never a human's. `understand ID FILE --sentence TEXT` refuses a text whose first section, by `narrative.Sections`, runs over `narrative.MaxSection`, and stores a reader's new responsibility stamped with the text's digest, unless a person stated the responsibility, which outranks it and stays; it is refused with a note or `--restamp`.

### Diff

- **Diff** (`diff.go`): `abbd diff` compares the units committed at a base, the merge base by default, with the state now through `topology.Compare`. `--unit ID` keeps the changes inside one module or feature through `Diff.Within` and `topology.Subtree`. `--page` writes `.abbd/compare/`: under `base/` the pages `pagesAt` draws from the state committed at the base, which it checks out into `compare/at` with `store.CheckoutAt` since git keeps no pages, a `.gitignore` of `*`, and `index.html`, which opens with a one-line `summary` of the counts, sets the unit's drawing then and now side by side (`drawing` cuts each SVG and the page style out of the two pages, falling back to a page's first drawing when the unit's page is a focus view), and folds the change lines below. The blueprint itself stays the current state. With `--json`, `--page` names its path on stderr so stdout stays JSON. Before a writing command runs, `keepPrevious` has the store keep `.abbd` as it was before the first write since the last commit, and `--base prev` reads the units and the pages from that copy. The tests' `snapshot` of `.abbd` leaves `compare/` out, since nothing there is committed. `--base prev` needs the copy's `HEAD` mark. `abbd review` also lists the units anchored at a file changed since the base (`anchoredAt`, through `gitx.ChangedSince`, a file name with a space included) and seeds from them, since most changes edit code and leave the topology alone.

### Review

- **Review** (`review.go`): `abbd review` prints the change since the base, then who uses each contract or entry the change touched, through `topology.Links` and `topology.EntryUses`, with each user's origin and the feature above it, a user of the whole contract counting for each entry and a removed entry found by the key its name takes; then the direct tier of `topology.ImpactOf` seeded from the units the change added, changed or touched and the units an added or removed relation really joins (`topology.RelationEnds`), or `byFeature` with `--features`; then what is worth a look in a seed, under one, or in a unit that holds one (a removed relation's gone end seeds the nearest unit above it that is still there, and a drifted relation counts by either end of its FROM.KIND.TO subject): a reader's coupling the change added, a STALE text or note, a decision note with no why, skipping the orphaned notes status skips, and drifted evidence from `checkEvidence`, or a line saying the evidence could not be checked. It opens with a one-line headline of its counts, lists of what the change reaches only the units past the seeds, the first 15 (`reachShown`), and always exits 0. With `--markdown` (`reviewMarkdown`) it writes one pull request comment opened by `reviewMarker`: the headline, a mermaid drawing of up to `maxDrawn` touched top-level modules, the counted relations between them and each use of a contract drawn to its provider, what is worth a look, and the whole review folded.

### Evidence and status

- **Evidence and status** (`evidence.go`): `abbd evidence` checks the items of the claims that show, the parent's through `Unit.ShownParent`, and prints each as live, drifted or dead. It never writes, so a drifted item stays drifted. `abbd status` prints whether the state and the blueprint are current, folds its `long:` and `unbacked:` lines into one count each unless `--verbose` (`statusLines` prints them all, and the usage says so), prints a `coverage:` line (`coverage`, through `gitx.LastCommitted`: how many top-level modules and features carry a text, who read them, the oldest commit date of one, and which carry none), names in its `described:` line the present units that record neither a purpose nor a responsibility (`TestStatusReportsUndescribedUnits` holds its count and the IDs it names), and names a state a merge left with two syncs STALE until `abbd sync` on the merged tree. It prints the unit, relation and module-text counts, the drifted and dead items, every mask and every parent conflict. Each dangling phrase gets the retract command its writer needs, with `--source REF` for a human's note. With `--check` it returns an error naming each thing that is behind: a STALE state, blueprint or module text, or drifted evidence. An UNKNOWN state or blueprint fails it too, and the error names the cause: no git work tree, a git error, or a state that does not say what was rendered. A blueprint NOT DRAWN in this checkout, as in a fresh clone, does not fail it while the state it is drawn from is current, since git keeps the state and not the pages. Dead evidence and orphaned texts, whose module `textModule` no longer accepts, are reported and never fail it. `readTexts` reports the readability of the texts that show beside a module, and skips the orphans.

### Uncovered modules

- **Uncovered modules** (`uncovered.go`, `main.go`): `attention`, which `sync` and `setup` run after they write, prints `uncovered:` for each manifest in the working tree, such as `go.mod` or `package.json`, under whose directory no present unit holds an anchor and which no unit holds by a directory anchor over it, so an Android `build.gradle` inside a module anchored on its directory stays quiet. It skips the root's manifest and any under `testdata`, `node_modules` or `vendor`. The line is a warning, and `status --check` never fails on it. It catches a module that an extraction script listing modules by hand does not know. `uncovered_test.go` drives it on a scratch repository.
- **Fingerprint** (`install.go`): a git tree object of the working tree minus `.abbd/`, saved in the state at sync. A nested repository with no commit yet counts by its files on disk that neither repository ignores, as an untracked directory does. `status` reports STALE when it no longer matches the tree. `keepingCurrent` moves it along when `install` edits `CLAUDE.md` while the state is current, and leaves a merged state for sync.

### Understanding
- **Understanding** (`understand.go`): a reader's text for any module or feature (the usage names `MOD-ID|FEAT-ID`), at any depth, stored INFERRED with the reader `--reader` names, such as `abbd reader` or `pstack how 0.15.36`, the digest, `store.CodeFormat` and the per-anchor and per-quote hashes of `store.Stamp`. `textModule` decides which units take a text, for `understand`, `explainHow` and the orphan count in `status`: any present module or feature. A module's digest reads its whole subtree, so a text on a module inside another describes that module's code, and the text of the module above it describes it too. `understand` cleans the text with `store.CleanText` first, so a byte order mark, line endings and trailing blanks do not count, and refuses to store the same text again on changed code. After it stores a text, `readText` prints each section over `narrative.MaxSection` characters and each phrase that reads as history, and never refuses the text for them. `explainHow` shows it with its reader as CURRENT or STALE. With `--history`, under each reader's coupling, `explain` prints `recorded in` with the commit and pull request that first wrote its first quote into the From unit's file (`gitx.Recorded`). `--restamp` stamps the stored text again without a new one, after the extraction moved what the module holds. `mayRestamp` refuses a text stored in an older format, and otherwise allows a restamp only when `store.Changed` finds nothing: every anchor and quote of the module now is one the text was written against, its code unchanged, and none of those is gone.

### Understanding (2)

A retract that moves a place of a quote up a rank changes that place's hash, so it blocks a restamp until a fresh text is stored. A refusal names up to five of them. A restamp keeps the text's hashes. `syncActual` runs `store.UpgradeUnderstandings` after it saves the units, and prints each old text that stays current and each one that goes STALE because the new digest reads code the old one never read, such as the second place of a quote cited twice in one file.

### Notes
- **Notes** (`understand.go`, `record.go`, `evidence.go`, `query.go`): `abbd understand ID.SLOT[.KEY] FILE --evidence ...` parses the address with `model.ParseNoteRef`, keeps the reader `--reader` names, takes only live quotes through `citations`, and stores a `store.Note` stamped by `store.NoteStamp` over those quotes alone. It refuses a quote its file holds more than once, since sync never moves a note's lines. It also refuses the same words, however spaced (`sameWords`), on the same set of quotes, in any order (`sameCitations`), once their code moved, and it keeps a stored `Why` only when the decision cites the same set of quotes; on other quotes it drops the `Why` and says so, since the human spoke about other code. `record fact ID.decisions.KEY` writes that `Why` as a human's, with its source, and leaves the stamp alone. `understand ID.SLOT[.KEY] --reread-by WHO` (`reread`) takes neither a FILE nor quotes: it stamps a STALE note again on the quotes it already cites, keeps its words and `Why`, and records a `store.Reread` of who, the date and the places that had moved. It refuses a current note, an empty WHO, a note whose quote its file no longer holds exactly once, and a note whose stored `Code` keys differ from the ones `NoteStamp` gives its `Evidence`, since a hand edit of its quotes left words written about other code. It moves each quote's lines to where the quote sits now. A note stored with new words drops that record. `noteUnit` holds the check, shared with storing a note, that the unit takes notes and lists the entry.

### Notes (2)

`forget ID.SLOT[.KEY]` finds the note whose file that name gives (`Note.FileRef`), across every unit since a misfiled note is listed under the unit its frontmatter says, removes it with `store.RemoveNote`, and prints whether it was CURRENT, STALE, orphaned or misfiled and the `Why` that went with it. `status` counts the notes, names each STALE one with the quotes whose code changed and how to store it again, stamp it again once reread, or forget it, and fails `--check` on it. It skips orphans, naming each file as it sits and the `forget` that removes it, including a file not at the path its frontmatter names. A file whose directory is no unit ID has no `FileRef`, so `dropNote` names the file to delete instead. It warns about each markdown file there with no frontmatter, and lints notes beside the module texts. `understand` refuses an `entries` note whose key names no entry of the contract, and `status` counts one whose entry the contract no longer lists as orphaned. `explain` prints each note with its reader, its state and who reread it. `skills_test.go` holds both skills to the bundled reader and to commands `parse` accepts. `notes_test.go` and `forget_test.go` drive all of it through `run` on a scratch repository, including where the blueprint puts a contract's notes. `extractor_test.go` runs this repository's own extraction script and reads each unit it prints by its `ref`. `coupling_test.go` runs setup with a supplement whose coupling joins two script units by their refs, refuses one whose two refs name the same unit, and warns when a supplement ref shadows the script's.

### Figures
- **Figures** (`figure.go`, `flow.go`, `stack.go`, `table.go`, `evidence.go`): `abbd flow KEY FILE`, `abbd stack KEY FILE` and `abbd table KEY FILE` store a figure from a draft, and `abbd flow KEY`, `abbd stack KEY` and `abbd table KEY` print the stored one as a draft. Their handlers, `flow`, `stack` and `table`, each run `figure[C]`, for a flow's steps, a stack's layers or a table's rows, so every rule here holds for every kind and its messages take the kind's nouns. `checkFigure` refuses a draft without one question on one line, with fewer or more parts or columns than the kind allows, with a column `model.ValidateColumns` refuses, with a quote the code does not hold exactly once, with a part whose `Gaps` the state shows, or with parts the kind's whole check refuses, such as a unit two layers hold. It moves each quote's lines to where the quote sits now. A quote's `symbol` is not checked. Each part records its writer: with `--source` it is a human's, USER_STATED, else a reader's. `retire` carries the stored figure's `Retired` parts forward with each stored part that is STALE. It keeps each one as its claim's `Retire` gives it, so a retired step keeps no calls. It forgets one whose code is back as written, one of whose own units left the state, or whose files are all gone. It refuses a reader's draft part that says a retired part's words, in any case or spacing and on any unit, and cites a file whose code changed under that part. For a table the cells compare by text whatever column holds them, so renaming a column does not make a retired row new. The refusal holds however many stores ago the part left the figure.

### Figures (2)

A human's store is not refused and clears the retired parts it says again. It cannot tell a reworded part from a re-read one. A human replaces any part. A reader may change a figure with a human's parts only once one is open, which means STALE on its own or named by a gap of the whole figure, such as two layers that hold one unit after it moved under another. Each other human part must come back as written and in its order, so it keeps the human's word. An open part that comes back as written keeps it too, and the question, the column head and the caption must come back as written (`mayReplace`). A column a gap names, such as one whose unit left the state, is open as well, so the reader may drop its unit or point it at another unit. The command prints which human parts it kept and which it replaced, and which of the human's columns it changed, and warns on the kind's `Long` field past 80 characters, a step's `does`, a layer's `role` or any cell of a row. `statusFigures` prints each STALE part with why and says to read that code and store the figure again, and each stray with its reason and how to clear it, and `status --check` fails while a part is STALE. A stack also says how many breaches it holds when it is stored, and `statusBreaches` lists each with its ends, their layers and its origin. A breach never fails the check. A table says how many cells under a unit's column `model.Readings` finds unbacked or unsaid when it is stored, and `statusCells` lists each with its row, its ends and the relation's origin. Neither fails the check, since only a reader of the code can say whether the cell or the graph is wrong.

### Lint
- **Lint** (`lint.go`): `abbd lint [VIEW]` builds the blueprint's model from `screenInput`, as `publish` does, and runs `screen.Lint` on every view or on those VIEW names. It loads `.abbd/lint-debt.yaml` with `LoadLintDebt` and holds the views to it with `screen.Gate`, which marks each hard breach a view owes as debt. It prints each breach and the totals per view and in all, or with `--json` a `lintReport` with its `lintSchema` version, the criteria, the views, the totals, the ceilings and the gate's failures. The ceilings are the weighed sum, the tees, the excess turns, the placement debt, the overflow, the views past one screen, and the detours, and the ceilings line after the totals and `--record` both print all six. The totals line names the tees beside the crossings they count among. The totals line names the detours, the lines that turn back or run beside themselves. It returns an error, so the command exits 1, only when the gate fails: a hard breach past its view's debt, or over every view a total past its ceiling. `lint_test.go` proves both on self's internal/model page, whose rule 13 breach its fixture records as debt, and holds orca src/'s excess turns and steps, which only fall, and the staircases it names, while the report counts each tee among the crossings. `--list` prints the view names from `screen.ViewNames`. `--record` writes `screen.Record` of every view, given the debt file it replaces, with `SaveLintDebt`, the one write lint makes. `lint_test.go` runs the command on this repository, on the fixtures and on copies of the `self` fixture with a debt file written for each case, and checks which gate fails by its message, not by the sums it measures.

### Lint (2)

On Orca's src/ it checks that lint names the circled spot that still turns, the mobile/ line into the Orca runtime, that the top native/ and preload bridge lines and orca CLI's line to the bottom RPC methods chip, now straight, break nothing, and that the bottom edge's lines from desktop main to the connector contract and to native/, which main drops straight, still read as they do, so a change to them shows. Each named breach must name the box at its line's box end by unit ID, the last item of a line into a box and the first of a line out of one. It also checks the excess turns and steps that view measures. The report also carries `levelsOf` the model, `screen.Levels` of the full views lint checked, and prints each advice as a `level VIEW:` line after the totals. `--record` refuses the first debt, when the old debt names no view and no ceiling, while `offLevel` finds a view with a hard breach that a level line says stands at the wrong level, since those breaches come from its units and not from routing. `--keep-level VIEW=REASON`, repeatable through `listFlag`, is the way out for a level the agent can justify: `keptLevels` refuses one without a reason or naming a view with no level line, keeps the reasons the old debt gave for views that still have a level line, and `--record` writes them under `levels` in the debt file. The report then sets each kept view's `Kept` and prints it as `level VIEW: kept, REASON`. `lint_test.go` checks the refusal on Orca's renderer page, the kept levels, a record over an existing debt file, and that `levels` in `--json` leaves features' pages out.

### Lint (3)

It also holds orca src/'s report to the staircases it names and to the totals that view measures, so a routing change that moves them shows there, and since a road drawing is traced along its routes, a change to how lines are traced shows there too.
