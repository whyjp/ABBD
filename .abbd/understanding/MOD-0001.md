## Overview

abbd CLI는 `.abbd` 상태를 읽고 쓰는 프로그램이다. 명령줄 하나를 동사 하나로 바꿔 실행하고, 쓰기 동사가 성공하거나 `retract`가 일부만 거부되면 블루프린트를 다시 그린다. 쓰기 동사는 setup, sync, migrate, record relation·unit·parent·fact·evidence, retract, understand, forget, flow, stack, table이다. 읽기 동사는 explain, brief, path, impact, diff, review, evidence, status, lint다. 다만 `install`은 `CLAUDE.md`를 쓰고, `scope`는 커밋하지 않는 scope 파일을 쓰며, `lint --record`는 `.abbd/lint-debt.yaml`을 쓴다. 모든 동사는 abbd exit codes를 지킨다. 성공하면 0, 명령이 실패하면 1, 명령줄을 해석하지 못하면 64다.

이 모듈은 sync state, module understanding, slot notes, 그리고 `abbd install`이 쓰는 CLAUDE.md abbd block을 제공한다. project.yaml의 추출 argv와 `language`, 그 스크립트가 내는 extraction JSON, unit files, blueprint files, relation key, evidence citation을 쓴다. 저장된 산문은 project.yaml이 정한 언어로 읽혀야 한다. brief가 그 언어를 먼저 알리고, 저장 명령은 다른 언어로 읽히는 글에 `language:` 줄을 찍고, lint는 그런 글을 실패로 잡는다. 각 동사 아래 일은 이웃 모듈이 맡는다. ID 조정, 증거 확인, git 질의, 토폴로지, 렌더링, 저장소가 그렇다. CLI는 스스로 결정을 내리거나 기록하지 않는다. 결정의 이유는 사람의 `--source`가 있어야 저장되고, 틀린 코드 사실은 여기서 철회하지 않고 추출기에서 고친다. 테스트 바이너리는 추출 스크립트를 겸한다. 인자 없이 실행하면 그 저장소 옆에 `ROOT.extraction.json`을 출력하므로, 테스트는 환경 변수를 나누지 않고 병렬로 돈다.

## Key Concepts

### 명령 실행과 sync

- **argv parsing and dispatch** (`cmd/abbd/main.go`): `run`과 `parse`가 `command` 표를 훑어 record relation 같은 두 단어 동사를 잇고, 위치 인자 사이의 플래그를 받으며, `--` 분리는 setup에만 허용한다. 플래그는 `opts`에, 저장소와 출력은 `env`에 담긴다. 해석 오류는 사용법을 찍고 64로 끝난다. 쓰기 동사가 성공하면 `publish`를 부르고, `partial`인 retract도 그린 뒤 1로 끝난다. 그 밖의 실패는 그리지 않고 1을 낸다. 스레드나 타이머는 없고, 해제할 자원도 없다.
- **sync pipeline** (`syncActual`): project.yaml이 지정한 스크립트를 `exec.Command`로 띄우고(타임아웃 없음), JSON을 파싱하고, git 이름 변경을 따라 ID를 조정하고, 증거를 적용하고, 디렉터리 그룹을 더하고, 문장을 찍은 뒤 유닛, 후보, state.yaml을 저장한다. 리비전은 트리 지문이 바뀌었거나 저장된 리비전이 없을 때만 움직인다. 유닛이 저장된 상태에서 유닛 0개짜리 추출은 거부한다. 스크립트 실패는 그 stderr를 담아 실패하고, 재시도하지 않는다.
- **setup determinism proof and supplement fold** (`cmd/abbd/setup.go`): 추출을 세 번 돌리되 마지막은 `PYTHONHASHSEED`와 `PERL_HASH_SEED`를 바꿔 돌리고, 어긋나면 처음 다른 줄을 짚는다. `--supplement`를 루트 기준으로 읽어 스크립트 출력 위에 접고, 증명 뒤에야 argv를 저장하며, setup으로 sync한다. `--`가 없으면 저장된 argv를 다시 쓴다. **migrate**(`cmd/abbd/migrate.go`)는 옛 형식 상태를 한 번 바꾼다. supplement가 쓴 주장(`claims`)을 supplement나 reader에게 나눠 주고, 그래프가 바뀌면 전체를 거부한다.
- **CLAUDE.md abbd block** (`cmd/abbd/install.go`): 어시스턴트에게 블루프린트를 먼저 묻고, sync하고, diff를 남기고, `.abbd`를 커밋하라고 이르는 표시된 글이다. 표시는 혼자 한 줄에 있고 펜스 밖에 있을 때만 센다. 짝 없는 표시는 오류이고, install은 줄바꿈과 파일의 나머지를 지킨다.
- **blueprint publish** (`cmd/abbd/screen.go`): 트리 스냅숏과 함께 화면 입력을 읽어 블루프린트 파일을 쓰고, 입력과 렌더 해시를 상태에 남긴다. 유닛이 없으면 아무것도 하지 않는다.

### 읽기와 기록

- **query commands** (`cmd/abbd/query.go`): 유닛을 ID, 이름, 파일, 심볼, 문구로 찾고 가까운 후보를 나열한 뒤 explain, path, impact를 찍는다. explain은 코드 다이제스트에 견줘 모듈 글을 CURRENT나 STALE로 보이고, impact는 파일에 걸린 유닛을 모두 씨앗으로 삼아 `--features`로 기능별로 묶는다.
- **review commands** (`cmd/abbd/diff.go`, `cmd/abbd/review.go`): diff는 기준 리비전의 유닛과 지금을 비교하고, `--check`에서는 경계 변경만이 실패가 된다. `abbd scope IDS --why TEXT`가 손댈 유닛을 선언하면 review가 변경을 그 옆에 둔다. 범위 밖 유닛과 손대지 않은 선언 유닛을 짚고, STALE인 `constraints` 노트를 다시 읽을 제약으로 이른다. evidence와 status(`cmd/abbd/evidence.go`)는 `checkEvidence`로 생존과 신선도를 쓰지 않고 보고한다.
- **record writers** (`cmd/abbd/record.go`): record relation, unit, parent, fact, evidence와 retract다. 받는 인용은 모두 지금 트리에 있어야 하고, 관계에서는 EXTRACTED가 USER_STATED를, USER_STATED가 INFERRED를 이긴다. 같은 코드의 중복 유닛은 거부한다. `target`은 record evidence와 retract가 다루는 유닛, 필드, 엣지, `.phrase`, `.when`이고, `partial`은 retract가 일부만 거부됐음을 뜻한다. reader의 문구가 프로젝트 언어로 읽히지 않으면 `language:` 줄을 찍는다.

### 글, 노트, 그림

- **texts and notes** (`cmd/abbd/understand.go`, `cmd/abbd/brief.go`): understand는 모듈 글을 코드 다이제스트로 찍어 저장하고, TODO 줄, 다른 섹션, 바뀐 코드에 바뀌지 않은 글은 거부한다. 긴 섹션, 역사 문구, 이름 없는 유닛, 다른 유닛의 경로를 보고한다. brief는 reader가 채울 뼈대를 찍고 `## Read first` 첫 줄에 쓸 언어를 밝힌다. 그 아래에 fan-in 순 핵심 유닛(`keyunits.go`, 20초 제한의 git grep), 런타임 결합 줄(`binding.go`), doc 주석에서 뽑은 상자 초안(`draft.go`)을 덧붙인다. 노트는 한 번만 나오는 인용을 인용하고, flow, stack, table은 그림 작성기 하나를 나눠 쓴다.

### 언어와 lint

- **언어 관문과 lint 보고** (`cmd/abbd/language.go`, `cmd/abbd/lint.go`, `cmd/abbd/phrases.go`): `languageLine`이 쓸 언어를 알리고, `checkLanguage`는 글의 산문 단어 중 그 언어 문자를 품은 단어의 비율이 문턱 아래일 때 `language:` 줄만 찍고 거부하지 않는다. `foreignProse`는 agent가 쓴 사실과 문구, 모듈 글, 노트, 그림 문장 가운데 그 언어로 읽히지 않는 것을 모은다. 문구는 `<ID> phrase <kind> <to>`로 하나씩, 그림은 질문과 캡션 외에 agent가 쓴 part마다(`flow <KEY> step N`, `stack <KEY> layer N`, `table <KEY> row N`) 키를 받고, table은 열 이름도 `table <KEY> columns`로 판정한다. 사람이 쓴 part는 건너뛴다. lint는 블루프린트나 한 뷰의 그림을 부채 파일에 견준다. 모든 뷰를 볼 때는 설명 없는 상자와, 그린 관계에 살아 있는 문구가 없는 개요 줄(`pair`로 묶음)을 나열한다. project.yaml이 `language`를 정하면 `proseGate`가 부채가 지지 않은 외국어 글을 실패로, 이제 읽히는 글을 내릴 수 있는 부채로 이른다. `lint --record`는 그 목록을 `proseDebt`로 `.abbd/lint-debt.yaml`의 `prose`에 남긴다. 언어가 같으면 이전 부채와의 교집합만 남겨 부채는 줄기만 하고, 그 사이 새로 쓴 외국어 글은 부채에 들지 않은 채 몇 개인지 찍힌다. 처음 기록하거나 언어가 바뀔 때만 찾은 것을 모두 받는다.
