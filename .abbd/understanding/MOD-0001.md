## Overview

The abbd CLI is the only program that writes or reads the `.abbd` state. It turns one command line into one verb, runs it, and after every writing verb renders the blueprint again. Its writing verbs are abbd setup, abbd sync, abbd migrate, abbd record relation, abbd record unit, abbd record parent, abbd record fact (a purpose, a responsibility, or an execution context's run, which `model.ParseRun` checks), abbd record evidence, abbd retract, abbd understand, abbd forget, abbd flow, abbd stack and abbd table. Setup and status work in a repository whose .gitignore is a whitelist. `abbd status` counts execution contexts among the kinds, and `abbd diff` counts run-time relations added and removed. `abbd status` counts in its `via:` line the live relations that name no via, which the drawing reads as run-time. Its reading verbs are abbd install, abbd explain, abbd brief, abbd path, abbd impact, abbd diff, abbd review, abbd evidence, abbd status, abbd runtime and abbd lint. Every verb keeps abbd exit codes: 0 on success, 1 when the command fails, 64 when the line does not parse.

It provides sync state, module understanding and slot notes, and the CLAUDE.md abbd block written by abbd install. It uses project.yaml for the registered extraction argv, extraction JSON from that script, unit files, blueprint files, the relation key and the evidence citation. The work below each verb lives in its neighbours: identity reconcile, evidence checks, git queries, topology, rendering and the store. The CLI never judges, blocks, asks or records a decision; a decision's reason needs a human's `--source`, and a wrong code fact is fixed in the extractor, not retracted here. The test binary doubles as the extraction script: run with no arguments, as a repository's extract command, it prints `ROOT.extraction.json` beside that repository, so the tests share no environment variable and run in parallel.

## Key Concepts

### Running a command and syncing

- **argv parsing and dispatch** (`cmd/abbd/main.go`): `run` and `parse` walk the `commands` table, join two-word verbs such as record relation, accept flags between positionals, and allow the `--` split only for setup. A parse error prints the usage and exits 64; a writing verb that succeeds calls `publish`, and a `partial` retract still publishes before it exits 1.
- **sync pipeline** (`syncActual`): runs the script named in project.yaml, parses its JSON, reconciles IDs across git renames, applies evidence, adds directory groups, stamps sentences, then saves units, candidates and state.yaml. The revision moves only when the tree fingerprint does, and an extraction with zero units is refused when units are stored.
- **setup determinism proof and supplement fold** (`cmd/abbd/setup.go`): runs the extraction three times, the last with reseeded hash seeds, and names the first differing line on a mismatch. It reads `--supplement` relative to the root, folds it over the script output, saves the argv only after the proof, and syncs as setup.
- **migrate** (`cmd/abbd/migrate.go`): converts an old-format state once, handing each inferred claim to the supplement or to a reader, and refuses the whole migration if the graph would change.
- **CLAUDE.md abbd block** (`cmd/abbd/install.go`): the marked text that tells an assistant to query the blueprint first, sync, diff and commit `.abbd`. A marker counts only alone on its line and outside fences; install keeps line endings and the rest of the file. The block says the blueprint is drawn at `.abbd/blueprint/index.html` and that `abbd sync` keeps it current, since the pages are committed.
- **blueprint publish** (`cmd/abbd/screen.go`): loads the screen input with the tree snapshot, writes the blueprint files, and records the inputs and rendered hashes in the state. It does nothing when there are no units. The pages are committed with the state, so a fresh clone has them; a checkout that lacks them reads NOT DRAWN in status without failing `--check`.

### Lint

- **lint report** (`cmd/abbd/lint.go`, `cmd/abbd/phrases.go`): `abbd lint` holds the drawings of the blueprint, or of one view, to the debt file, and over every view also lists the units no box describes (`undescribed`) and the overview lines whose relations carry no live phrase (`unphrased`), which say at rest at most a via word such as 데이터, and none for a call or an import. It also lists the plug-point contracts whose relations look recorded the wrong way round (`direction`, `topology.ReversedPlugPoints`): a contract of callback slots that one module provides and several consume via call. That line advises and never fails the gate.

### Reading and recording

- **query commands** (`cmd/abbd/query.go`): resolve a unit by ID, name, file, symbol or phrase, listing near matches, then print explain, path and impact. Path names two units that run on one execution context as only sharing it. Explain shows the module text CURRENT or STALE against its code digest; impact seeds every unit anchored at a file and groups by feature with `--features`.
- **run-time work list** (`cmd/abbd/runtime.go`, `MOD-0058`): `abbd runtime` scans the tree with `internal/runscan`'s catalog, one `Entry` pattern per spawn or channel call of each language, and lists each EXEC, posts_to, runs_on or provides candidate whose sites the state does not cite yet; `--records` prints the raw records. A posts_to candidate counts as stored once a relation quotes one send and one recv of its pair. Setup, sync and status count the open ones on a `runtime:` line, printed only when the catalog finds a candidate and never failing `--check`.
- **review commands** (`cmd/abbd/diff.go`, `cmd/abbd/review.go`): `abbd scope IDS --why TEXT` declares the units a task means to touch, and `abbd review` sets what the change did beside them (`scopeLines`: units outside the scope, named by their top-level unit, and declared units it left alone); its `--markdown` comment draws one line per pair of modules (`edgeLabel`). Review names a STALE `constraints` note as a constraint to read again, and counts any note whose cited file the change edited, though no unit is anchored there, and `understand` stores a `relations` note like any keyed slot.

### Key units

`abbd brief` lists a module's key units by fan-in (`keyUnits`: the types and distinctive functions its non-test files declare, ranked by how often the repository's tracked files in the same languages name them outside the module, dunders left out, through one git grep of at most 40 names that gives up after 20 seconds), and `understand` reports each the text never names; `status` leaves that search out, since it runs in CI. Here they are `env`, `opts` and `command`, which carry a verb's flags and run it, `claims` and `target` in migrate and record, `presentUnit`, `textModule` and `partial`. Explain also names a module's set of build artifacts and who said it, and each coupling's condition, and diff names an artifact that changed. Brief also lists the module's lines that bind at run time (`binding.go`): a load by name, a process started, a registry, a compiled-in bundle, up to five of each kind. Lint also names each overview line, the box pair its distinct drawn relations join, where none carries a live phrase (`phrases.go`), a contract counted on its provider's box. For each box of the module that records neither a purpose nor a responsibility, brief drafts one from the Go doc comment of its anchored symbol, or else its file's header comment (`draft.go`), never from code, a README, a licence or a generated mark,, a lead the reader keeps only where the code bears it out, and lint names every such box as status does. With a CODEOWNERS, review groups the top-level units the change touches or reaches by owner, a catch-all rule giving way to the one for a module's directory. A human's why goes only on a decision; `record fact` refuses one on any other keyed slot. diff compares the units at a base with now, and `--check` exits 1 only on a boundary change. `--page` draws the base's pages again through `pagesAt`, from the state checked out at that revision, since git holds no pages. Evidence and status (`cmd/abbd/evidence.go`) report liveness and freshness without writing, and review, lint, stack and table print what a change reaches and what the drawings breach.
- **record writers** (`cmd/abbd/record.go`): record relation, unit, parent, fact and evidence, and retract, check every quote live and keep EXTRACTED over USER_STATED over INFERRED. A phrase on a shown line stores only a note, and a duplicate unit on the same code is refused.
- **texts and notes** (`cmd/abbd/understand.go`): understand stores a module text stamped with its code digest, refusing placeholder lines, extra sections and unchanged words on changed code, and reports long, unmentioned and misplaced names. Brief prints the skeleton a reader fills, slot notes cite quotes held once, and flow, stack and table share one figure writer.
