## Overview

`internal/gitx` is ABBD's only channel to git. It is one file, `gitx.go`, with nine exported, stateless functions, two private helpers, `run` and `gitlinks`, and one private type, `gitlink`, a submodule's path and recorded commit. Each function runs `git -C <dir> ...` and turns stdout into a string, slice or map. The package exports no types, keeps no state and imports only the standard library. It never writes the user's index, refs or commits.

The central idea is the working-tree fingerprint. `Snapshot` stages the whole working tree into a throwaway index, untracked files included and the `exclude` path left out, then runs `git write-tree`. A submodule enters as the commit the superproject's index records, not the one checked out, so a clean clone of a synced commit snapshots the same tree. Callers pass `store.Dir`, so `.abbd/` never counts. `syncActual` in `cmd/abbd/main.go` stores that tree as `State.Fingerprint` and the result of `Head` as `State.Revision`. On the next sync, `Renames` diffs the stored and fresh trees so `identity.Reconcile` can follow moved files. `screenInput` takes a fresh snapshot so `abbd status` and the blueprint can call the state STALE. `keepingCurrent` in `install.go` snapshots around an edit outside `.abbd/` and moves the fingerprint along only when the state was current. The other functions serve wider reads. `MergeBase` picks the base for `abbd diff`, and `Files` and `Show` let `store.UnitsAt` read unit files at that revision. `WorkingFiles` lists what git would commit. `internal/evidence` uses that list for move candidates, and `topology.Find` uses it when a query names a file.

## Key Concepts

- **`run`** (`gitx.go`): the private helper every function goes through. It runs `git -C dir args...` with extra environment variables appended, captures stdout and leaves stderr unattached, so git's messages are dropped.
- **Snapshot** (`gitx.go`): a tree object of the tracked and untracked, non-ignored files under `dir`, minus `exclude`. `gitlinks` reads each submodule's recorded commit with `git ls-files -s`, the add skips the submodule paths, and `update-index --cacheinfo` puts the recorded commits back. `GIT_INDEX_FILE` points into an `abbd-index-` temp directory that is removed afterwards. Outside a repository it returns an empty string and no error.
- **`Renames`** (`gitx.go`): old to new paths from `git diff-tree -r -M -l0 --name-status -z --relative`. It keeps rename entries and skips copies. Equal or empty trees give an empty map.
- **`ok` result** (`gitx.go`): `Renames` and `Changed` return `ok=false` with no error when `git cat-file -e` cannot find the old tree, usually after `git gc`. `syncActual` then warns that file moves are not detected and carries on.
- **`Changed`** (`gitx.go`): every path that differs between two snapshots, with a moved file listed under both names. Nothing in the repository calls it today.
- **`MergeBase`** (`gitx.go`): tries origin's `HEAD` symbolic ref, then `@{upstream}`, `origin/main`, `origin/master`, `main` and `master`, and returns the first merge base git accepts. When none works it returns an error asking for `--base REV`.
- **`Gitlinks`** (`gitx.go`): every submodule the index records, mapped from its path to the recorded commit, read once by `gitlinks` from `git ls-files -s`. It is empty outside a repository. `store` hashes a submodule by its pin, so a module's digest sees a new pin on every clone, and a directory anchor inside a submodule stands for that pin. `Snapshot` reads the same list.
- **`Head`** (`gitx.go`): the current commit, or an empty string outside a repository or before the first commit.
- **`WorkingFiles`** (`gitx.go`): `git ls-files --cached --others --exclude-standard`. It is the set the fingerprint counts, except that `.abbd/` stays in. It lists a submodule as one path, never lists an ignored file, and returns nil outside a repository, where `store` walks the disk instead.
- **Paths relative to `dir`** (`gitx.go`): every function takes and returns paths relative to the directory it was given, through `-C`, `--relative` and the `./path` form in `Show`. A project root below the repository top still works.
