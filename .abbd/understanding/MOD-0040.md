### Overview

`internal/gitx` is the only place ABBD shells out to git. Every function goes through `run(dir, env, args...)`, which executes `git -C dir ...` with the caller's extra environment and returns stdout. Outside a repository the functions return empty values rather than errors, so ABBD still works in a plain directory, only without rename tracking.

The central idea is the *snapshot*. `Snapshot(dir, exclude)` records the whole working tree, untracked files included, as a git tree object, without touching the user's index or making a commit. The CLI takes a snapshot when a turn starts, between steps and at sync, and stores the tree hash as a fingerprint. `Renames` and `Changed` then compare two such trees. `cmd/abbd` feeds the rename map to `identity.Reconcile`, so a moved file keeps its design-unit ID, and uses the changed paths to tell which units a turn touched.

### Key Concepts

- **run**: the single git runner. Its `env` slice is appended to `os.Environ()`, which is how `Snapshot` redirects the index.
- **Head**: `rev-parse --verify -q HEAD`. It returns `""` before the first commit, and the turn baseline records that as its revision.
- **Dir**: the absolute git directory. `internal/store` puts session state under `<git-dir>/abbd/sessions` with it, so session files never show up in the working tree.
- **Snapshot**: `git add -A -- . :(exclude)<exclude>` into a temporary `GIT_INDEX_FILE`, then `write-tree`. Callers pass `store.Dir` (`.abbd`), so ABBD's own state never counts as a code change.
- **Renames**: `diff-tree -r -M -l0 --name-status -z`. It returns old-to-new paths relative to `dir`. `-l0` lifts git's rename-detection limit.
- **Changed**: `diff-tree --no-renames --name-only`. A moved file appears under both names, so both the old and the new owner see the change.
- **ok flag**: `Renames` and `Changed` return `ok=false` when the old tree no longer exists (`cat-file -e` fails), for example after `git gc` pruned an unreferenced snapshot.

### Gotchas

- Snapshot trees are unreferenced objects. Git may garbage-collect them, and callers must treat `ok=false` as "history lost", not "nothing changed".
- `Snapshot` returns `("", nil)` outside a repository. An empty fingerprint makes `Renames` report no renames.
- `run` captures stdout only, and git's stderr is dropped, so a failing git command shows up as a bare exit error.
