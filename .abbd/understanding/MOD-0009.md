## Overview

`internal/bootstrap` is one file, `overlay.go`, with one exported function, `Overlay`. `abbd setup --supplement FILE` calls it, and so does `abbd migrate`, which needs the supplement to tell its claims from a reader's. By then the command has run the extraction script and parsed its output, and setup has proved the script deterministic. `Overlay` folds the semantic supplement onto that script result. The supplement is JSON that pstack's readers write, and the setup skill puts it at `.abbd/extractor/supplement.json`. The script reports what the code shows mechanically. The readers add what only reading reveals. That covers a unit's purpose and responsibility, units the script cannot see, which module or feature a unit sits in, and couplings through a callback, a config flag or shared data. `Overlay` returns one `extract.Result`, which setup passes through `syncActual` to `identity.Reconcile`. It does no I/O and assigns no IDs.

`Overlay` is a gatekeeper as much as a merger. Anchors always come from the script, and so do the names and signatures of the units the script reports. A reader's signature lands only where the script reads none. Everything the supplement adds gets the writer `supplement`, which is INFERRED, and must tie to code. A unit that matches no script unit needs evidence, and so do a parent and a coupling the script did not extract. When something cannot be tied to code, `Overlay` returns an error that says how to fix the supplement. `setup` then stops before `SaveProject`, so nothing is written. Units that match nothing and cite no evidence are collected and reported together in one sorted error.

## Key Concepts

- **Script result** (`overlay.go`): `base`, the parsed script output. `Overlay` copies its units and relations and gives any keyless unit the key `#<i>`. `newScript` indexes those units by key for matching and parent lookups.
- **Supplement** (`overlay.go`): `doc`, parsed by `extract.ParseSupplement`. It shares the script's schema and checks, but its units may name the key of a script module or feature as their parent. Its other keys are local to the file.
- **Anchor matching** (`overlay.go`): `match` picks the script unit of the same `Kind` that shares the most anchors, compared by `model.Anchor.Key()`, which is `path#symbol`. When the best matches nest, as a package directory holds its sub-modules, the innermost wins. No overlap, or a tie between units that do not nest, is an error. Names are never compared.
- **Semantic unit** (`overlay.go`): a supplement unit with `evidence`, which says the script cannot see it. `semantic()` keeps the supplement's `ref` as `SupplementRef`, by which a re-run of setup finds the stored unit again. It gives the unit the key `supplement:<ref>`, or `supplement#<n>` when it has none, a name by the `supplement` and no digest. It clears the signature and parent for the later passes to set. It is an error if it shares an anchor with a script unit, unless that unit is its named parent or an ancestor of that parent and their anchors differ.

### Supplement parent

- **Supplement parent** (`overlay.go`): a `parent` ref that `resolve` looks up first among the supplement units that landed, then among the script's refs. It must be a module or a feature, the two kinds `model.Kind.Holds` allows. It rests on `parent_evidence`, or else on the unit's own evidence. It goes into the unit's `Placed` as the supplement's claim, so the script's parent stays beside it.
- **Supplement coupling** (`overlay.go`): a supplement relation whose ends `resolve` finds, each among the supplement units that landed and then among the script's refs, so an end the script reports needs no supplement unit of its own. An end it finds in neither is an error naming that ref, and so are two ends that find the same unit, as a supplement unit restating a script unit under a ref of its own and coupled to the script's ref does. `RelationKind.Joins` checks the kind against the two ends' kinds. One the script already extracted is skipped. Any other must cite evidence and is appended with the writer `supplement` and its `Via`. Each relation's phrase, on an extracted edge or not, is appended to `Phrases` with the writer `supplement`, as a note and never a claim. On an edge the script reads, `model.ValidatePhrase` checks the phrase against the script's via too, so it cannot restate it.
- **`Findings`** (`overlay.go`): `Matched` counts the supplement units that landed, semantic ones included. `Conflicts` lists a documented signature the code contradicts, a second supplement unit on the same code, and a supplement ref that names another unit than the script's same ref, which `resolve` then hides. `setup` prints each as a `conflict` line and carries on.
- **Supplement artifact** (`overlay.go`): a supplement unit's `artifact` fills a matched script unit's only when the script read none, written by the supplement, so the build's own reading wins and a sync keeps it.
- **Supplement condition** (`overlay.go`): a supplement coupling keeps its `when`, the condition it holds under, like a script relation.
