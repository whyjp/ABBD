## Overview

`internal/store` is the only code that reads or writes the `.abbd/` directory. A `Store`, built by `Open(projectRoot)`, holds nothing but the path `<project>/.abbd`, and every call goes straight to disk. Its rule sits in the package comment. Markdown with YAML frontmatter is the source, and everything else derives from it. Each unit is one file named after its ID, such as `architecture/MOD-0001.md`. Beside the unit files sit `state.yaml` and `candidates.yaml`, which sync owns, `project.yaml`, the module texts under `understanding/`, and the rendered `blueprint/index.html` and `blueprint/graph.json`. `UnitsAt` also reads unit files at an older revision through `gitx.Files` and `gitx.Show`. The package imports `gitx` and `model`, and imports `identity` only for its `Candidate` type.

The store guards what it keeps. `parseUnit` and `loadUnits` refuse a file whose name does not match its ID, a kind in the wrong directory, a duplicate ID and any unit `model.Unit.Validate` rejects. Every load ends in `model.Resolve`, so callers get each value's origin, each edge's shown claim and each unit's parent. `SaveUnits` resolves and validates each unit before writing it, so the file always splits shown and hidden claims the way a load would. `writeFile` skips a write when the bytes are unchanged. Otherwise it writes a `.tmp` file and renames it over the old one. The store reads two unit formats. `legacy.go` converts an old-format file on load and stays for good, because `abbd diff` reads states committed at older revisions. Every command that changes units, except `abbd migrate`, loads them through `Writable`, which refuses the old format. The store also computes the fingerprints that mark derived views out of date. It has no cache and no lock. Matching lives in `internal/identity`, evidence checks in `internal/evidence` and rendering in `internal/screen`. Its callers are `cmd/abbd`, for nearly every command, and `screen.Load`, which gathers what the blueprint shows.

## Key Concepts

- **Unit file** (`store.go`): `<kind dir>/<ID>.md`. It holds YAML frontmatter with a `model.Unit`, a writer on every value, a generated body with a `# Name` heading and the anchor list, then an optional `## Notes` section the user owns and the store carries through untouched.
- **`Writable`** (`store.go`): `LoadUnits` for a command that will write. It returns `ErrOldFormat`, which points at `abbd migrate`, when any unit file is in the old format. `LoadUnits` reads either format, and `Legacy` also names the units still in the old format, for `abbd migrate`.
- **Old format** (`legacy.go`): a unit whose name has an `origin` and no `writer`, with one parent slot and a `dead` flag on relations. `convert` maps EXTRACTED to `script`, USER_STATED to `human` and INFERRED to `supplement`, and gives a directory group's name to `group`. It marks a dead relation's items dead with `DeadBeforeMigration`, and gives an absent unit `unneeded`, `evidence-dead` or `not-reported`. `regroup` gives the `group` writer each script parent claim that points at a group or sits on one. A human's parent comes out with no `over`, and `abbd migrate` fills it from the extraction.
- **`UnitsAt`** (`store.go`): the unit files as committed at a revision, in either format, which `abbd diff` compares with the current ones. A revision without `.abbd/` has no units.
- **`State`** (`store.go`): `state.yaml`, the sync watermark. `Revision` is the commit where this tree was first synced, and a drifted item dies at a sync of a later one. `Fingerprint` is the `gitx.Snapshot` tree, `MDHash` hashes the unit files, and `HighWater` holds the last number minted per kind.
- **`NextID`** (`store.go`): mints the next number of a kind and saves it to `state.yaml` at once. `abbd record unit` uses it.
- **`InputsHash`** (`store.go`): a SHA-256 over every file under `.abbd/` except `blueprint/`, including the extractor and the understanding texts. The blueprint carries it as a watermark, and `screen` calls the blueprint STALE when the two differ.
- **`MDHash`** (`store.go`): the same hash over the unit files alone. Sync records it in `State`, and no code compares it today.
- **`Understanding`** (`understanding.go`): pstack how's Overview and Key Concepts for one module, with `Unit`, `Origin`, `Digest` and `Code`, the hash of each file the digest read when the text was written, in frontmatter and the text as the body. `abbd understand` writes it as INFERRED, and only for a top-level module.
- **`ModuleDigest`** (`understanding.go`): the first 16 hex characters of a SHA-256 over the code a module's text describes. `moduleCode` collects the module and every present unit under it at any depth, and takes their anchors. A directory anchor stands for the files `gitx.WorkingFiles` lists under it, `.abbd/` left out, or for the files on disk outside a repository. `read` gives a file with LF endings, and a submodule as the commit `gitx.Gitlink` reports, so a directory anchored at a submodule never hashes to nothing. An anchor that extraction derived from the unit's own evidence does not count as a whole file. A quote of a file no anchor covers counts by `evidence.Checker.Around`, the quoted lines and 5 on each side wherever they sit now, so an edit elsewhere in a shared file such as `CLAUDE.md` leaves the text current. A missing file or quote hashes as missing. A text whose `Digest` differs shows as STALE in `abbd status`, `abbd explain` and the blueprint.
- **`Stamp` and `Changed`** (`understanding.go`): `Stamp` returns the digest and the `Code` map, a 16-hex hash of each file the digest reads, a quoted file whole. `Changed` lists what blocks `abbd understand --restamp`: a file of the module now that differs from `Code` or is missing from it, and a file in `Code` that is gone. A file that left the module and still exists does not block it.
- **Digest upgrade** (`understanding.go`): `legacyModuleDigest` is the 0.6 digest, over the whole files cited by a module and its direct children, and the paths it read. `UpgradeUnderstandings`, which `syncActual` runs, looks at each text with no `Code`, so an older ABBD stored it, whose stored digest equals the 0.6 digest now. When the 0.6 digest read, whole, every file the new one reads, the text is stamped with `Stamp` and stays current. Otherwise it is returned as widened, keeps its stamp and reads STALE. A text the old digest called STALE stays STALE.
- **`Project`** (`store.go`): `project.yaml`, the argv of the extraction script that `abbd setup` registers and `abbd sync` runs.
