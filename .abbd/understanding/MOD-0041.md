## Overview

`internal/store` is the only code that reads or writes the `.abbd/` directory. A `Store`, built by `Open(projectRoot)`, holds nothing but the path `<project>/.abbd`, and every call goes straight to disk. Its rule sits in the package comment. Markdown with YAML frontmatter is the source, and everything else derives from it. Each unit is one file named after its ID, such as `architecture/MOD-0001.md`. Beside the unit files sit `state.yaml` and `candidates.yaml`, which sync owns, `project.yaml`, the module texts under `understanding/`, and the rendered `blueprint/index.html` and `blueprint/graph.json`. `UnitsAt` also reads unit files at an older revision through `gitx.Files` and `gitx.Show`. The package imports `gitx` and `model`, and imports `identity` only for its `Candidate` type.

The store guards what it keeps. `parseUnit` and `LoadUnits` refuse a file whose name does not match its ID, a kind in the wrong directory, a duplicate ID and any unit `model.Unit.Validate` rejects. `SaveUnits` validates before writing. `writeFile` skips a write when the bytes are unchanged. Otherwise it writes a `.tmp` file and renames it over the old one. The store also computes the fingerprints that mark derived views out of date. It has no cache and no lock. Matching lives in `internal/identity`, evidence checks in `internal/evidence` and rendering in `internal/screen`. Its callers are `cmd/abbd`, for nearly every command, and `screen.Load`, which gathers what the blueprint shows.

## Key Concepts

- **Unit file** (`store.go`): `<kind dir>/<ID>.md`. It holds YAML frontmatter with a `model.Unit`, a generated body with a `# Name` heading and the anchor list, then an optional `## Notes` section the user owns and the store carries through untouched.
- **`UnitsAt`** (`store.go`): the unit files as committed at a revision, which `abbd diff` compares with the current ones. A revision without `.abbd/` has no units.
- **`State`** (`store.go`): `state.yaml`, the sync watermark. `Revision` is the commit where this tree was first synced, `Fingerprint` is the `gitx.Snapshot` tree, `MDHash` hashes the unit files, and `HighWater` holds the last number minted per kind.
- **`NextID`** (`store.go`): mints the next number of a kind and saves it to `state.yaml` at once. `abbd record unit` uses it.
- **`InputsHash`** (`store.go`): a SHA-256 over every file under `.abbd/` except `blueprint/`, including the extractor and the understanding texts. The blueprint carries it as a watermark, and `screen` calls the blueprint STALE when the two differ.
- **`MDHash`** (`store.go`): the same hash over the unit files alone. Sync records it in `State`, and no code compares it today.
- **`Understanding`** (`understanding.go`): pstack how's Overview and Key Concepts for one module, with `Unit`, `Origin` and `Digest` in frontmatter and the text as the body. `abbd understand` writes it as INFERRED, and only for a top-level module.
- **`ModuleDigest`** (`understanding.go`): the first 16 hex characters of a SHA-256 over the files cited by the anchors and evidence of a module and of its direct children, with absent units left out. A missing file hashes as missing. A text whose `Digest` differs shows as STALE in `abbd status`, `abbd explain` and the blueprint.
- **`Project`** (`store.go`): `project.yaml`, the argv of the extraction script that `abbd setup` registers and `abbd sync` runs.
