## Overview

The store is the one package that reads and writes the `.abbd` directory (`Project` also holds the project's `Name` and `Purpose` from project.yaml, and `ProjectDir` names the project root it sits in; `InputsHash` counts the CODEOWNERS `owners.File` finds there as an input, since the pages name owners), where Markdown with YAML frontmatter is the source and everything else derives from it. It provides unit files (one file per unit under architecture or features), sync state in state.yaml, project.yaml with the registered extraction argv, module understanding texts, slot notes, and the stored flows, stacks and tables. It also keeps the merge candidates file, the lint debt, the blueprint pages, committed beside the state they are drawn from, and the copy of `.abbd` that the compare view reads as the previous state.

It stamps texts, notes and figure parts against the code they describe, so a reader of the state can tell CURRENT from STALE, and it hashes its own inputs so the blueprint can tell when it is stale. It uses git queries for the files at a revision, the submodule pins and the snapshot, the evidence checker for the lines around a quote, the unit model for units, claims and evidence, and the candidate shape from identity. It does not decide anything about the units it holds: it never reconciles IDs, runs the extraction, judges a text's contents or writes code.

## Key Concepts

### Unit files and state

- **unit notes section** (`renderUnit`): a unit file is frontmatter, a generated title and anchor list, then the human part from the `## Notes` heading on, which `parseUnit` splits off on read and appends unchanged on write. Old-format files stay readable through `internal/store/legacy.go`, since a diff reads states committed long ago.
- **units at a revision** (`UnitsAt`): reads and parses the committed unit files at a revision through git, so a revision without `.abbd` has no units.
- **ID high-water mark** and **ID high-water minting** (`NextID`): state.yaml keeps the last number minted per kind so a number never returns; `NextID` bumps it for a hand-recorded unit and saves the state. `LoadState` reads a merged state by dropping conflict markers and keeping the higher high water.
- **blueprint pages** (`SaveBlueprint`, `CheckoutAt`): `SaveBlueprint` writes one render's pages and removes every other file there, except a `.gitignore` other than the `*` an earlier abbd wrote to keep the pages out of git (`foreignIgnore`), and `BlueprintHash` skips any `.gitignore`. `CheckoutAt` writes the `.abbd` committed at a revision, its pages aside, into a directory and opens a store there, so `abbd diff --page` can draw the base again in the renderer of now.
- **merge candidates file** (`LoadCandidates`): candidates.yaml lists each new unit that shares an anchor with an existing one, written as an empty list rather than left absent.
- **no-op-aware atomic write** (`writeFile`): every write skips a file whose bytes are already equal, and otherwise writes a .tmp sibling and renames it into place, so the same state writes the same bytes.

### Staleness

- **store staleness hashes** (`InputsHash`): hashes every `.abbd` file a page can render, leaving out the blueprint, the state, the lint debt and the compare view, where `scope.yaml` holds the `Scope` that `LoadScope` and `SaveScope` read and write for `abbd scope`, kept out of git; `HashRender` hashes files by name with CRLF read as LF, so a converted checkout stays current.
- **module code digest** (`internal/store/understanding.go`): `Stamp` records one hash per anchor of the module and of every unit under it, a directory as one hash of the paths under it, and each quote as the lines around it, and the digest hashes them all. `ModuleDigest` compares a stored text, `Changed` lists what moved, and `UpgradeUnderstandings` carries older texts forward only when their code is shown unchanged.
- **slot notes and figures** (`internal/store/note.go`): a note or a figure part is stamped only against the places it cites, a quote held more than once counting as missing, so an edit near one note stales that note alone; `internal/store/figure.go` stores flows, stacks and tables with a stamp per part.
