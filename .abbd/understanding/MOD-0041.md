## Overview

`internal/store` is the only code that reads or writes the `.abbd/` directory. A `Store`, built by `Open(projectRoot)` once per command, holds the path `<project>/.abbd` and a `codebase`, the project's code as that command reads it. Calls on `.abbd/` go straight to disk. Its rule sits in the package comment. Markdown with YAML frontmatter is the source, and everything else derives from it. Each unit is one file named after its ID, such as `architecture/MOD-0001.md`. Beside the unit files sit `state.yaml` and `candidates.yaml`, which sync owns, `project.yaml`, the module texts under `understanding/`, the figures under `flows/`, `stacks/` and `tables/`, and the rendered `blueprint/`: the pages and `graph.json`. `SaveBlueprint` writes the files of one render and removes every other file there, so the page of a module that left the state goes with it, and `blueprint_test.go` holds that. `UnitsAt` also reads unit files at an older revision through `gitx.Files` and `gitx.Show`. The package imports `evidence`, `gitx` and `model`, and imports `identity` only for its `Candidate` type.

### The store guards what it keeps

The store guards what it keeps. `parseUnit` and `loadUnits` refuse a file whose name does not match its ID, a kind in the wrong directory, a duplicate ID and any unit `model.Unit.Validate` rejects. Every load ends in `model.Resolve`, so callers get each value's origin, each edge's shown claim and each unit's parent. `SaveUnits` resolves and validates each unit before writing it, so the file always splits shown and hidden claims the way a load would. `writeFile` skips a write when the bytes are unchanged. Otherwise it writes a `.tmp` file and renames it over the old one. The store reads two unit formats. In the current one, `parseUnit` also reads a unit's supplement ref spelled `supplement_key` into `SupplementRef`, and the next save writes it as `supplement_ref`. It refuses a relation that still carries the old `phrase:` field, through `oldPhrase`, and says to move it to `phrases:`, so the phrase is not dropped without a word. It refuses a file that spells both with different refs, as the extraction refuses a unit with a different `ref` and `key`, since either could be the one setup pairs on. `legacy.go` converts an old-format file on load and stays for good, because `abbd diff` reads states committed at older revisions. Every command that changes units, except `abbd migrate`, loads them through `Writable`, which refuses the old format. The store also computes the fingerprints that mark derived views out of date. Its only cache is the `codebase`, and it has no lock. Matching lives in `internal/identity`, evidence checks in `internal/evidence` and rendering in `internal/screen`. Its callers are `cmd/abbd`, for nearly every command, and `screen.Load`, which gathers what the blueprint shows.

## Key Concepts

- **Unit file** (`store.go`): `<kind dir>/<ID>.md`. It holds YAML frontmatter with a `model.Unit`, a writer on every value, a generated body with a `# Name` heading and the anchor list, then an optional `## Notes` section the user owns and the store carries through untouched.
- **`Writable`** (`store.go`): `LoadUnits` for a command that will write. It returns `ErrOldFormat`, which points at `abbd migrate`, when any unit file is in the old format. `LoadUnits` reads either format, and `Legacy` also names the units still in the old format, for `abbd migrate`.
- **Old format** (`legacy.go`): a unit whose name has an `origin` and no `writer`, with one parent slot and a `dead` flag on relations. `convert` maps EXTRACTED to `script`, USER_STATED to `human` and INFERRED to `supplement`, and gives a directory group's name to `group`. It marks a dead relation's items dead with `DeadBeforeMigration`, and gives an absent unit `unneeded`, `evidence-dead` or `not-reported`. `regroup` gives the `group` writer each script parent claim that points at a group or sits on one. A human's parent comes out with no `over`, and `abbd migrate` fills it from the extraction.
- **`UnitsAt`** (`store.go`): the unit files as committed at a revision, in either format, which `abbd diff` compares with the current ones. A revision without `.abbd/` has no units.

### State

- **`State`** (`store.go`): `state.yaml`, the sync watermark and the one file every sync rewrites. `Revision` is the commit where this tree was first synced, and a drifted item dies at a sync of a later one. `Fingerprint` is the `gitx.Snapshot` tree, `Blueprint` is the `InputsHash` the blueprint was rendered from, `Rendered` is the `HashRender` of the files that render wrote, and `HighWater` holds the last number minted per kind.
- **`LoadState`** (`store.go`): reads `state.yaml` line by line, so it also reads a state a merge left with both sides' lines, by `merge=union` or as conflict markers. It drops each line `conflictMarker` names, walks the mapping with `pairs`, keeps each key's first value and the higher high water of each kind. It sets `Merged`, which is never written, when it dropped a marker or a key held two values, and a merged state reads STALE until `abbd sync` writes one state on the merged tree. `state_test.go` reads a union-merged state and one with conflict markers and CRLF endings, and checks a saved state reads back unmerged.
- **`NextID`** (`store.go`): mints the next number of a kind and saves it to `state.yaml` at once. `abbd record unit` uses it.

### InputsHash

- **`InputsHash`** (`store.go`): a SHA-256 over every file under `.abbd/` except `blueprint/`, `compare/` (`CompareDir`, the view `abbd diff --page` writes, and `PreviousDir` inside it, where `KeepPrevious` copies `.abbd` before the first write since the commit it records in a `HEAD` file, building the copy in `prev.tmp` and renaming it into place), `state.yaml` and `lint-debt.yaml`, including the extractor and the understanding texts. It reads CRLF as LF, so a Windows checkout that converts line endings hashes the same. `publish` records it in `State.Blueprint`, and `screen` calls the blueprint STALE when it differs from the hash now.
- **`HashRender` / `SaveBlueprint` / `BlueprintHash`** (`store.go`): `HashRender` hashes files by name, reading CRLF as LF, and `InputsHash` and `BlueprintHash` both go through it. `SaveBlueprint` writes the rendered files and removes every other entry under `blueprint/`, and `publish` records the `HashRender` of what it wrote in `State.Rendered`. `BlueprintHash` hashes the files under `blueprint/` now, and is empty when there are none, so a page missing, added, edited by hand or checked out from an older render no longer matches the state and reads STALE.

### Understanding

- **`Understanding`** (`understanding.go`): a reader's Overview and Key Concepts for one module or feature, at `UnderstandingFile` from the project root, with `Unit`, `Origin`, the `Reader` who wrote it (left out when none was named), `Digest`, `Format` and `Code`, the hash of each anchor and quote the digest read when the text was written, in frontmatter and the text as the body. `abbd understand` writes it as INFERRED, for a module or a feature at any depth. `SaveUnderstanding` refuses a text with an empty digest, which would read current whatever the code did. `CleanText` strips a leading byte order mark and gives every text LF line endings and no trailing blanks, on save, on load and before `abbd understand` compares a new text with the stored one.

### Note

- **`Note`** (`note.go`): what a reader wrote into one slot, at `understanding/<ID>/<SLOT>.md`, with the `Reader` who wrote it, its `Evidence`, the `Code` and `Digest` of `NoteStamp`, a human's `Why`, and a `Reread` record of who read a STALE note's code again and kept its words, when, and what had moved. `NoteStamp` runs `stamp` over a `moduleCode` with no anchors, so a note's code is only the lines around each quote it cites. Sync never moves a note's lines, so a quote its file no longer holds exactly once counts as missing rather than as whichever copy sits near the old lines. `digestOf` hashes a `Code` map for both stamps. `LoadNotes` reads every note in slot order and fills `Changed` with each cited place whose hash moved, so status, explain and the screen read one answer to whether a note is STALE. It records each note's `File` as found. A file not at `NoteFile` of its frontmatter's unit and slot is `Misfiled` and not `Known`, so `LoadNote` never takes it for its slot's note. A markdown file there that does not open with frontmatter is no note: `readFrontmatter` returns `errNoFrontmatter`, and `LoadNotes` returns the path among its strays rather than failing. A file that opens frontmatter and is malformed still fails. `FileRef` names a note by where its file sits, so a misfiled note can be named. It gives a name only when the file's directory is a unit ID, which holds no dot, so no two files share one. `SaveNote` refuses a note that cites nothing. `RemoveNote` deletes a note's file, and its unit's directory once that is empty.

### codebase

- **`codebase`** (`understanding.go`): one command's read of the project's code. It lists `gitx.WorkingFiles` and `gitx.Gitlinks` once, `.abbd/` left out, or walks the disk outside a repository. git lists an untracked repository inside the project as its directory, with a trailing slash, and `list` walks that directory instead. `walk` skips a `.git` directory and leaves out a `.git` file, the gitfile of a worktree or submodule checkout, while still walking the files beside it. It hashes each path once, so `status`, `sync` and the blueprint read each file once however many texts they check. `read` gives a file with LF endings and a submodule as `submodule <commit>` from the index, so an edit inside a submodule counts once it is committed there and staged.
- **`moduleCode`** (`understanding.go`): the code a module's text describes. It collects the module and every present unit under it at any depth, and takes each anchor once. A file anchor reads the file. A directory anchor reads the paths git lists under it, a submodule as one path. When git lists nothing there, `under` falls back to the enclosing submodule's pin or, for an ignored directory, to the files on disk, and marks the anchor `fallback`. An anchor that extraction derived from the unit's own evidence does not count as a whole file. The cited quotes count in files no anchor covers.

### Stamp, ModuleDigest and Changed

- **`Stamp`, `ModuleDigest` and `Changed`** (`understanding.go`): `Stamp` returns the `Code` map and the digest over it. A file anchor maps to its file's hash, a directory anchor to one hash of every path and hash under it, and each place a quote is cited to the hash of `evidence.Checker.Around`, the quoted lines and 5 on each side wherever they sit now. `quotes` orders the places of one quote in a file by line, and the key is `path#quote-<hash>`, where the hash covers the quote and, from the second place on, which place it is. Counting places rather than lines keeps a key when code above the quote moves it down. An edit elsewhere in a shared file such as `CLAUDE.md` changes neither. The digest is the first 16 hex characters of a SHA-256 over the sorted map, so it reads exactly what `Code` records. `ModuleDigest` is that digest. A text whose `Digest` differs shows as STALE in `abbd status`, `abbd explain` and the blueprint. `Changed` lists what blocks `abbd understand --restamp`: an anchor or quote now whose hash differs from `Code`, naming a directory anchor as code under it, one missing from `Code`, and one in `Code` whose path is gone. One that left the module while its path still exists does not block it. A place's key counts its rank among the places cited, so when the unit citing an earlier place leaves, the place left takes that place's key and blocks a restamp. The hashes cannot show which code a place read before: a place can also take another's lines when its own quote is edited away or when code is swapped. So only a fresh text clears it.

### Digest upgrade

- **Digest upgrade** (`understanding.go`): `UpgradeUnderstandings`, which `syncActual` runs, looks at each text not in `CodeFormat`. A text with no `Code` came from ABBD 0.6, and `legacyModuleDigest` recomputes its digest over the whole files cited by a module and its direct children. A format 1 text recorded a hash per file, and `format1Digest` recomputes its digest, where a directory git lists nothing under read nothing. A format 2 text recorded the hashes `Stamp` records now, except that `quotesOnce` kept one place of a quote cited at several, and `stampQuotes` recomputes its digest that way. When the old digest matches and read every file and every quoted place the new one reads, the text is stamped again in the current format and stays current. When it matches but the new digest reads more, such as a fallback directory or the second place of a quote cited twice, the text is returned as widened, keeps its stamp and reads STALE. A text the old digest called STALE stays STALE.
- **`Project`** (`store.go`): `project.yaml`, the argv of the extraction script that `abbd setup` registers and `abbd sync` runs.

### LintDebt

- **`LintDebt`** (`store.go`): `lint-debt.yaml`, what the drawings owe the drawing criteria. It holds each view's hard breaches by criterion, the ceilings of the gated totals (the weighed sum, the tees, the excess turns, the placement debt and the detours, as the file's header says), under `pages` the totals each page a reader looks at may not raise, and under `levels` the reason the repository keeps each view at a level abbd lint would change. `LoadLintDebt` reads none when the file is missing. `SaveLintDebt` writes it under a comment that says what the file is. No page draws it, so it is no input of the blueprint.

### Figures
- **Figures** (`figure.go`): every figure a reader or a human stores, a flow at `flows/<KEY>.md`, a stack at `stacks/<KEY>.md` or a table at `tables/<KEY>.md`. A `Figure[C]` holds a question, the `Columns` of a kind that has a head, the ordered `Parts` and the `Retired` parts of one kind of claim, and the caption as the file's body, and `Flow`, `Stack` and `Table` name the three kinds. Each `Part[C]` is a claim with its `Stamp`: its own `Writer`, `Source` and `Code`. `SaveFigure` sets `Code` with `NoteStamp` over each part's evidence and refuses a part that cites no code, so loading fills `Changed` per part, and `Moved` with the files of those places, and an edit near one part's quotes stales that part alone. A part with no evidence or no `Code` reads STALE, and one with no writer reads as a reader's. `Part.Why` joins the changed places with the claim's gaps against the state, the one reason status, the page and a reader's replace all read. `Figure.Origin` is USER_STATED only when a human wrote every part, and `Figure.Gaps` runs the kind's check over all its claims and its head and returns each `model.Gap` with the places of the parts it involves. `changed` compares a stamp with what was written, for notes and parts alike. `Retired` holds the parts that went STALE and left the figure, each with its claim and the `Code` it was written against, and loading fills their `Changed` and `Moved` too, so a command can drop one whose code is back as it was written and refuse a part that repeats one on a file whose code changed.

### Figures (2)

`encodeFigure` writes the frontmatter in the order a reader reads it: the question, the format, the columns when there are any, the parts under the kind's own key and the retired parts. So a flow file keeps the bytes it had before figures had kinds, which `figure_test.go` pins on this repository's own flow, and `decodeFigure` reads the same keys. `ParseFigureDraft` keeps only a draft's question, columns, parts and caption, so a draft can neither add nor clear `Retired`, and `FigureDraft` prints a stored figure back as a draft. `LoadFigures` reads every kind into `Figures` and is the store's one list of kinds, and `LoadFigure[C]` reads one figure. A file there with no frontmatter, or whose frontmatter does not parse, is a `Stray` with its reason, so one bad file stops no reader of the others. One whose name is no figure key is read but not `Known`.
