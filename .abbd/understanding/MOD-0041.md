## Overview

`internal/store` is the only code that touches the `.abbd/` directory on disk. Every other package works on in-memory `model.Unit` values and goes through a `store.Store`, which holds nothing but the path `<project>/.abbd`. The package's rule is in its doc comment: Markdown files with YAML frontmatter are the source, and everything else derives from them. Each design unit (module, contract or feature) is one file named after its ID, such as `architecture/MOD-0001.md`. Next to those files, the store keeps a few YAML files that sync owns (`state.yaml`, `candidates.yaml`), the project config (`project.yaml`), pstack how's text about each module (`understanding/MOD-xxxx.md`), and the rendered blueprint (`blueprint/index.html`, `blueprint/graph.json`).

Apart from reading and writing these files, the store produces the fingerprints ABBD uses to say when something is out of date. It hashes the `.abbd` inputs so the blueprint can tell it is STALE. It hashes the code files a module cites so a stored understanding can tell it was written against older code. It keeps a per-kind high-water mark so an ID number is never handed out twice. It has no cache, no lock and no business logic. Matching units across syncs lives in `internal/identity`, evidence checks in `internal/evidence`, and rendering in `internal/screen`.

## Key Concepts

- **`Store`**: a value that holds the `.abbd` root path. `store.Open(projectRoot)` builds one, and every call reads or writes the disk directly.
- **Unit file**: `<kind dir>/<ID>.md`. It has YAML frontmatter (a `model.Unit`), then a body the store generates (an `# Name` heading and the anchor list), then an optional `## Notes` section that belongs to the user and is carried through untouched.
- **`State`** (`state.yaml`): the sync watermark. `Revision` is the commit where this tree was first synced, `Fingerprint` is a git tree of the working tree excluding `.abbd`, `MDHash` hashes the unit files, and `HighWater` is the last number used for each kind.
- **`Understanding`** (`understanding/<MOD-ID>.md`): pstack how's Overview and Key Concepts for one top-level module. It is always INFERRED and stamped with a `Digest` of the module's code.
- **Fingerprints**: `InputsHash` covers everything under `.abbd` except `blueprint/` and tells whether the blueprint is current. `ModuleDigest` covers the code a module cites and tells whether its understanding is current. `MDHash` covers the unit files.
- **`Project`** (`project.yaml`): the argv of the project's extraction script, which `abbd sync` runs.
