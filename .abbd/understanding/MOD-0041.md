## Overview

`internal/store` is the only code that reads or writes the `.abbd/` directory. A `Store`, built by `Open(projectRoot)` once per command, holds the path `<project>/.abbd` and a `codebase`, the project's code as that command reads it. Calls on `.abbd/` go straight to disk. Its rule sits in the package comment. Markdown with YAML frontmatter is the source, and everything else derives from it. Each unit is one file named after its ID, such as `architecture/MOD-0001.md`. Beside the unit files sit `state.yaml` and `candidates.yaml`, which sync owns, `project.yaml`, the module texts under `understanding/`, and the rendered `blueprint/index.html` and `blueprint/graph.json`. `UnitsAt` also reads unit files at an older revision through `gitx.Files` and `gitx.Show`. The package imports `gitx` and `model`, and imports `identity` only for its `Candidate` type.

The store guards what it keeps. `parseUnit` and `loadUnits` refuse a file whose name does not match its ID, a kind in the wrong directory, a duplicate ID and any unit `model.Unit.Validate` rejects. Every load ends in `model.Resolve`, so callers get each value's origin, each edge's shown claim and each unit's parent. `SaveUnits` resolves and validates each unit before writing it, so the file always splits shown and hidden claims the way a load would. `writeFile` skips a write when the bytes are unchanged. Otherwise it writes a `.tmp` file and renames it over the old one. The store reads two unit formats. `legacy.go` converts an old-format file on load and stays for good, because `abbd diff` reads states committed at older revisions. Every command that changes units, except `abbd migrate`, loads them through `Writable`, which refuses the old format. The store also computes the fingerprints that mark derived views out of date. Its only cache is the `codebase`, and it has no lock. Matching lives in `internal/identity`, evidence checks in `internal/evidence` and rendering in `internal/screen`. Its callers are `cmd/abbd`, for nearly every command, and `screen.Load`, which gathers what the blueprint shows.

## Key Concepts

- **Unit file** (`store.go`): `<kind dir>/<ID>.md`. It holds YAML frontmatter with a `model.Unit`, a writer on every value, a generated body with a `# Name` heading and the anchor list, then an optional `## Notes` section the user owns and the store carries through untouched.
- **`Writable`** (`store.go`): `LoadUnits` for a command that will write. It returns `ErrOldFormat`, which points at `abbd migrate`, when any unit file is in the old format. `LoadUnits` reads either format, and `Legacy` also names the units still in the old format, for `abbd migrate`.
- **Old format** (`legacy.go`): a unit whose name has an `origin` and no `writer`, with one parent slot and a `dead` flag on relations. `convert` maps EXTRACTED to `script`, USER_STATED to `human` and INFERRED to `supplement`, and gives a directory group's name to `group`. It marks a dead relation's items dead with `DeadBeforeMigration`, and gives an absent unit `unneeded`, `evidence-dead` or `not-reported`. `regroup` gives the `group` writer each script parent claim that points at a group or sits on one. A human's parent comes out with no `over`, and `abbd migrate` fills it from the extraction.
- **`UnitsAt`** (`store.go`): the unit files as committed at a revision, in either format, which `abbd diff` compares with the current ones. A revision without `.abbd/` has no units.
- **`State`** (`store.go`): `state.yaml`, the sync watermark. `Revision` is the commit where this tree was first synced, and a drifted item dies at a sync of a later one. `Fingerprint` is the `gitx.Snapshot` tree, `MDHash` hashes the unit files, and `HighWater` holds the last number minted per kind.
- **`NextID`** (`store.go`): mints the next number of a kind and saves it to `state.yaml` at once. `abbd record unit` uses it.
- **`InputsHash`** (`store.go`): a SHA-256 over every file under `.abbd/` except `blueprint/`, including the extractor and the understanding texts. It reads CRLF as LF, so a Windows checkout that converts line endings hashes the same. The blueprint carries it as a watermark, and `screen` calls the blueprint STALE when the two differ.
- **`MDHash`** (`store.go`): the same hash over the unit files alone. Sync records it in `State`, and no code compares it today.
- **`Understanding`** (`understanding.go`): pstack how's Overview and Key Concepts for one module, with `Unit`, `Origin`, `Digest`, `Format` and `Code`, the hash of each anchor and quote the digest read when the text was written, in frontmatter and the text as the body. `abbd understand` writes it as INFERRED, and only for a top-level module. `SaveUnderstanding` refuses a text with an empty digest, which would read current whatever the code did. `CleanText` strips a leading byte order mark and gives every text LF line endings and no trailing blanks, on save, on load and before `abbd understand` compares a new text with the stored one.
- **`codebase`** (`understanding.go`): one command's read of the project's code. It lists `gitx.WorkingFiles` and `gitx.Gitlinks` once, `.abbd/` left out, or walks the disk outside a repository. git lists an untracked repository inside the project as its directory, with a trailing slash, and `list` walks that directory instead. `walk` skips a `.git` directory and leaves out a `.git` file, the gitfile of a worktree or submodule checkout, while still walking the files beside it. It hashes each path once, so `status`, `sync` and the blueprint read each file once however many texts they check. `read` gives a file with LF endings and a submodule as `submodule <commit>` from the index, so an edit inside a submodule counts once it is committed there and staged.
- **`moduleCode`** (`understanding.go`): the code a module's text describes. It collects the module and every present unit under it at any depth, and takes each anchor once. A file anchor reads the file. A directory anchor reads the paths git lists under it, a submodule as one path. When git lists nothing there, `under` falls back to the enclosing submodule's pin or, for an ignored directory, to the files on disk, and marks the anchor `fallback`. An anchor that extraction derived from the unit's own evidence does not count as a whole file. The cited quotes count in files no anchor covers.
- **`Stamp`, `ModuleDigest` and `Changed`** (`understanding.go`): `Stamp` returns the `Code` map and the digest over it. A file anchor maps to its file's hash, a directory anchor to one hash of every path and hash under it, and each place a quote is cited to the hash of `evidence.Checker.Around`, the quoted lines and 5 on each side wherever they sit now. `quotes` orders the places of one quote in a file by line, and the key is `path#quote-<hash>`, where the hash covers the quote and, from the second place on, which place it is. Counting places rather than lines keeps a key when code above the quote moves it down. An edit elsewhere in a shared file such as `CLAUDE.md` changes neither. The digest is the first 16 hex characters of a SHA-256 over the sorted map, so it reads exactly what `Code` records. `ModuleDigest` is that digest. A text whose `Digest` differs shows as STALE in `abbd status`, `abbd explain` and the blueprint. `Changed` lists what blocks `abbd understand --restamp`: an anchor or quote now whose hash differs from `Code`, naming a directory anchor as code under it, one missing from `Code`, and one in `Code` whose path is gone. One that left the module while its path still exists does not block it. A place's key counts its rank among the places cited, so when the unit citing an earlier place leaves, the place left takes that place's key and blocks a restamp. The hashes cannot show which code a place read before: a place can also take another's lines when its own quote is edited away or when code is swapped. So only a fresh text clears it.
- **Digest upgrade** (`understanding.go`): `UpgradeUnderstandings`, which `syncActual` runs, looks at each text not in `CodeFormat`. A text with no `Code` came from ABBD 0.6, and `legacyModuleDigest` recomputes its digest over the whole files cited by a module and its direct children. A format 1 text recorded a hash per file, and `format1Digest` recomputes its digest, where a directory git lists nothing under read nothing. A format 2 text recorded the hashes `Stamp` records now, except that `quotesOnce` kept one place of a quote cited at several, and `stampQuotes` recomputes its digest that way. When the old digest matches and read every file and every quoted place the new one reads, the text is stamped again in the current format and stays current. When it matches but the new digest reads more, such as a fallback directory or the second place of a quote cited twice, the text is returned as widened, keeps its stamp and reads STALE. A text the old digest called STALE stays STALE.
- **`Project`** (`store.go`): `project.yaml`, the argv of the extraction script that `abbd setup` registers and `abbd sync` runs.
