### Overview

`internal/confirm` is the queue of guesses waiting for a human. A guess is a why-field (a unit's `Purpose` or `Responsibility`) or a coupling that only an agent has vouched for: a semantic relation from a supplement or `abbd propose relation` that is not yet part of the actual topology. The package is 160 lines with three functions that matter. `Queue` lists the pending items, `Apply` confirms one, and `Reject` records that one is wrong. `abbd confirm` and the screen's confirm forms drive it through `cmd/abbd`, which saves the returned unit with `internal/store`.

Neither function changes the input slice. `decide` finds the unit or relation a key names and edits a copy, so the caller decides whether to persist. The queue never blocks alignment or a turn. It only shows a human what is still INFERRED.

### Key Concepts

- **Item**: `Key`, the `Unit` it belongs to, the `Value` a human judges, and `Design`, which is true when the item touches an intended design unit. Design items sort first.
- **Confirm key** (`if-confirm-key`): `MOD-0001.purpose`, `MOD-0001.responsibility`, or a relation as `topology.Edge.String` prints it, `MOD-0002.consumes.MOD-0001`. `relationKey` reuses the topology edge format, so the confirm key and the change key share the `FROM.kind.TO` shape.
- **Queue**: a why-field qualifies when `Fact.Guess()` is true. A relation qualifies when it does not `Counts()`, is not `Dead` (no live evidence), and has not been `Rejected`.
- **relationValue**: what a human judges a coupling by: its `Origin`, its `via`, and the first evidence entry.
- **Apply**: with no value it keeps the origin and only sets `Confirmation` to `Confirmed`. With a value it replaces the fact as `UserStated`. A relation takes no value.
- **Reject**: a why-field needs the human's replacement value, and the rejected guess is kept in `Fact.Rejected`. A rejected relation stays on record, never counts, and drops out of the queue.

### Gotchas

- `decide` tells the key forms apart only by dot count. One dot means a field and anything else means a relation. This works because model IDs and relation kinds contain no `.`.
- A relation key is matched by printing every relation and comparing strings, not by parsing it. A key with a typo comes back as `no confirmable item`.
- You cannot reject a relation that already counts (an extracted edge). It is part of the actual topology, not a guess.
- The abbd-setup skill and the screen's forms quote these key shapes directly, so a format change has to reach both.
