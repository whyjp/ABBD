## Overview

`internal/extract` is where ABBD reads the extraction JSON. That is the units-and-relations document a project's extraction script prints, and pstack's supplement uses the same schema. It is one file, `extract.go`, and its package comment calls it "the boundary where untrusted model output becomes typed units". A model wrote the script and a model reader wrote the supplement, so this package checks their shape once and nothing downstream checks it again. `Parse` reads script output and `ParseSupplement` reads a supplement. Both decode strictly with unknown fields refused. They normalize every path, check every unit and relation against the rules in `internal/model`, and tag each fact with its origin. They return a whole `Result` or the first error, never part of a result.

The package depends only on `internal/model`. It knows nothing of stored IDs, the `.abbd/` state or git, and its output is keyed by extractor-local `key` strings. `cmd/abbd` calls `Parse` in `sync` and `setup`, and `ParseSupplement` in `readSupplement`. `internal/bootstrap` folds the two results together, and `internal/identity` matches the result against stored units and assigns IDs. `NormalizeEvidence` is exported too. `abbd record` runs every `--evidence` through it, so recorded quotes follow the same path rules as extracted ones.

## Key Concepts

- **`Result`** (`extract.go`): one extraction run, a slice of `Unit` and a slice of `Relation`. Relations name their ends by unit `Key`, not by ID.
- **`Unit`** (`extract.go`): a design unit before it has an ID. It carries `Kind`, sorted and deduplicated `Anchors`, an EXTRACTED `Name`, an optional EXTRACTED `Signature`, INFERRED `Purpose` and `Responsibility`, an opaque `Digest`, a `Parent` key of the module or feature that contains it, with `ParentOrigin` and `ParentEvidence`, and `Evidence`. Parsing never sets `ParentOrigin`. The overlay does.
- **Wire shapes** (`extract.go`): `rawResult`, `rawUnit` and `rawRelation` are the private JSON form, decoded with `DisallowUnknownFields`. `Unit` and `Relation` are the checked, typed form.
- **Unit checks** (`extract.go`): `parseUnits` validates the kind, which refuses unknown kinds and the reserved domain kinds. It requires a name and at least one anchor. It allows a `signature` only on contracts (`IF`, `EVT`, `DATA`, `CFG`).
- **Key and parent checks** (`extract.go`): keys are unique. A parent must be the key of another module or feature, the two kinds `model.Kind.Holds` allows. `parentCycle` refuses loops. `ParseSupplement` sets `foreignParents`, so a parent key the supplement does not hold is left for `bootstrap.Overlay` to resolve against the script.
- **Relation checks** (`extract.go`): both ends must be existing keys and must differ. `RelationKind.Joins` checks that the kind fits the ends, `Via.Validate` checks the via, and the evidence is normalized. Every parsed relation is EXTRACTED, and the overlay re-tags a supplement's relations as INFERRED.
- **Path normalization** (`extract.go`): `normalizePath` turns backslashes into slashes, trims and cleans the path, and refuses empty, absolute or root-escaping paths. Anchors must compare equal to the root-relative paths git reports, because identity matching runs on them.
- **Evidence** (`extract.go`): a verbatim quote with `path`, optional `lines` and `symbol`, and `quote`. `NormalizeEvidence` normalizes its path and runs `model.Evidence.Validate`, which also refuses quotes from `.abbd/` or `.git/`. A unit's evidence becomes anchors too, so a reader's unit gets a stable identity.
- **Origin tagging** (`extract.go`): code facts are EXTRACTED and any statement of intent is INFERRED, since "Extraction reads code, so any statement of intent it makes is a guess". Nothing here produces USER_STATED.
