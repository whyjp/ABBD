### Overview

`cmd/abbd/guard.go` is the text check behind the PreToolUse hook. While ABBD mode is on, `hookPreToolUse` in `hook.go` builds a `guard` with `env.guard(cwd)` and asks it about each tool call: `guard.command` for a Bash or PowerShell command, `guard.toolPath` for Write, Edit and NotebookEdit, and `guard.reachesScreen` for any other tool, such as a browser or fetch. A non-empty string is the deny reason the agent reads. The guard keeps an agent away from three things: the abbd commands only a human runs, files only the CLI writes, and the running `abbd serve` screen.

The guard is defense in depth, not a boundary. `parseShell` splits a command closely enough to see `abbd approve` behind `go run ./cmd/abbd`, a redirect into `.abbd/`, a heredoc piped into `bash`, or a `$(...)` substitution. A script file, or a variable naming the command, still gets past it.

### Key Concepts

- **`parseShell` / `parsed`**: turns a command string into `segment`s (words, redirect targets, pipeline number), stdin `body`s (heredocs, here-strings, `<<<` words, marked quoted when they do not expand) and `subs` (command substitutions).
- **`guard.check`**: the verdict. It recurses into substitutions, executable bodies and the arguments of `shells` such as `bash -c` or `iex`, up to `maxDepth` 4, and returns the first reason.
- **`humans`**: the abbd subcommands denied in the mode: `align`, `approve`, `reject`, `confirm`, `couple`, `setup`, `mode off`, `serve`. `abbdCommand` finds the subcommand after skipping global flags, treating `--root` and `--session` as flags that take a value.
- **`protected`**: a path is protected when it is under `.abbd/` (except `.abbd/extractor/` while `setupOpen`), under the git directory's `abbd/` session state, one of the registered script's files, or a glob at the root that matches `.abbd`. A deleter also may not reach any directory holding the root.
- **Command classes**: `readers` only read, so a protected name in their arguments is text; `deleters`, `cds` and `gitWriters` decide what counts as a target and where the cwd moves.
- **`registersOnly`**: the one `abbd setup` an agent may run, in a greenfield project, as a bare `abbd setup -- <argv>`.
- **`guard.screen`**: the screen's port, read from `serve.addr` through `Store.ScreenAddr`, spelled with `127.0.0.1`, `localhost`, `[::1]` and `0.0.0.0`.

### Gotchas

- `humans` must keep step with the `commands` table in `main.go`, the forms `serve.go`'s `actions` run, and the list quoted in the abbd-mode skill. A new human command added only to `main.go` is not denied.
- `hook.go` denies any tool input that mentions `serve.addr`, because a command could build the address from the port and no text check resolves `127.0.0.1:$P`.
- `checkGit` denies `git clean`, `stash` and `reset --hard` with no pathspec outright, since they reach `.abbd/` with the rest of the tree.
