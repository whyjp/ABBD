### Overview

`internal/extract` is the trust boundary between an extractor's JSON and ABBD's typed units. The project's registered extraction script, a supplement, an adoption file and a greenfield statement all print the same format. `Parse` decodes it and either returns a `Result` or fails with a message that names the offending unit or relation. Nothing gets an ID here. Units and relations are still named by extractor-local `key`s, and `internal/identity` later matches them to stable IDs by their anchors.

`Parse` runs in two layers. `parseUnits` checks each unit on its own: the decoder rejects unknown fields, the kind must be valid, the name non-empty, every anchor path normalized, and only a contract may carry a signature. The evidence on a unit is folded into its anchors, so a unit the script cannot see still has something stable to match on. `Parse` then checks the graph: keys are unique, a `parent` is another module's key and never forms a cycle, relations name existing keys and not themselves, and each relation's kind can join the two unit kinds (`model.RelationKind.Joins`) with a known `via`.

### Key Concepts

- **`rawUnit` / `rawRelation` / `rawResult`**: the exact JSON wire shape. Their fields are the whole list of what an extractor may print.
- **`Result`, `Unit`, `Relation`**: the typed output. Names and values are `model.Fact`s with origins attached.
- **Origin assignment**: `name` and `signature` become EXTRACTED. `purpose` and `responsibility` go through `inferred` and become INFERRED and UNCONFIRMED, because code cannot prove intent.
- **`StatedBy`**: restates every fact and relation with another origin, USER_STATED for greenfield or ADOPTED for documents.
- **`normalizePath`**: forward slashes, `path.Clean`, and a refusal of absolute paths or `..`, so anchors compare equal to git's root-relative paths.
- **`NormalizeEvidence`**: normalizes each evidence path and runs `model.Evidence.Validate`, which also bans citing `.abbd/` or `.git/`.
- **`parentCycle`**: follows `Parent` keys from a unit and reports a loop.

### Gotchas

- The decoder uses `DisallowUnknownFields`, so one extra field anywhere fails the whole extraction, not just that unit. The abbd-setup skill's "Unknown fields are rejected" says the same.
- Relations parsed here always get the EXTRACTED origin. `internal/bootstrap`'s overlay re-marks a supplement's relations as INFERRED, so the origin set here is not final.
- An evidence entry adds an anchor. Editing a quote's path or symbol can therefore change which ID a semantic unit matches.
