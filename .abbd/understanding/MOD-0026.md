## Overview

`internal/identity` decides which design unit is which across extraction runs. On every `abbd sync` and `abbd setup`, the extraction reports units with anchors and keys but no IDs. For setup, `bootstrap.Overlay` has already folded in the reader's supplement. `Reconcile` pairs those units with the ones stored in `.abbd/`. A matched unit keeps its ID and is marked present again. An unmatched one gets the next number above a per-kind high-water mark, so a deleted number never returns. `Reconcile` never drops a unit. A stored unit that the extraction's writers no longer report is marked absent with a reason, and an overlap that did not become a match is recorded as a merge candidate for a human.

### The package has one source file

The package has one source file, `identity.go`, and `Reconcile` is pure. It does no I/O. It clones the stored claims before it edits them, and it sorts its input by kind and anchor list and its candidate pairs by rank, so input order never changes the outcome. It first applies git renames to stored anchors and evidence paths. It then pairs supplement units by their stored supplement key, and assigns the other pairs globally, best match first. It also decides what the run may overwrite. The `Writers` the extraction speaks for lose their claims on each reported unit and get the claims it makes, and every other writer's claims stay. So setup replaces the supplement's claims and keeps what `abbd record` wrote. `Reconcile` ends with `model.Resolve`, which picks each edge's shown claim and each unit's parent. The main caller is `syncActual` in `cmd/abbd/main.go`, used by sync with `Sync` and by setup with `Setup`. It loads units with `Store.Writable`, which refuses a state in the old format, then candidates, state and renames. It refuses an empty extraction against a non-empty store, calls `Reconcile`, and passes the units through `evidence.Checker.Apply` and `group.Fallback` before saving. `supplementClaims` in `cmd/abbd/migrate.go` calls `Reconcile` with `Setup` and no renames or prior candidates, and reads only `Result.Keys` to pair the supplement's units with stored ones. `internal/store` imports the package only for `Candidate`.

## Key Concepts

- **Match rule** (`identity.go`): a supplement unit takes over the first stored unit of the same kind with the same `SupplementRef`. Any other extracted unit and a stored unit of the same kind not yet taken may pair when they share two or more anchors, or when their anchor sets are identical. Identical sets are the only way a one-anchor unit matches. Pairs rank by identical sets, then larger overlap, then smaller symmetric difference, then stored position, then input position.
- **Anchor** (`model.go`): a `Path` and `Symbol`, compared by `Key()`. `applyRenames` rewrites stored anchor paths and re-sorts them with `model.SortAnchors` before any comparison.
- **High-water mark** (`identity.go`): the largest number minted per kind. `Reconcile` copies the given map, raises it past any stored ID, mints from it and returns it in `Result.HighWater`.
- **`Writers`** (`identity.go`): `Sync` is the script alone. `Setup` is the script and the supplement. An unmatched stored unit is touched only when one of these writers wrote its name. It goes absent as `not-reported` for the script's and `withdrawn` for the supplement's. One that was already absent keeps its reason and is still listed in `Unmatched`. A reader's or a human's unit stays, and its evidence decides.
- **Held by a human** (`identity.go`): `heldByHuman` marks a unit with a human's name, purpose, responsibility or signature, a human's parent claim, or a human's relation claim, shown or hidden, at either end. An unreported supplement unit that is held stays present, and its ID lands in `Result.Stated`. Only `Setup` owns supplement names, so only setup keeps units this way.

### merge

- **`merge`** (`identity.go`): folds an extracted unit into the stored unit it took over. The extraction sets the anchors, the code `Digest` and the contract's `Entries`, and a non-empty `SupplementRef`. The name is replaced when its writer is one the extraction speaks for, or when the offered writer outranks it in `model.Precedence`, and the unit's evidence goes with it. Purpose, responsibility and signature are replaced on the same terms, and an empty field takes what is offered. A replaced field takes the offer even when the offer is empty, so the extraction can clear its own value.
- **Parent and relation claims** (`identity.go`): `setParents` and `setRelations` work on each reported unit. They drop the claims of the writers the extraction speaks for and add the claims it makes. The script's parent is added when its key resolved in this run. The supplement's `Placed` parents are added when the extraction owns their writer. A relation carries its `Via`, `Evidence` and `Entries` onto the claim. `setPhrases` does the same for the extraction's phrase notes, replacing those its writers hold. A relation with no writer is the script's, and one that repeats a claim with the same end, kind and writer is skipped. Units it did not report keep their relations as they were.
- **Entries on claims** (`identity.go`): `setRelations` carries each extracted relation's `Entries`, the keys of the entries of its target it uses, onto the claim it makes, and a new unit takes the extraction's entries as they come. An entry has no identity apart from its contract and its key, so a renamed entry is one entry gone and one added.

### carry

- **`carry`** (`identity.go`): a restated item takes the lines, status, `Since` and reason of the stored item that cites the same code (`Evidence.Same`, path and quote). It looks in the claim's own stored items first, then in every item the unit stores (`items`). So re-running setup never revives a dead item. The script's own evidence and the script's relations are taken as they come.
- **`Candidate`** (`identity.go`): `New`, `Existing` and one `Shared` anchor, the first anchor of the extracted unit that the stored unit held before the merge. A matched unit links only to stored units left without a match. `keepLive` keeps a candidate while both IDs exist, removes duplicates and sorts. `abbd sync` prints each as `X candidate-of Y via path#symbol`.
- **`Result`** (`identity.go`): `Units` sorted by ID, `Events` (`matched` or `new` per extracted unit, in sorted input order), `Unmatched`, `Stated`, `Keys` (the ID each extracted key took), `Candidates` and `HighWater`.
- **Invariant test** (`invariant_test.go`): random runs of sync, setup, record and code edits over a small world. `TestNothingSilentlyDisappears` checks that every present unit stays present or says why, that every reader's and human's claim stays stored, and that resolved parents form a tree. `TestSyncChangesOnlyTheScriptsClaimsAndIsIdempotent` checks that sync touches only the script's claims and that two runs on one tree agree.
- **Artifact carry** (`identity.go`): a matched unit takes the extraction's `Artifact` as it takes a signature, by writer: a supplement's stays through a sync of the script, and a script's goes when the script stops reading it.
