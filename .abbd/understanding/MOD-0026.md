## Overview

`internal/identity` decides which design unit is which across extraction runs. On every `abbd sync` and `abbd setup`, the extraction reports units with anchors and keys but no IDs. For setup, `bootstrap.Overlay` has already folded in the reader's supplement. `Reconcile` pairs those units with the ones stored in `.abbd/`. A matched unit keeps its ID. An unmatched one gets the next number above a per-kind high-water mark, so a deleted number never returns. `Reconcile` never drops a unit. A stored unit nobody reported is marked `Absent`, and an overlap that did not become a match is recorded as a merge candidate for a human.

The package is one file, `identity.go`, and `Reconcile` is pure. It does no I/O, and it sorts its input and its candidate pairs, so input order never changes the outcome. It first applies git renames to stored anchors, then assigns pairs globally, best match first. It also decides what the run may overwrite. Extraction owns anchors, the code `Digest`, evidence, EXTRACTED names and EXTRACTED relations. A reader's signature survives a plain sync when the script reads none. Purpose and responsibility are filled in only when empty, unless guesses are being replaced. Parents come from the extraction by key. When the extraction places a unit nowhere, a parent a reader or a human gave it stays while that module is present, unless it would close a cycle. The caller is `syncActual` in `cmd/abbd/main.go`. It loads units, candidates, high-water marks and renames, calls `Reconcile`, then passes the units through `evidence.Apply` and `group.Fallback` before saving. `internal/store` imports the package only for `Candidate`.

## Key Concepts

- **Match rule** (`identity.go`): an extracted unit and a stored unit of the same kind may pair when they share two or more anchors, or when their anchor sets are identical. Identical sets are the only way a one-anchor unit matches. Pairs rank by identical sets, then larger overlap, then smaller symmetric difference.
- **Anchor** (`model.go`): a `Path` and `Symbol`, compared by `Key()`. `extract.parseUnits` and `abbd record unit` add a semantic unit's evidence locations as anchors.
- **High-water mark** (`identity.go`): the largest number minted per kind. `Reconcile` raises it past any stored ID, mints from it and returns it in `Result.HighWater`.
- **`Guesses`** (`identity.go`): `KeepGuesses` is for `abbd sync`, whose script cannot see INFERRED facts, so an unreported semantic unit stays present and its evidence decides. `ReplaceGuesses` is for `abbd setup`, whose supplement owns the guesses and withdraws what it no longer reports.
- **Held by a human** (`identity.go`): under `ReplaceGuesses`, an unreported semantic unit stays when it carries a USER_STATED fact or relation, or when a staying unit points to it with a USER_STATED relation. `heldByHuman` repeats until nothing grows, and these IDs land in `Result.Stated`.
- **Relation ownership** (`identity.go`): `setRelations` replaces each reported unit's EXTRACTED relations, keeps the others, and drops stored INFERRED ones under `ReplaceGuesses`. A duplicate edge keeps the extracted copy first, then the stored one. Unreported units keep their relations as they were.
- **`Candidate`** (`identity.go`): `New`, `Existing` and one `Shared` anchor. A matched unit links only to stored units left without a match. Prior candidates survive while both IDs exist, and sync prints each as `X candidate-of Y via path#symbol`.
- **`Result`** (`identity.go`): `Units` sorted by ID, `Events` (`matched` or `new` per extracted unit), `Unmatched`, `Stated`, `Candidates` and `HighWater`.
