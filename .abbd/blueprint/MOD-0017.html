Overview

internal/extract is where ABBD reads the extraction JSON. That is the units-and-relations document a project's extraction script prints, and pstack's supplement uses the same schema. It is one file, extract.go, and its package comment calls it "the boundary where untrusted model output becomes typed units". A model wrote the script and a model reader wrote the supplement, so this package checks their shape once and nothing downstream checks it again. Parse reads script output and ParseSupplement reads a supplement. Both decode strictly with unknown fields refused. They normalize every path, check every unit and relation against the rules in internal/model, and give each fact its writer. They return a whole Result or the first error, never part of a result.

The package depends only on internal/model. It knows nothing of stored IDs, the .abbd/ state or git, and its output is keyed by each unit's extractor-local ref. A unit spells it ref or key, and parseUnits refuses a unit that spells both with different values, because gitleaks' generic-api-key rule reads a path-like key value with enough entropy as a secret. cmd/abbd calls Parse in sync, setup and migrate, and ParseSupplement in readSupplement, which setup and migrate use. internal/bootstrap folds the two results together, and internal/identity matches the result against stored units and assigns IDs. NormalizeEvidence is exported too. abbd record runs every --evidence through it, so recorded quotes follow the same path rules as extracted ones.

Key Concepts

  • Result (extract.go): one extraction run, a slice of Unit and a slice of Relation. Relations name their ends by unit Key, not by ID, and carry their Writer.
  • Unit (extract.go): a design unit before it has an ID. It carries Kind, sorted and deduplicated Anchors, a Name and an optional Signature by the script, Purpose and Responsibility, an opaque Digest, the Parent key of the module or feature that contains it with ParentEvidence, and Evidence. Parsing leaves Placed and SupplementRef empty, and bootstrap.Overlay fills them.
  • Placement (extract.go): one writer's parent claim, by key, with its evidence. The overlay adds the supplement's to Placed, and identity stores each one as a parent claim beside the script's.
  • Wire shapes (extract.go): rawResult, rawUnit and rawRelation are the private JSON form, decoded with DisallowUnknownFields. Unit and Relation are the checked, typed form.
  • Unit checks (extract.go): parseUnits validates the kind, which refuses unknown kinds and the reserved domain kinds. It requires a name and at least one anchor. It allows a signature only on contracts (IF, EVT, DATA, CFG).
  • Key and parent checks (extract.go): keys are unique. A parent must be the key of another module or feature, the two kinds model.Kind.Holds allows. parentCycle refuses loops. ParseSupplement sets foreignParents, so a parent key the supplement does not hold is left for bootstrap.Overlay to resolve against the script.
  • Relation checks (extract.go): both ends must differ. In script output both must be existing refs. In a supplement an end may be a ref only the script reports, so parse checks the kind alone there and leaves RelationKind.Joins to the overlay, which knows both kinds. Otherwise RelationKind.Joins checks that the kind fits the ends, Via.Validate checks the via, model.ValidatePhrase checks a phrase, which only a supplement may give, and the evidence is normalized. Every parsed relation's writer is script, and the overlay appends the supplement's own couplings with the writer supplement.
  • Entries (extract.go): a contract's entries are its parts as the code spells them, such as a route, a method, a flag or a field, each a model.Entry with a name and an optional shape and required. normalizeEntries trims them, keeps the code's order, gives each entry without a key the one model.EntryKey reduces its name to, and refuses entries on a unit that is not a contract and two entries that share a key. A relation's entries name entries of its to unit by name or by key, and entryKeys turns them into the sorted keys of that unit's entries, refusing a name the unit does not list. Two relation lines on one edge add their entries up into one relation, because one claim holds an edge, and a line that names no entries keeps that relation whole, since it uses every entry. ParseSupplement refuses entries outright: they are what the code spells, so only the script reports them.
  • Path normalization (extract.go): normalizePath turns backslashes into slashes, trims and cleans the path, and refuses empty, absolute or root-escaping paths. Anchors must compare equal to the root-relative paths git reports, because identity matching runs on them.
  • Evidence (extract.go): a verbatim quote with path, optional lines and symbol, and quote. The JSON never sets an item's status. NormalizeEvidence normalizes its path, trims its symbol and runs model.Evidence.Validate, which also refuses quotes from .abbd/ or .git/. A unit's evidence becomes anchors too, so a reader's unit gets a stable identity.
  • Writer tagging (extract.go): names, signatures and relations get the writer script, which is EXTRACTED. A purpose or responsibility in the JSON gets the writer supplement, which is INFERRED, since "Extraction reads code, so any statement of intent it makes is a guess, and it ranks with the supplement's". Nothing here produces a reader or human value.
