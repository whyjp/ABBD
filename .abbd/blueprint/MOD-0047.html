Overview

internal/topology is the read-only query layer over the stored topology. It takes the []model.Unit slice that internal/store loads, either from the working tree (LoadUnits) or from a git revision (UnitsAt). From ABBD it imports only internal/model. cmd/abbd calls it for its query commands. Find resolves what an agent has in hand to units, through env.find in cmd/abbd/query.go, which explain, path and impact share. A well-formed ID skips Find, and when nothing matches Nearest suggests the closest names. Explain serves abbd explain. Path and Weakest serve abbd path. ImpactOf serves abbd impact. Compare builds the Diff behind abbd diff between a base revision, the merge base by default, and the working tree, Diff.Lines and Diff.String print it, and Diff.Boundary drives its --check gate. The package never writes a unit and never opens the store.

Its other job is to keep the three origins apart. EXTRACTED means the script read the relation from code. USER_STATED means a human said it. INFERRED means a pstack reader quoted evidence for it. A relation whose evidence is all dead, or whose end is absent, is dropped everywhere. A live or drifted inferred one is still walked by ImpactOf and Path, but it carries an (inferred, via ...) label, which ends in drifted while its evidence has drifted. It sits apart in Explanation.Inferred and Diff.InferredAdded, and it never changes RelationsAdded or RelationsRemoved. A reader of the output can tell what the code vouches for from what a reader guessed.

Key Concepts

  • Find / Match / Tier (find.go): resolves a query best first. An exact ID returns one match (ByID), and an exact name returns every unit with that name (ByName), both ignoring case. Only then does Find read the project's file list. byCode reads the query as a symbol, ignoring case, or as a path, dropping a :12-30 suffix and a leading ./. targets widens a path to known files that end with it, and a bare name to files with that base name or stem. Units whose anchors or evidence hold the path rank first, the most specific first, and units with code under a named directory follow. A query with /, \ or . that matched code stops there. Any other query also gets byPhrase matches, ranked by how many query words a unit holds and then by where, the name weighing most and a project file under its anchors least. Ties go to the deeper unit, then the smaller ID.
  • Match.Anchored (find.go): true when one of a unit's anchors is the queried path or a directory that holds it. abbd impact seeds the best match plus every other anchored match, so a path change reaches every unit anchored there. Symbol, evidence and phrase matches stay unanchored.
  • Nearest (find.go): the present units whose names are fewest Levenshtein edits from the query, ignoring case.
  • Link (impact.go): one relation between two present units that is not dead, a model.Edge plus Origin, Via, the Phrase note, the Entries of its target it uses, and Drifted. Label names its origin, its via and a drift, then the phrase with its own origin and drift. Links reads only shown relations and is the graph that Explain, ImpactOf and Path walk.
  • Explain / Explanation (query.go): the unit, its direct children as Refs, the drawn links Out and In, and the reader's links Inferred. A link between a unit inside it, at any depth, and a unit outside counts as the unit's own (own).
  • ImpactOf / Impact (impact.go): a breadth-first walk from the seeds and every unit inside them, at any depth. It follows what depends on or consumes an impacted unit, and the contracts a seed or a unit inside one provides. A unit reached through what it uses passes the change on to what uses it, not to the other contracts it provides: the change does not travel through those. A contract's provider, and what a seed itself uses, are listed but not followed. Each Item says why it is there. Direct holds the seeds, their neighbours and the consumers of a neighbouring contract. Far holds the rest.
  • Path / Hop (path.go): a cheapest-first walk over Links plus nesting, a Contains link from parent to child, each walked either way. Cost compares joints first, then hops, nesting hops and the weakest origin. A joint is two users of one unit meeting through it. unloop then cuts any stretch that leaves a unit and comes back to it, and markJoints records a joint that remains in Hop.Shares and Hop.Provider.
  • ByFeature / Feature (feature.go): groups an Impact under the outermost FEAT that is or holds each impacted unit, the feature itself first, each item with its tier. Uses lists the impacted contracts the feature or a unit inside it consumes, with the union of the entry keys those links name, or none when any of those links names no entries, since that unit uses the contract whole. Impacted units no feature holds come back apart. abbd impact --features prints it.
  • EntryUses (entry.go): for one contract, the live links that narrow to each of its entries, by entry key: who consumes a route, who writes or reads a field. explain and the blueprint's entry tables read it.
  • strength (query.go): EXTRACTED 2, USER_STATED 1, INFERRED 0. It breaks Path's last tie and drives Weakest. It also gives a contains hop the weaker of the unit's name origin and its ParentOrigin, which counts as EXTRACTED when empty.
  • Lifting (diff.go): a relation of an inside unit counts as its enclosing unit's. Compare lifts both ends to the top-level unit (top, between) and drops an edge that lifts onto itself. Explain lifts to the unit being explained. InferredAdded is not lifted and keeps each coupling's own ends.
  • Diff (diff.go): present units added and removed, so a unit gone absent counts as removed. Changed contract Signatures, contract Entries added or removed, and a change to an entry's name, shape or need as one line per field that changed (Field is name, shape or required, and Lines words shape as type for a contract that holds data and as signature otherwise), one Listed line for a contract that came to list its entries or stopped instead of one per entry, contracts whose Code digest changed under the same signature and entries when both digests exist, drawn top-level relations added or removed, UsesAdded and UsesRemoved for an entry a drawn relation came to use or stopped using, on a top-level relation both sides have and a contract that lists entries on both, UsesWidened and UsesNarrowed for a use that came to take the whole contract or only some of its entries, which entryUses tells by a relation that names no entries, so neither reads as a line per entry, and InferredAdded with its via and first quote. Boundary is true for a changed signature, a changed entry or entry list, an added or removed contract, or an added or removed drawn relation. A code-only change, a new use of an entry on a relation already there, a non-contract unit and an inferred coupling never set it.
