Overview

internal/gitx는 ABBD가 git에 닿는 유일한 통로다. 파일은 gitx.go 하나이고, 상태 없는 공개 함수 열한 개와 비공개 도우미 run, runInput, gitlinks, unbornRepos, addFiles, addMode, unignored, ignored, 그리고 서브모듈의 경로와 기록된 커밋을 담는 비공개 타입 gitlink 하나로 이루어진다. 각 함수는 git -C <dir> ...을 돌려 stdout을 문자열, 슬라이스, 맵으로 바꾼다. 공개 타입이 없고, 상태를 두지 않으며, 표준 라이브러리만 가져온다. 사용자의 index, ref, 커밋은 결코 쓰지 않는다.

중심 개념은 작업 트리 지문이다. Snapshot은 추적되지 않은 파일까지 포함한 작업 트리 전체를 버릴 index에 올리되 exclude 경로는 빼고, git write-tree를 돌린다. .gitignore가 이미 무시하는 경로는 exclude로 이름 붙이지 않는다(ignored, git check-ignore --no-index를 거치므로 추적되는 .abbd에 흔들리지 않는다). git이 그런 pathspec을 거부하고, /* 같은 허용 목록 .gitignore는 .abbd도 무시하기 때문이다. 서브모듈은 체크아웃된 커밋이 아니라 상위 프로젝트 index가 기록한 커밋으로 들어가므로, sync된 커밋을 새로 클론해도 같은 트리가 나온다. 호출자는 store.Dir을 넘기므로 .abbd/는 세지 않는다. abbd CLI의 syncActual은 그 트리를 State.Fingerprint로, Head의 결과를 State.Revision으로 저장한다. 다음 sync에서 Renames가 저장된 트리와 새 트리를 비교해 identity.Reconcile이 옮겨진 파일을 따라가게 한다. screenInput은 새 스냅숏을 떠서 abbd status와 블루프린트가 상태를 STALE이라 부를 수 있게 한다. install.go의 keepingCurrent는 .abbd/ 밖을 고치는 앞뒤로 스냅숏을 뜨고, 상태가 CURRENT였을 때만 지문을 옮긴다. 나머지 함수는 더 넓은 읽기를 맡는다. MergeBase는 abbd diff의 기준을 고르고, FilesAt은 그 리비전에서 한 경로 아래 파일을 모두 git 호출 두 번으로 읽어 store.UnitsAt과 store.CheckoutAt에 준다. WorkingFiles는 git이 커밋할 파일을 나열한다. internal/evidence는 그 목록으로 이동 후보를 찾고, topology.Find는 질의가 파일을 이를 때 그 목록을 쓴다.

Key Concepts

  • run (gitx.go): 모든 함수가 거치는 비공개 도우미다. 덧붙인 환경 변수와 함께 git -C dir args...를 돌려 stdout을 받고, stderr는 잇지 않으므로 git의 메시지는 버려진다. runInput은 stdin에 문자열을 넣는 같은 도우미이고, addFiles가 경로와 index 줄을, FilesAt이 객체 ID를 그것으로 흘려보낸다.
  • FilesAt (gitx.go): 한 리비전에서 주어진 경로 아래 파일을 dir 기준 경로로 돌려주되 keep이 거절한 것은 뺀다. git ls-tree -r -z로 blob을 나열하고 git cat-file --batch 한 번으로 모두 읽으므로, 파일 수백 개짜리 상태도 git 호출 두 번이면 된다. 읽을 수 없는 머리줄은 그 파일 이름과 함께 오류가 된다.

Snapshot

  • working-tree snapshot (Snapshot): dir 아래 추적되거나 추적되지 않았지만 무시되지 않은 파일에서 exclude를 뺀 트리 객체다. gitlinks가 git ls-files -s로 각 서브모듈의 기록된 커밋을 읽고, add는 서브모듈 경로를 건너뛰며, update-index --cacheinfo가 기록된 커밋을 되돌려 놓는다. git add는 아직 커밋이 없는 중첩 저장소를 거부하므로, unbornRepos가 그런 저장소, 곧 끝에 슬래시가 붙은 추적되지 않은 항목 중 Head가 빈 것을 모두 찾고 add는 그것을 건너뛴다. 그다음 addFiles가 그 안의 파일을 WorkingFiles가 나열하는 대로 hash-object -w와 update-index -z --index-info로 더해, 지문이 그것을 실제 모습대로 추적되지 않은 디렉터리로 보게 한다. addMode는 git add가 더할 것만 남긴다. 일반 파일은 100644나 100755로, 심볼릭 링크는 120000으로 더하고, 링크의 blob은 대상의 내용이 아니라 링크가 가리키는 대상이다. 사라진 경로, 파일도 심볼릭 링크도 아닌 경로, 심볼릭 링크 디렉터리 아래의 경로는 버린다. Windows 정션은 git에게 심볼릭 링크가 아니어서 git이 그 안으로 들어가고, Lstat은 그것을 불규칙이라 부르므로, 불규칙이면서 디렉터리로 풀리는 부모는 디렉터리로 센다. 첫 커밋 전에 파일을 지우거나 이름을 바꿨을 때, 또는 디렉터리가 나중에 심볼릭 링크가 됐을 때 그 저장소의 index가 그런 경로를 나열할 수 있고, git check-ignore는 심볼릭 링크 아래 경로를 거부한다. 그다음 unignored가 git check-ignore가 프로젝트에서 무시한다고 하는 것을 버린다. hash-object --stdin-paths로 가는 경로는 모두 C 형식 따옴표로 감싸므로 이름에 줄바꿈이 있어도 된다. git은 hash-object --stdin-paths, --index-info, --cacheinfo의 경로를 작업 트리 꼭대기 기준으로 읽으므로, dir이 저장소의 하위 디렉터리면 그 경로와 서브모듈 경로에 rev-parse --show-prefix가 주는 접두사를 붙인다. GIT_INDEX_FILE은 abbd-index- 임시 디렉터리를 가리키고, 그 디렉터리는 끝나면 지운다. 저장소 밖에서는 빈 문자열을 돌려주고 오류는 내지 않는다.

Renames

  • rename detection (Renames): git diff-tree -r -M -l0 --name-status -z --relative에서 옛 경로를 새 경로로 잇는다. 이름 변경 항목만 남기고 복사는 건너뛴다. 같은 트리나 빈 트리는 빈 맵을 준다.
  • ok result (gitx.go): Renames와 Changed는 git cat-file -e가 옛 트리를 찾지 못하면, 대개 git gc 뒤에, 오류 없이 ok=false를 돌려준다. 그러면 syncActual은 파일 이동을 알아채지 못한다고 경고하고 계속한다.
  • Changed (gitx.go): 두 스냅숏 사이에 다른 경로를 모두 나열하고, 옮겨진 파일은 두 이름 모두로 나온다. 지금 저장소에서 이것을 부르는 곳은 없다.
  • ChangedSince (gitx.go): 한 리비전과 작업 트리 사이에 다른 추적 파일을 git diff -z --name-only --no-renames --relative REV --로, 그리고 git이 무시하지 않는 추적되지 않은 파일을 모두 NUL로 나눠 루트 기준으로 돌려주며, 이름이 바뀐 파일은 두 이름 모두로 나온다. abbd review는 이것을 읽어 코드가 바뀐 유닛에서 씨앗을 얻는다.
  • LastCommitted (gitx.go): 한 경로를 건드린 마지막 커밋의 날짜를 git log -1 --format=%cs로 YYYY-MM-DD로 주거나 빈 값을 준다. abbd status는 이것으로 커버리지 줄에 가장 오래 커밋된 글의 날짜를 붙인다.
  • Recorded (gitx.go): 주어진 파일에서 한 인용을 더하거나 뺀 첫 커밋(git log --reverse -S)을 날짜와 제목과 함께 주고, 조상 경로에서 첫 부모가 아직 그 인용을 갖지 않은 첫 병합의 풀 리퀘스트도 준다. 그래서 주 줄기에 바로 만든 커밋은 풀 리퀘스트를 이르지 않는다. abbd explain은 reader의 결합마다 이것을 읽되 그 결합의 유닛 파일만 찾는다.

MergeBase

  • default-branch base search (MergeBase): origin의 HEAD 심볼릭 ref, @{upstream}, origin/main, origin/master, main, master를 차례로 해 보고 git이 받는 첫 병합 기준을 돌려준다. 하나도 안 되면 --base REV를 달라는 오류를 낸다.
  • Gitlinks (gitx.go): index가 기록한 서브모듈을 모두 그 경로에서 기록된 커밋으로 잇는다. gitlinks가 git ls-files -s에서 한 번 읽는다. 저장소 밖에서는 비어 있다. store는 서브모듈을 그 핀으로 해시하므로 모듈의 digest는 클론마다 새 핀을 보고, 서브모듈 안의 디렉터리 anchor는 그 핀을 대신한다. Snapshot도 같은 목록을 읽는다.
  • Head (gitx.go): 현재 커밋이고, 저장소 밖이나 첫 커밋 전이면 빈 문자열이다.
  • WorkingFiles (gitx.go): git ls-files --cached --others --exclude-standard다. 지문이 세는 집합과 같되 .abbd/가 들어 있다는 점만 다르다. 서브모듈은 경로 하나로 나열하고, 무시된 파일은 결코 나열하지 않으며, 저장소 밖에서는 nil을 돌려주고 그때 store는 디스크를 직접 훑는다.
  • Paths relative to dir (gitx.go): 모든 함수는 받은 디렉터리 기준 경로를 받고 돌려준다. -C, --relative, 그리고 ls-tree가 현재 디렉터리 기준으로 경로를 받고 내는 방식을 거친다. 그래서 저장소 꼭대기 아래의 프로젝트 루트에서도 그대로 돈다.
