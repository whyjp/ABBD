Overview

internal/gitx is ABBD's only channel to git. It is one file, gitx.go, with nine exported, stateless functions, private helpers run, runInput, gitlinks, unbornRepos, addFiles, addMode and unignored, and one private type, gitlink, a submodule's path and recorded commit. Each function runs git -C <dir> ... and turns stdout into a string, slice or map. The package exports no types, keeps no state and imports only the standard library. It never writes the user's index, refs or commits.

The central idea is the working-tree fingerprint. Snapshot stages the whole working tree into a throwaway index, untracked files included and the exclude path left out, then runs git write-tree. It names no exclude for a path .gitignore already ignores (ignored, through git check-ignore --no-index, so a tracked .abbd does not sway it), since git refuses such a pathspec and a whitelist .gitignore such as /* ignores .abbd too. A submodule enters as the commit the superproject's index records, not the one checked out, so a clean clone of a synced commit snapshots the same tree. Callers pass store.Dir, so .abbd/ never counts. syncActual in cmd/abbd/main.go stores that tree as State.Fingerprint and the result of Head as State.Revision. On the next sync, Renames diffs the stored and fresh trees so identity.Reconcile can follow moved files. screenInput takes a fresh snapshot so abbd status and the blueprint can call the state STALE. keepingCurrent in install.go snapshots around an edit outside .abbd/ and moves the fingerprint along only when the state was current. The other functions serve wider reads. MergeBase picks the base for abbd diff, and FilesAt reads every file under a path at that revision in two git calls, for store.UnitsAt and store.CheckoutAt. WorkingFiles lists what git would commit. internal/evidence uses that list for move candidates, and topology.Find uses it when a query names a file.

나머지 설명

Key Concepts

  • run (gitx.go): the private helper every function goes through. It runs git -C dir args... with extra environment variables appended, captures stdout and leaves stderr unattached, so git's messages are dropped. runInput is the same with a string on stdin, which addFiles feeds paths and index lines through.

Snapshot

  • Snapshot (gitx.go): a tree object of the tracked and untracked, non-ignored files under dir, minus exclude. gitlinks reads each submodule's recorded commit with git ls-files -s, the add skips the submodule paths, and update-index --cacheinfo puts the recorded commits back. git add refuses a nested repository with no commit yet, so unbornRepos finds each one, an untracked entry with a trailing slash whose Head is empty, and the add skips it. addFiles then adds its files, as WorkingFiles lists them inside it, through hash-object -w and update-index -z --index-info, so the fingerprint sees it as the untracked directory it is. addMode keeps what git add would add: a regular file as 100644 or 100755, and a symlink as 120000, whose blob is the link's target, not the target's content. It drops a path that is gone, is neither a file nor a symlink, or sits below a symlinked directory. A Windows junction is not a symlink to git, which walks into it, and Lstat calls it irregular, so a parent that is irregular and resolves to a directory counts as a directory. That repository's index can list such a path when a file is deleted or renamed before the first commit, or when a directory later becomes a symlink, and git check-ignore would refuse a path below a symlink. unignored then drops what git check-ignore says the project ignores. Each path to hash-object --stdin-paths goes in C-style quotes, so a name may hold a newline. git reads the paths of hash-object --stdin-paths, --index-info and --cacheinfo from the top of the work tree, so they and the submodule paths take the prefix rev-parse --show-prefix gives when dir is a subdirectory of the repository. GIT_INDEX_FILE points into an abbd-index- temp directory that is removed afterwards. Outside a repository it returns an empty string and no error.

Renames

  • Renames (gitx.go): old to new paths from git diff-tree -r -M -l0 --name-status -z --relative. It keeps rename entries and skips copies. Equal or empty trees give an empty map.
  • ok result (gitx.go): Renames and Changed return ok=false with no error when git cat-file -e cannot find the old tree, usually after git gc. syncActual then warns that file moves are not detected and carries on.
  • Changed (gitx.go): every path that differs between two snapshots, with a moved file listed under both names. Nothing in the repository calls it today.
  • ChangedSince (gitx.go): the tracked files that differ between a revision and the working tree, from git diff -z --name-only --no-renames --relative REV --, and the untracked files git does not ignore, all NUL-separated and relative to the root, a renamed file under both names. abbd review reads it to seed from the units whose code changed.
  • LastCommitted (gitx.go): the date of the last commit that touched a path, as YYYY-MM-DD, from git log -1 --format=%cs, or empty. abbd status reads it to date the oldest committed text in its coverage line.
  • Recorded (gitx.go): the first commit whose diff adds or removes a quote in the given files (git log --reverse -S), with its date and subject, and the pull request of the first merge on the ancestry path whose first parent does not hold it yet, so a commit made on the main line itself names none. abbd explain reads it under each reader's coupling, searching only the coupling's unit file.

MergeBase

  • MergeBase (gitx.go): tries origin's HEAD symbolic ref, then @{upstream}, origin/main, origin/master, main and master, and returns the first merge base git accepts. When none works it returns an error asking for --base REV.
  • Gitlinks (gitx.go): every submodule the index records, mapped from its path to the recorded commit, read once by gitlinks from git ls-files -s. It is empty outside a repository. store hashes a submodule by its pin, so a module's digest sees a new pin on every clone, and a directory anchor inside a submodule stands for that pin. Snapshot reads the same list.
  • Head (gitx.go): the current commit, or an empty string outside a repository or before the first commit.
  • WorkingFiles (gitx.go): git ls-files --cached --others --exclude-standard. It is the set the fingerprint counts, except that .abbd/ stays in. It lists a submodule as one path, never lists an ignored file, and returns nil outside a repository, where store walks the disk instead.
  • Paths relative to dir (gitx.go): every function takes and returns paths relative to the directory it was given, through -C, --relative and the ./path form in Show. A project root below the repository top still works.
