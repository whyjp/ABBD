Overview

internal/screen turns the .abbd/ store into the blueprint a human reads. Load reads the store, Build derives a Model, and Files renders the blueprint's files. The pages are static HTML with no script, cut from the one model: index.html holds the overview, the flows and the stacks, each module or feature that holds units has its own <ID>.html, and contracts.html and units.html index every contract and every unit. graph.json holds the unit rows, every live relation, the overview drawing, the full module views and the figures, for tools. The CLI's publish (cmd/abbd/screen.go) runs after every command marked writes (setup, sync, record relation|unit|parent|fact|evidence, retract, migrate, understand, forget, flow, stack). It renders nothing for an empty store. Once every file is written and any other file under blueprint/ removed, it records in the state's Blueprint the inputs hash it rendered from and in Rendered the hash of the files it wrote, so no file holds any value of the sync. abbd status reuses Load, through the same screenInput, for its freshness verdicts, and the page points at abbd status instead of stating one. The package imports internal/model, internal/store, internal/topology and internal/narrative, never writes the topology, and draws no box the store lacks, apart from a focus view's twin.

The overview draws each top-level module and feature as a box, and a top-level contract no module provides as a loose box. A blue contract line runs from a user's chip on the bottom edge to the provider's chip on the top edge. One chip stands for the contracts that line carries, named when it is one and counted when it is more, and the contracts no line reaches fold into one +N 계약 chip on the provider. A thick orange bypass line marks a module dependency no contract line already carries. Two modules that depend on each other that way share one mutual line with a head at each end. A relation from a unit at any depth is lifted to the top-level unit that contains it. INFERRED couplings are drawn too, because sync rechecks their quotes. Only dead ones are dropped, and a drifted one is drawn like a live one. A drawn edge counts as extracted when any relation under it is the script's, else stated, else inferred. A small circle at a line's start marks a reader's or a human's relation, a bundle of both is mixed, and a dashed line runs against the reading direction. Every top-level module and every unit that holds others has its own view, and a box links to one only when viewOf names it, so no link opens a missing page. A feature with no parts has none. Everything is sorted before it is placed, so the same store always draws the same picture. docs/blueprint-svg.md states the drawing rules. legible_test.go measures them per line and channel, and trace_test.go traces every relation along the drawn ink and counts the bends and the short jogs on its path.

Key Concepts

  • Input / Model (screen.go): Input is what Load reads, including each module's understanding and its code digest now. Load leaves Tree, the git snapshot, for the caller to fill. Model is what Build derives. It holds the unit catalogue, the Overview, Links between two contracts listed as text, one Inside per view, the overview's Focus views, every live relation as []Line for graph.json (graph.go), and the extraction command the page footer names.
  • tree (tree.go): the parent tree the views follow. A unit whose parent is absent moves to the top level, so nothing present drops out. A unit with children and no live relations of its own is abstract, and an inside box for it draws its members' relations (sources). within and outside say which child of a view, or which largest unit outside it, stands for an end.
  • overview (overview.go): the plan planOverview builds and the insides reuse. top lists the top-level units and the live relations between them, with the stored relations and origins each drawn edge stands for. Each top-level contract gets its providers and users, and a module that provides a contract is not drawn as its user.
  • Drawing / Box / Port / Wire (overview.go): one SVG picture with its coordinates set. A Box is a top-level module or feature, an inside unit, or a loose contract. Its Href opens a view the blueprint holds, and it stays empty when there is none. On the overview, chipFor makes one chip per set of contracts a drawn line carries, labelled with its one contract or with 계약 N개 joined by a no-break space so shorten keeps the word. A module whose chips need more than chipWrap wraps them into at most two rows instead of widening, and the last row folds what does not fit into one "+N" Port. settle then moves a single unfolded row of chips over the x their lines run at. A chip is at most chipMax wide: chipLines wraps a longer label onto more lines, broken after a separator or before a space, so it is never cut and never leaves its edge, and every chip in a row takes the row's height, which chipBand sums for a box or a frame edge. On an inside frame, two ports that land on one spot share a chip, and its Keys name every port it stands for. Drawing.Relations lists the pairs of places the view requested before routing, which the checker holds the ink to.
  • arrange / layered (layout.go, layered.go): the layered layout. It orders nodes to leave few edges pointing back (Eades, Lin and Smyth), ranks without those edges, and sets each node above what it uses. A node nothing uses sits just above the highest thing it uses, and nodes with no line gather on a bottom layer. Each pair of places more than a row apart gets a chain of dummies. order sorts every row, chains included, then sets a box joined to nothing last in its row, and wrap splits a layer wider than the budget. shed takes the shortest chains out while the rows are still too wide with every chain crooked. place treats each box and each straight run of a chain as one block, Brandes and Köpf style. Each chain, longest first, becomes as few runs as it can: a run grows down while the order holds and the drawing fits its budget, found by halving. shorten then moves an item along its row, past up to moveMost items, where that saves more than crossCost of line on the placed drawing, a crossing counted as crossCost, and the rows are placed again unless that takes the drawing past its budget. A focus view passes a focusSeat, so seat orders rows by the full view's x, brick deals a wide ring into interleaved rows, and ring packs each row around the focus on one vertical axis.
  • route (route.go): orthogonal routing on that grid. A line crosses each gap on its own track and passes rows down its chain or between boxes. A line with no chain keeps the x it passed the row above at where the row lets it, and gutterTo steps it aside toward its end. A chain no line uses keeps no room, a passing line keeps off the stubs into the boxes beside its row, and the lines of a box's chips and of the box itself never share an x on one edge. Lines of one kind that leave one box share a departure trunk through every row two of them still pass. Two or more lines of one kind into one box edge share an arrival bus, unless they all ride one departure bus into different boxes, and boxes in one row share one only when exactly the same places reach them. Boxes that the same two or more places all reach may share one arrival bus instead, from share. route draws a view both ways and keeps those shared buses only when weigh, on the routed ink, finds no more touching ink of one kind between unrelated places, crossings or side-by-side runs, and fewer bends and jogs along each line's whole way. A view with more than shareMost requests is drawn plain, since weigh compares every pair of strands. viaX keeps a step off a departure track between the two trunks, and stepX finds a step onto an arrival track at the nearest clear x. Each bus is drawn once with its line count, and place sizes each gap with room for the counts.
  • junctions / anchor (ink.go): what the routed paths look like to a reader. junctions puts a Dot wherever ink of one colour goes three or more ways, and where a line crosses onto a trunk of its own kind that runs past it. anchor sets each ×N beside its own stub or drop, on the side where the nearest other ink is farthest.
  • Inside (inside.go): one view built by (*overview).inside, within a 920 pixel budget against the overview's 1320. Its frame carries the module's contracts and dashed ← name or → name ports for units outside it met without one. Lines from outside units into inside units come in on top. A crowded side hands its least committed ports to the other side, and the frame never grows past the budget. It also holds Units with one sentence each, Unwired contracts kept off the frame and grouped by a first word that three or more share, Inferred couplings with an end in the module or a direct child, Up and Trail, and the Understanding of the module the view is for. Every top-level module and every unit that holds others has a view, so a nested module that holds units shows its text beside its own inside. One that holds none has no view, and Build puts its text on its InsideUnit in the parent's view, where the page folds it under the unit's entry.
  • Focus (focus.go): a view cut from a dense one, which has more than two boxes and more than twice as many relations as boxes. Each module or feature box of a dense overview gets one, and each box of a dense inside. planOverview or inside plans the full view and keeps only the lines with an end at the focus and the boxes at their other ends, so a focus view never draws a line the full view lacks. A unit that both uses the focus and is used by it is drawn a second time below as a twin, ID <unit>↓, and base maps it back. Focus views take the overview's width. The overview's sit on index.html, and an inside's on its module's page. A focus view of an inside names its boxes by their last path segment. Focus views link each ring box to its own focus view, and stay out of graph.json. Pages gives a copy of each full view to linkFocus, which makes each box that opens nothing else open its focus view. centres keeps the ring in the full view's order. TestFocusViewsArePartialGraphsOfTheirView and TestFocusViewsKeepTheMapOfTheirView hold both rules.
  • Freshness (screen.go): ActualFreshness compares the working-tree snapshot with the synced fingerprint. BlueprintFreshness compares the state's Blueprint, the inputs hash the blueprint was rendered from, with the inputs hash now. It also compares the state's Rendered with Input.Rendered, the store.BlueprintHash of the files there now that Load reads, so a page missing, added, edited or left from an older render reads STALE, a module's own page included. Either is UNKNOWN when a side is missing, and either is STALE when the state is Merged, since a merged state's values match neither the merged tree nor its inputs. Model holds no freshness verdict and no value of the sync, so a render changes only with the data.
  • Understanding (words.go): a how text cut into Blocks of headings, list items, paragraphs, pipe tables and fenced code, and Spans of plain, code and bold text. blocks reads the text through narrative.Lines, so the page splits it at the headings the readability report counts, and a # or | line inside a fence stays code. A fenced block becomes one block of kind pre, whose Code holds its lines as written. A table's Rows start with its header, drop the rule line and keep an escaped \| in its cell. It is marked Stale when its stored digest differs from store.ModuleDigest, which hashes the files of the module and of every unit under it at any depth, and the lines around the quotes they cite in other files. The template draws it through howhead and howtext in both places, and howtext draws its blocks with the blocks template the notes use too. It escapes the text and never trusts its markup.
  • Note (notes.go): one slot note as the page shows it: its heading and key, Stale with the places that changed, its blocks and quotes, for a decision the human's why and source, and who reread it after its code moved and on what date. A note whose slot abbd does not know, whose file is not where its slot's note belongs, or whose entry its contract no longer lists, shows nowhere. placeNotes runs last in Build. A module's notes go in its own Inside, or under its entry in its parent's inside when it has none. A contract's go in the inside of its home: the module it sits in when that module provides it, else the provider whose provides relation, its own or one of a unit inside it, rests on the strongest origin, so a reader's coupling never moves a contract away from the provider the code shows. A unit no inside shows keeps its notes on its row of the unit list.
  • Entries (entries.go): a contract's entries as one table, one EntryRow each with the entry's name and shape, its need, the units that provide it and those that use it from topology.EntryUses, and the reader's entries note on it. The shape column reads 시그니처, or 타입 for a contract that holds data, and the use columns read 쓰는 단위 and 읽는 단위 there. A column no row fills is left out. The page draws the table across the whole inside of the contract's home, below the drawing and the text, so nothing in it is cut. A header never breaks, an entry's name or shape keeps to one line up to 40 characters and wraps anywhere past that, so a long route or type with no space stays inside the page, and the description column takes the rest of the width and wraps. Each row's id is e- with the contract's ID and the entry's key, so two contracts with an entry of one key keep their own rows. A contract with entries shows in its home's inside even with no notes, and an entry's note shows on its row rather than among the contract's notes.
  • site / Files (page.go, page.html, page.css): the embedded Korean template, one named template per kind of page (index, module, contracts, units) around a shared head and foot, with its origin and kind labels and hover tips. The css func inlines page.css into every page, so each page opens on its own. A module's page shows its inside as .inside.page, and a focus view stays hidden until its anchor is the target. Files renders every page through Pages and adds graph.json, all from the model alone, so the same store renders the same bytes whatever sync wrote them.
  • Pages (site.go): one page per file, each with its Title, its template and Current, the anchor of its own view (overview, m-<ID>, contracts or units). A module page carries its Inside and a Trail of the modules above it, which the breadcrumbs draw. Every page carries the Nav from navTree: each module that has a page, under the module that holds it, siblings by name. The nav lists modules and features under separate headings, a top-level feature and everything under it counting as a feature, and marks the current page with aria-current. TestTheNavListsFeaturesApartFromModules holds that split on this repository's own state. Paged names the units that have a page, so a unit's name links there.
  • Indexes (site.go, page.html): contractRows lists every contract grouped by kind, IF, EVT, DATA, then CFG, and by name within a kind. Each row names the module it sits in as its owner, and the units whose live relations provide and use it. Each is a Ref to the unit's page when it has one, else to its row u-<ID> in the unit index. units.html lists every unit by ID with its kind, its parent, its responsibility or purpose, its anchors, and its signature and quotes folded, so the browser's find reaches any ID, name, path or symbol.
  • link (site.go): the template links by anchor, href="#id", as if the site were one page. link reads every id each page holds and rewrites each anchor after all pages render. An anchor that is another page's own view opens that page at its top, an anchor the page itself holds stays as it is, and any other opens the first page in order that holds it, as FILE#id. An anchor no page holds stays unchanged. site_test.go checks that every link opens a page and a section that exist.
  • Figures (figure.go, flow.go, stack.go): flows derives one FlowView per stored flow and stacks one StackView per stored stack. figureID anchors a figure at flow-KEY or stack-KEY, and partID a part at flow-KEY.N or stack-KEY.N, which no key can produce. A part is STALE when Part.Why gives a reason, its code moved or the state lost what it names. A figure's badge is its weakest part origin, and in a mixed figure partMarks gives a part the human stated its own badge and source. In a flow, consecutive steps on one unit share a Lane, and a call shows only when Step.Against finds its relation. In a stack, each Band shows its layer's units as UnitChips, and each breach model.Breaches finds sits in the band it leaves as a BreachChip that names both ends, the relation's verb and the higher layer. A lower unit that provides a higher layer's contract shows no chip. A stack's Reasons are the texts of Figure.Gaps. href sends a click to the unit's own inside, else to the inside of the nearest unit holding it, else for a contract to its note home's inside. linkFigures lists on each inside the steps on the units it holds and the layers that hold its units, by number. page.html draws a flow as a numbered list and a stack as a list of bands, both in HTML that wraps every line, and lists every flow and every stack by its question on the overview. At 560px and below a lane's unit and a band's name stand above their contents.
  • Real states (fixtures_test.go, testdata/): the unit files of four real stores, this repository, ripgrep, Orca and pstack, as sync left them. TestEveryRealDrawingIsLegible measures every full and focus view of each against docs/blueprint-svg.md's rules. debt lists the views that do not keep them yet with what they measure now: a listed view may only improve, and the test fails once it keeps every rule and is still listed. chips_test.go measures a small hand-written drawing whose chips leave their box and the canvas, so the escaped-chip count cannot read 0 unnoticed.

origin display words 둘레 DATA-0014

internal/screen의 안에서 고른 상자 전체 그림으로
