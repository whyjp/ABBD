Overview

internal/screen turns the .abbd/ store into the blueprint a human reads. Load reads the store, Build derives a Model, and Files renders the blueprint's files. The pages are static HTML with no script, cut from the one model: index.html holds only the overview, each module or feature that holds units or has a focus view on the overview has its own <ID>.html, each flow, stack and table has its own page, and contracts.html and units.html index every contract and every unit. graph.json holds the unit rows, every live relation, the module lists without their drawings and the figures, for tools. So a change rewrites the pages of the views that draw it, and a change inside one module rewrites that module's page and graph.json. The pages and graph.json cite a quote by its file and words through cite, without its lines, so moving a quote's lines alone rewrites no page. A change to the lines around a quote marks its claim STALE, and that mark lands on the pages that show the claim. The CLI's publish (cmd/abbd/screen.go) runs after every command marked writes (setup, sync, record relation|unit|parent|fact|evidence, retract, migrate, understand, forget, flow, stack, table). It renders nothing for an empty store. Once every file is written and any other file under blueprint/ removed, it records in the state's Blueprint the inputs hash it rendered from and in Rendered the hash of the files it wrote, so no file holds any value of the sync. abbd status reuses Load, through the same screenInput, for its freshness verdicts, and the page points at abbd status instead of stating one. The package imports internal/model, internal/store, internal/topology and internal/narrative, never writes the topology, and draws no box the store lacks, apart from a focus view's twin.

The overview draws each top-level module and feature as a box, and a top-level contract no module provides as a loose box. A contract line runs from a user's chip on the bottom edge to the provider's chip on the top edge. One chip stands for the contracts that line carries, named when it is one and counted when it is more, and the contracts no line reaches fold into one +N 계약 chip on the provider. A thick bypass line with an open head marks a module dependency no contract line already carries. Two modules that depend on each other that way share one mutual line with a head at each end. A relation from a unit at any depth is lifted to the top-level unit that contains it. INFERRED couplings are drawn too, because sync rechecks their quotes. Only dead ones are dropped, and a drifted one is drawn like a live one. A drawn edge counts as extracted when any relation under it is the script's, else stated, else inferred. A small circle at a line's start marks a reader's or a human's relation, a bundle of both is mixed, and a dashed line runs against the reading direction. Every top-level module and every unit that holds others has its own view, and a box links to one only when viewOf names it, so no link opens a missing page. A feature with no parts has none. Everything is sorted before it is placed, so the same store always draws the same picture. docs/blueprint-svg.md states the drawing rules. legible.go measures them per line and channel, trace.go traces every relation along the drawn ink and counts the bends and the short jogs on its path, and lint.go holds every drawing to the Drawing criteria on top of both.

Key Concepts

  • Input / Model (screen.go): Input is what Load reads, including each module's understanding and its code digest now. Load leaves Tree, the git snapshot, for the caller to fill. Model is what Build derives. It holds the unit catalogue, the Overview, Links between two contracts listed as text, one Inside per view, the overview's Focus views, every live relation as []Line for graph.json (graph.go), and the extraction command the page footer names.
  • tree (tree.go): the parent tree the views follow. A unit whose parent is absent moves to the top level, so nothing present drops out. A unit with children and no live relations of its own is abstract, and an inside box for it draws its members' relations (sources). within and outside say which child of a view, or which largest unit outside it, stands for an end.
  • overview (overview.go): the plan planOverview builds and the insides reuse. top lists the top-level units and the live relations between them, with the stored relations and origins each drawn edge stands for. Each top-level contract gets its providers and users, and a module that provides a contract is not drawn as its user.
  • Drawing / Box / Port / Wire (overview.go): one SVG picture with its coordinates set. A Box is a top-level module or feature, an inside unit, or a loose contract. Its Href opens a view the blueprint holds, and it stays empty when there is none. On the overview, chipFor makes one chip per set of contracts a drawn line carries, labelled with its one contract or with 계약 N개 joined by a no-break space so shorten keeps the word. A module whose chips need more than chipWrap wraps them into at most two rows instead of widening, and the last row folds what does not fit into one "+N" Port. settle then moves a single unfolded row of chips over the x their lines run at. A chip is at most chipMax wide: chipLines wraps a longer label onto more lines, broken after a separator or before a space, so it is never cut and never leaves its edge, and every chip in a row takes the row's height, which chipBand sums for a box or a frame edge. On an inside frame, two ports that land on one spot share a chip, and its Keys name every port it stands for. Drawing.Relations lists the pairs of places the view requested before routing, which the checker holds the ink to. A line's ink is drawn in pieces, its stub, the buses it rides and their drops, so route also gives each request a Route along its whole way (routing.ways), drawn unseen above the ink in its source's colour and taking no pointer, with arrowheads that are <use> of heads painted in the route's own colour. A route turns where its line's ink turns, so a line that rides a bus past its drop and back shows that detour lit too, and TestFewLinesDoubleBack holds such lines to a count that may only fall. hover numbers a drawing's boxes and chips, a twin with its unit and a contract chip with its box, classes each route and dot by the shapes at its ends, each piece of ink by every route that runs along it, and each shape by the shapes its relations join it to. The fixed hoverCSS rules, with no script on the page, fade all the ink while a reader points at ink or a shape and show the lines lit as their routes, whole: pointed-at ink shows every route along it in its own colour, with its marks and its ends, and keeps its title, and a pointed-at box shows exactly its one-hop lines in the box's colour (--kN, set by paint). A drawing with more than hoverMax shapes or routeMax routes takes no part, and only a page with a drawing carries the rules. A climbing line is drawn in a lighter tint of its colour, and faint lightens the dots only climbing lines meet at.
  • Lead / Zone / dress (lead.go, zone.go, dress.go): what a view adds to read like a hand-polished diagram, after paint. lead picks the view's lead: the stored flow whose steps run furthest on the view, each next step on a box a drawn line joins to the lead, or, with no flow stored, the line chain from the one box no other box uses, along the line with strictly the most relations, stopping at a tie. Fewer than two hops draws none. Each hop is a route the view already draws, numbered with a badge off boxes, labels and counts, and quiet greys every other line, head and dot while routes keep their colours for hover. zone tints the boxes of a stored stack's layers, else of a shared directory (home), plus the outside contracts, only where their padded area holds no other box, chip or band; its title takes the corner fewest lines cross. dress dots a line whose relations all arise by convention, import, trait, macro or build feature, fills a hub (half again as many lines as any other box) where no lead fills its entry, and gives each box a small-caps kind and role line where its chips leave room. A quiet view drops a label that now stands over a flat track of another line of its colour (unlabelKin). A view past hover's caps is never made quiet, and chips on a filled box carry OnFill for a panel outline. The overview key reads Quiet through legendFor, so a quiet view's key draws the bypass grey. Box.Role carries entry or hub apart from Class, which the level check reads. A hub's view is quiet too, but hubLines keeps in the hub's colour the ink whose every route has the hub at one end. page.css draws each coloured box with a 1.5px border in its colour over a 5% tint (tintMix), with no bar. It draws a pointed-at or focused box's border in its own colour (--c), the colour hover lights its lines in, and darkens a filled box instead; a focus view's centre box keeps its weight. It also draws a bypass at the 1.5px of any other line, so its orange and open head mark it without the weight.
  • arrange / layered (layout.go, layered.go): the layered layout. It orders nodes to leave few edges pointing back (Eades, Lin and Smyth), ranks without those edges, and sets each node above what it uses. A node nothing uses sits just above the highest thing it uses, and nodes with no line gather on a bottom layer. Each pair of places more than a row apart gets a chain of dummies. order sorts every row, chains included, by one tactic, then sets a box joined to nothing last in its row. Build lays each view of a unit out with every tactic, and choose keeps a later tactic's drawing only where its cost beats the best so far, which starts as the first tactic's. The overview keeps the plain order of its rows, since every module's page holds a focus view seated by it, but choose picks its ranking from overviewTactics: plain, fold, which leaves the edges of two places that use each other out of the ranking, as one two-headed line joins them, and entry, which breaks each cycle at the node the places already ranked use most. arrange marks a fold or entry that changes nothing idle, and the draw closure skips it. For the overview cost.over is how far the drawing runs past one screen (criterion S): screenW wide and the view's room tall, screenH less what its page sets above the drawing, the overview's questions (overviewRoom) or a page's note. Whether it runs past is weighed right after the hard breaches and how far only after lint's weighed sum. A fold or entry drawing is passed over when it moves more boxes than the least plainly ranked one, or when it neither has fewer hard breaches nor fits where the plain one does not, so a small change cannot flip the overview's ranking to save a few turns; fold_test.go holds the fold and fit_test.go the choice. judge lints each drawing of a unit's view as abbd lint does, except one that already loses to the best so far on the touches and breaks of its routing, which beats compares first. cost.beats compares touches, then breaks of rules 13 and 15, then lint's hard breaches, then the overflow, then the crossings plus the excess turns plus stepCrossings times the staircase steps lint traces on the page, then lint's weighed sum, both with stepCrossings more for each placement breach and each chip folded into a "+N" chip, which its Port marks Folded, so a line that turns twice in a clear column, 2 excess turns and no step, cannot buy crossings, then stepCrossings times the staircase steps plus the crossings, the steps counted once per pair of places along each line's way from the routing that route returns, then the steps alone, paths that turn more than twice, braid and dashed ink, and the first measure that differs decides. A step is a turn past a line's second or a jog, and it weighs as much as 4 crossings. A seated tactic also sets a unit's wired frame chips as chipNode rows above and below the boxes, ordered and placed with them, so each chip stands over the chain its line takes and keeps that x as settle's target. A view whose chips do not fit their sides, a focus view and the overview are not drawn seated or laned, since a chip handed to the other side would leave the seat or lane it was set over behind, and the draw closure says so. lane_flip_test.go holds a one-box view and a three-row view to that guard, and shows the three-row view takes lanes once its chips fit. A laned tactic instead gives each wired frame chip whose lines pass rows a lane, one chain from the frame's edge down every row its lines pass, joined in each row to the boxes it meets in the next (proper); place pulls the lane toward the nearest box it reaches, route runs the chip's lines down it, and the chip stands over its first row. With follow, order then moves each lane among the other items of its row to where what it joins in the next row stands, rows bottom up for top lanes and top down for bottom ones, so a lane runs beside its box. A loose tactic leaves the chips to be set after the layout but has both sweeps of order place every dummy of a chain from the frame's edge by its box end alone: otherwise a sweep down sets each under its dummy in the row above, so chains from the frame keep their first order all the way down, and one that ends on a box left of the others runs right of them and turns across them into it. The draw closure skips it for a view with no wired frame chip. A cover tactic, plain or loose, marks a chip one when every line of it runs down a chain from the frame's edge that has lanes for more than one line, in a view that is not a focus view; settle then stands such a chip off centre, back to where its line still meets its edge 4px in, when the chip before it would push it off its line, and the chips before it give way while their own lines still meet them. Two chips over one box whose lines share a chain 16px apart then stand edge to edge over their lanes, and both lines drop straight. The draw closure skips it for a view with no such chip. A reorder tactic, loose and cover, then lets reorder move chips of each frame edge to other places in their order while fewer chips stand over none of the x their lines run at (attach.runs), then less distance from them: on a crowded edge the order of the mean x pushed a chip with one line far off it while a chip whose lines spread wide stood where that line runs. It is drawn only where it moves a chip, and reorder_test.go holds src/'s bottom edge to it. A gather tactic, plain and median, draws one chip per box and edge for the modules outside that meet that box with no contract (a port keyed by gatherPort and the box, a key no title, label or link shows), named while the names fit gatheredPx and the label fits one line, cut only between names and counted as +N past that, so each box takes one line from the frame. Each gathered line keeps the tooltip line and evidence of every line it gathers, said with its real far end, and a chip that gathers one module links to that module's view. It is drawn only where some outside module meets two or more boxes, choose passes over it where it crosses more than the least of the ungathered drawings, and a gathered view's focus views gather the same way (Inside.gathered); gather_test.go holds it. choose passes over a laned drawing whose cost.moved, its placement breaches and folded chips, exceeds the least of the view's unlaned drawings that judge read by more than laneMoves (1), or whose weighed sum passes the least of theirs: lanes save steps by standing chips off their boxes and trade excess turns for steps, which seen weighs less than the gate does. Each ordering is drawn twice: wide, where place lets every block spread over the whole budget toward what it joins and then trims the drawing to what the blocks cover, and narrow, packed as tight as the order lets it, at narrowBudget for a unit's view. The draw closure leaves each drawing's cost in the read it is handed, and a focus view, handed none, is never weighed. wrap splits a layer wider than the budget into rows. Where the boxes with a line to what lies below fit in a wrapped layer's last row, stack puts them there, so their lines leave from the bottom row. shed takes the shortest chains out while the rows are still too wide with every chain crooked. place treats each box and each straight run of a chain as one block, Brandes and Köpf style. Each chain, longest first, becomes as few runs as it can: a run grows down while the order holds and the drawing fits its budget, found by halving. shorten then moves an item along its row, past up to moveMost items, where that saves more than crossCost of line on the placed drawing, a crossing counted as crossCost, and the rows are placed again unless that takes the drawing past its budget. A focus view passes a focusSeat, so seat orders rows by the full view's x, brick deals a wide ring into interleaved rows, and ring packs each row around the focus on one vertical axis.
  • route (route.go): orthogonal routing on that grid. A line crosses each gap on its own track and passes rows down its chain or between boxes. A line with no chain keeps the x it passed the row above at where the row lets it, and gutterTo steps it aside toward its end. A line whose x is the lane its own chain holds in a row keeps straight on it past a wide gap, when it stands 12px off the boxes, no other chain runs in that channel and no stub or other pass comes within a lane, so it does not swing out to the gap's middle and back. A full view drops a line between rows next to each other whose boxes' spans meet straight as well, outside hubs and shared buses, and keeps that drawing only where weigh finds it beats the bundled one. A line that leaves its departure trunk where the trunk ends runs on at the trunk's x in the next row unless another line steps down off that trunk in the same gap, and on a chain from the frame whose lanes carry one chip's lines of more than one kind, the lanes spread over the chain's width so two stems never run side by side. A chain no line uses keeps no room, a passing line keeps off the stubs into the boxes beside its row, and the lines of a box's chips and of the box itself never share an x on one edge. A line alone in its slot that passes no row and runs down no chain, between boxes in rows next to each other or between a frame chip and a first- or last-row box, takes the x its other end already stands at when that edge has it clear, so it drops straight. A frame's edge keeps no list of the stubs set on it, so there clear means only on the edge and off the chains passing the next row. Lines of one kind that leave one box share a departure trunk through every row two of them still pass. A line leaving its departure trunk for an arrival trunk below its top steps down a little before it on a via, except where joinsHarmless says the join misleads no reader: then its track runs onto the trunk and keeps the via's x for the others. The arrival trunk a line leads may pass a row where that line's own departure trunk ended, so it runs on down the lead's chain instead of swinging out to a gap's middle.
