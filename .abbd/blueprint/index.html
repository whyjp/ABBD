Overview

cmd/abbd is the ABBD command line. It is one package main that dispatches fourteen verbs over the .abbd/ directory, where a repository keeps its architecture topology. Humans and assistants run it from a shell, and the block that abbd install writes into CLAUDE.md points assistants to the /abbd skill for how to use it. The usage text calls the CLI a lever. It registers the project's extraction script and proves it deterministic. It keeps unit IDs stable across runs and checks every quoted piece of evidence against the working tree. It records what readers infer and what humans state, stores pstack how's module texts, and answers explain, path and impact queries. It never judges, blocks, asks or records a decision. Even diff --check only exits 1 when a change reaches the boundary between modules, so a CI job can label the PR.

The package is glue. The logic lives in internal/. identity reconciles IDs, evidence checks quotes, topology answers queries and diffs, screen renders, store owns the on-disk format, gitx reads git, extract parses the script's JSON, bootstrap folds in the supplement, and group adds directory groups when a view gets crowded. cmd/abbd parses argv against a declarative command table, applies the CLI rules for records, wires those packages together in a fixed order, and prints results line by line. After every verb that writes, run calls publish, which re-renders .abbd/blueprint/index.html and then graph.json.

Key Concepts

  • Command table (main.go): the commands map. Each verb names its flags from flagDefs, its allowed positional counts, whether it takes -- ARGV, and whether it writes. parse joins the first two words to find verbs like record unit, and parseInterspersed accepts flags anywhere on the line. A usage error exits 64 and a failed verb exits 1.
  • Sync pipeline (main.go): syncActual loads the stored units, candidates and state, snapshots the tree, reads git renames since the last fingerprint, and runs identity.Reconcile. It then runs evidence.Apply and group.Fallback and saves units, candidates and state. It refuses an extraction with no units when units are already stored.
  • Guesses mode (main.go): sync passes identity.KeepGuesses, so stored INFERRED facts survive a script that cannot see them. setup passes identity.ReplaceGuesses, so the supplement owns the guesses. A guess it drops is withdrawn unless a human stated something about that unit.
  • Determinism proof (setup.go): deterministic runs the script three times and demands identical output. The third run sets new PYTHONHASHSEED and PERL_HASH_SEED values. A mismatch reports the first differing line, and nothing is saved.
  • Origin (record.go): EXTRACTED comes from the script, INFERRED from a reader with --evidence, and USER_STATED from a human with --source. recordRelation never overwrites an EXTRACTED relation and never lets an INFERRED finding replace a USER_STATED one. recordParent places a unit inside another module or feature, INFERRED with --evidence or USER_STATED with --source. It refuses a directory group that sync made.
  • Live citation (record.go): citations parses each PATH:LINES:QUOTE, normalizes it with extract.NormalizeEvidence, and refuses a quote the working tree does not hold now. A unit from record unit has an INFERRED name and stays present only while its evidence is live. Its --parent must be a module or feature of the state. That parent is the reader's, INFERRED on the unit's own evidence. So a later sync keeps it when the script takes the unit over without a parent of its own.
  • Query resolution (query.go): find takes a unit ID, a name, a file, a directory, a symbol or a phrase through topology.Find. A match that is not exact prints the best five with reasons. impact also seeds every other unit anchored at a queried path.
  • Fingerprint (install.go): a git tree object of the working tree minus .abbd/, saved in the state at sync. status reports STALE when it no longer matches the tree. keepingCurrent moves it along when install edits CLAUDE.md while the state is current.
  • Understanding (understand.go): how's text for a top-level module, stored INFERRED with store.ModuleDigest. understand refuses to store the same text again on changed code, and explainHow shows it as CURRENT or STALE.

Overview

internal/bootstrap is one file, overlay.go, with one exported function, Overlay. Only abbd setup --supplement FILE calls it. By then setup has proved the extraction script deterministic and parsed its output. Overlay folds the semantic supplement onto that script result. The supplement is JSON that pstack's readers write, and the setup skill puts it at .abbd/extractor/supplement.json. The script reports what the code shows mechanically. The readers add what only reading reveals. That covers a unit's purpose and responsibility, units the script cannot see, which module or feature a unit sits in, and couplings through a callback, a config flag or shared data. Overlay returns one extract.Result, which syncActual hands to identity.Reconcile. It does no I/O and assigns no IDs.

Overlay is a gatekeeper as much as a merger. Anchors always come from the script, and so do the names and signatures of the units the script reports. A reader's signature lands only where the script reads none, and then it is INFERRED. Everything the supplement adds is INFERRED and must tie to code. A unit that matches no script unit needs evidence, and so do a parent and a coupling the script did not extract. When something cannot be tied to code, Overlay returns an error that says how to fix the supplement. setup then stops before SaveProject, so nothing is written. Units that match nothing and cite no evidence are collected and reported together in one sorted error.

Key Concepts

  • Script result (overlay.go): base, the parsed script output. Overlay copies its units and relations and gives any keyless unit the key #<i>. newScript indexes those units by key for matching and parent lookups.
  • Supplement (overlay.go): doc, parsed by extract.ParseSupplement. It shares the script's schema and checks, but its units may name the key of a script module or feature as their parent. Its other keys are local to the file.
  • Anchor matching (overlay.go): match picks the script unit of the same Kind that shares the most anchors, compared by model.Anchor.Key(), which is path#symbol. When the best matches nest, as a package directory holds its sub-modules, the innermost wins. No overlap, or a tie between units that do not nest, is an error. Names are never compared.
  • Semantic unit (overlay.go): a supplement unit with evidence, which says the script cannot see it. semantic() copies it under the key supplement#<n> with an INFERRED name and no digest, and clears its signature and parent for the later passes to set as INFERRED. It is an error if it shares an anchor with a script unit, unless that unit is its named parent or an ancestor of that parent and their anchors differ.
  • Supplement parent (overlay.go): a parent key looked up first among the supplement units that landed, then among the script's keys. It must be a module or a feature, the two kinds model.Kind.Holds allows. It rests on parent_evidence, or else on the unit's own evidence, and is stored with ParentOrigin INFERRED.
  • Reader coupling (overlay.go): a supplement relation whose ends both landed. One the script already extracted is skipped. Any other must cite evidence and is appended INFERRED with its Via.
  • Findings (overlay.go): Matched counts the supplement units that landed, semantic ones included. Conflicts lists a documented signature the code contradicts and a second supplement unit on the same code. setup prints each as a conflict line and carries on.

Overview

internal/model is ABBD's vocabulary. It holds the Go types for everything stored under .abbd/architecture/ and .abbd/features/, plus the rules that decide which values are legal. It is one file, model.go, of about 470 lines, and it imports only the standard library. Every other internal package but gitx uses it (extract, bootstrap, identity, evidence, store, topology, screen, group), and so does cmd/abbd. It does no I/O, runs no git and renders nothing.

The package exists to keep provenance honest. Every name, why-field, signature, parent and relation carries an origin. EXTRACTED means the deterministic script read it from code. INFERRED means a pstack reader found it. USER_STATED means a human said it, and the record says where. Unit.Validate enforces the consequences. A USER_STATED fact, parent or relation needs a Source, and no other origin may carry one. A why-field is never EXTRACTED. An INFERRED name, parent or relation needs evidence, but an INFERRED purpose or responsibility does not. Only contracts carry a Signature, and a parent must be another module or feature. RelationKind.Joins checks that an edge joins legal kinds. ParseEvidence and ParseEdge read what abbd record gets on the command line. Downstream code branches on small predicates. Relation.Counts holds a relation to live EXTRACTED and USER_STATED edges, and topology.Compare uses it to decide which relations between modules abbd diff --check sees. Its comment says a reader's coupling is not drawn, but the blueprint's overview now draws live INFERRED edges too. Present drops absent units.

Key Concepts

  • Unit (model.go): one design unit. It has an ID, a Kind, a Name fact and at least one Anchor. It may have a Parent, the module or feature that contains it, with ParentOrigin, ParentSource and ParentEvidence, its own Evidence, the why-fields Purpose and Responsibility, a contract Signature and Digest, outgoing Relations and the Absent flag. The user-owned Notes stays out of the YAML. Semantic reports an INFERRED name.
  • Kind (model.go): MOD, the contract kinds IF, EVT, DATA and CFG, and FEAT. Dir() sends features to features and the rest to architecture. DOM, STATE, TRN and INV are reserved and rejected. Holds() is true for MOD and FEAT, the two kinds that may contain others. A module holds its units, and a feature holds its parts, such as a skill's steps.
  • ID (model.go): KIND-NNNN, such as MOD-0007. FormatID pads to four digits and ParseID accepts four or more.
  • Fact (model.go): a Value, its Origin, and a Source for USER_STATED only. Guess reports an INFERRED value.
  • Anchor (model.go): the Path and optional Symbol a unit's identity hangs on. Key() is path#symbol, and SortAnchors dedups and sorts by it.
  • Evidence (model.go): a verbatim Quote at a Path, with optional Lines and Symbol. Span parses Lines. Validate refuses paths under .abbd/ or .git/, because those files repeat the quote.
  • Relation (model.go): an edge held by its source unit, with To, Kind, Origin, Source, Via, Evidence, and the Dead and Digest liveness fields. Semantic means it has evidence, Guess means it is INFERRED, and Counts means it is live and EXTRACTED or USER_STATED.
  • Relation grammar (model.go): depends_on joins any two kinds, consumes ends at a contract, and provides runs from a module or feature to a contract. Via is one of import, trait, callback, macro, config, build-feature, data, convention or call.
  • Edge (model.go): From, Kind and To, printed as the shell-safe MOD-0001.depends_on.MOD-0002 and read back by ParseEdge.
  • ParentCycle (model.go): names a present unit whose parents lead back to itself, or returns empty when the parents form a tree. abbd record parent refuses a placement that makes one.

Overview

internal/screen turns the .abbd/ store into the blueprint a human reads. Load reads the store, Build derives a Model, and Files renders two files. index.html is one static page with no script. graph.json is the same data for tools. The CLI's publish (cmd/abbd/screen.go) saves them after every command marked writes (setup, sync, record relation|unit|parent|fact, understand). abbd status reuses Load for its freshness verdicts. The package never writes the topology, and the fold boxes it invents never reach the store.

The overview draws each top-level module and feature as a box. Provided contracts are chips on its top edge and used ones are chips on its bottom edge. A blue line runs from a user's chip to the provider's chip, and a thick orange bypass line marks a module dependency no contract carries. A relation from a unit at any depth is lifted to the top-level unit that contains it. Live INFERRED couplings are drawn too, because sync rechecks their quotes. Only dead ones are dropped. A small circle at a line's start marks a reader's or a human's relation, and a dashed line runs against the reading direction. Every top-level module and every unit that holds others has its own view. An overview box links to its view only when viewOf names one. A feature with no parts has none, so its box carries no link and its title offers no click. Everything is sorted before it is placed, so the same store always draws the same picture. docs/blueprint-svg.md states the drawing rules and legible_test.go measures them.

Key Concepts

  • Input / Model (screen.go): Input is what Load reads. Load leaves Tree, the git snapshot, for the caller to fill. Model is what Build derives. It holds the unit catalogue, the Overview, Links between two contracts listed as text, one Inside per view, every live relation as []Line for graph.json, and both freshness values.
  • tree (tree.go): the parent tree the views follow. A unit whose parent is absent moves to the top level, so nothing present drops out. A unit with children and no live relations of its own is abstract, and its box draws its members' relations (sources).
  • fold (fold.go): a cycle of three or more units in a view becomes one synthetic box, ID <container>~N, whose own view draws the cycle. It folds only a cycle that holds at most two thirds of the view, and never on the overview.
  • overview (overview.go): the plan planOverview builds and the insides reuse. top lists the top-level units and the live relations between them. Each contract gets its providers and users, and each drawn edge keeps the stored relations it stands for and their origins.
  • Drawing / Box / Port / Wire (overview.go): one SVG picture with its coordinates set. A Box is a top-level module or feature, an inside unit, a fold, or a contract no module provides. Its Href opens a view the page holds, and it stays empty when there is none. A crowded edge folds its last chips into one "+N" Port. Wire.Kind is the CSS class. Origin, Marks, Back and Count carry the origin circle, the dash and a bus's ×N.
  • arrange (layout.go): the layered layout. It breaks cycles for ranking only and sets each node above what it uses. It orders layers to cut crossings (order2), wraps a layer wider than the width budget (wrap) and pulls boxes toward their neighbours (align).
  • route (route.go): orthogonal routing on that grid. A line crosses each gap on its own track and passes rows through the gutters between boxes. Lines of one kind that leave or reach one box share a bus drawn once. place then sizes each gap.
  • Inside (inside.go): one view built by (*overview).inside. Its frame carries the contracts of the module or feature it opens and dashed ports for the modules it meets without one. It also holds Units with one sentence each, Unwired contracts kept off the frame, Inferred couplings with their quotes, Up and Trail, and the Understanding.
  • Freshness (screen.go): ActualFreshness compares the working-tree snapshot with the synced fingerprint. BlueprintFreshness compares the rendered watermark with the inputs hash now.
  • Understanding (words.go): a how text cut into Blocks and Spans. It is marked Stale when the module's digest has moved. The template escapes it and never trusts its markup.
  • page / Files (page.go): the embedded Korean template with its labels and tips. Files renders both files with the inputs_hash watermark.

Overview

internal/store is the only code that reads or writes the .abbd/ directory. A Store, built by Open(projectRoot), holds nothing but the path <project>/.abbd, and every call goes straight to disk. Its rule sits in the package comment. Markdown with YAML frontmatter is the source, and everything else derives from it. Each unit is one file named after its ID, such as architecture/MOD-0001.md. Beside the unit files sit state.yaml and candidates.yaml, which sync owns, project.yaml, the module texts under understanding/, and the rendered blueprint/index.html and blueprint/graph.json. UnitsAt also reads unit files at an older revision through gitx.Files and gitx.Show. The package imports gitx and model, and imports identity only for its Candidate type.

The store guards what it keeps. parseUnit and LoadUnits refuse a file whose name does not match its ID, a kind in the wrong directory, a duplicate ID and any unit model.Unit.Validate rejects. SaveUnits validates before writing. writeFile skips a write when the bytes are unchanged. Otherwise it writes a .tmp file and renames it over the old one. The store also computes the fingerprints that mark derived views out of date. It has no cache and no lock. Matching lives in internal/identity, evidence checks in internal/evidence and rendering in internal/screen. Its callers are cmd/abbd, for nearly every command, and screen.Load, which gathers what the blueprint shows.

Key Concepts

  • Unit file (store.go): <kind dir>/<ID>.md. It holds YAML frontmatter with a model.Unit, a generated body with a # Name heading and the anchor list, then an optional ## Notes section the user owns and the store carries through untouched.
  • UnitsAt (store.go): the unit files as committed at a revision, which abbd diff compares with the current ones. A revision without .abbd/ has no units.
  • State (store.go): state.yaml, the sync watermark. Revision is the commit where this tree was first synced, Fingerprint is the gitx.Snapshot tree, MDHash hashes the unit files, and HighWater holds the last number minted per kind.
  • NextID (store.go): mints the next number of a kind and saves it to state.yaml at once. abbd record unit uses it.
  • InputsHash (store.go): a SHA-256 over every file under .abbd/ except blueprint/, including the extractor and the understanding texts. The blueprint carries it as a watermark, and screen calls the blueprint STALE when the two differ.
  • MDHash (store.go): the same hash over the unit files alone. Sync records it in State, and no code compares it today.
  • Understanding (understanding.go): pstack how's Overview and Key Concepts for one module, with Unit, Origin and Digest in frontmatter and the text as the body. abbd understand writes it as INFERRED, and only for a top-level module.
  • ModuleDigest (understanding.go): the first 16 hex characters of a SHA-256 over the files cited by the anchors and evidence of a module and of its direct children, with absent units left out. A missing file hashes as missing. A text whose Digest differs shows as STALE in abbd status, abbd explain and the blueprint.
  • Project (store.go): project.yaml, the argv of the extraction script that abbd setup registers and abbd sync runs.

Overview

internal/topology is the read-only query layer over the stored topology. It takes the []model.Unit slice that internal/store loads, either from the working tree (LoadUnits) or from a git revision (UnitsAt). From ABBD it imports only internal/model. cmd/abbd calls it for its query commands. Find resolves what an agent has in hand to units, and Nearest suggests names when nothing matches. Explain serves abbd explain. Path and Weakest serve abbd path. ImpactOf serves abbd impact. Compare builds the Diff behind abbd diff, and Diff.Boundary drives its --check gate. The package never writes a unit and never opens the store.

Its other job is to keep the three origins apart. EXTRACTED means the script read the relation from code. USER_STATED means a human said it. INFERRED means a pstack reader quoted evidence for it. A dead inferred relation, whose quote is gone, is dropped everywhere. A live one is still walked by ImpactOf and Path, but it carries an (inferred, via ...) label. It sits apart in Explanation.Inferred and Diff.InferredAdded, and it never changes RelationsAdded or RelationsRemoved. A reader of the output can tell what the code vouches for from what a reader guessed.

Key Concepts

  • Find / Match / Tier (find.go): resolves a query best first. An exact ID or name returns at once (ByID, ByName). Otherwise byCode reads the query as a symbol or a path, dropping a :12-30 suffix. It ranks the units whose anchors or evidence hold it, the most specific anchor first. A query with /, \ or . that matched code stops there. Any other query also gets byPhrase matches, scored by the query words a unit's name, descriptions, quotes and files hold.
  • Match.Anchored (find.go): true when one of a unit's anchors is the queried path or a directory that holds it. abbd impact seeds the best match plus every other anchored match, so a path change reaches every unit anchored there. Evidence and phrase matches stay unanchored.
  • Link (impact.go): one live relation between two present units, a model.Edge plus Origin, Via and Evidence. Links is the graph that Explain, ImpactOf and Path walk.
  • ImpactOf / Impact (impact.go): a breadth-first walk from the seeds and the units inside them. It follows what depends on or consumes an impacted unit, and the contracts that unit provides. A contract's provider, and what a seed itself uses, are listed but not followed. Direct holds the seeds, their neighbours and the consumers of a neighbouring contract. Far holds the rest.
  • Path / Hop (path.go): a cheapest-first walk over Links plus nesting, a Contains link from parent to child, each walked either way. Cost compares joints first, then hops, nesting hops and the weakest origin. A joint is two users of one unit meeting through it. markJoints records a joint that remains in Hop.Shares and Hop.Provider.
  • strength (query.go): EXTRACTED 2, USER_STATED 1, INFERRED 0. It breaks Path's last tie and drives Weakest. It also gives a contains hop the weaker of the unit's name origin and its ParentOrigin.
  • Lifting (diff.go): a relation of an inside unit counts as its enclosing unit's. Compare lifts to the top-level unit (top, between). Explain lifts to the unit being explained (own in query.go).
  • Diff (diff.go): units added and removed, changed contract Signatures, contracts whose Code changed under the same signature, drawn top-level relations added or removed, and InferredAdded. Boundary ignores code-only changes.
