Overview

cmd/abbd is the ABBD command line. It is one package main that dispatches seventeen verbs over the .abbd/ directory, where a repository keeps its architecture topology. Humans and assistants run it from a shell, and the block that abbd install writes into CLAUDE.md points assistants to the /abbd skill for how to use it. The usage text calls the CLI a lever. It registers the project's extraction script and proves it deterministic. It keeps unit IDs stable across runs and checks every quoted piece of evidence against the working tree. It records what readers infer and what humans state, refreshes and retracts those claims, and converts an old-format state once. It stores pstack how's module texts and answers explain, path and impact queries. It never judges, blocks, asks or records a decision. Even diff --check only exits 1 when a change reaches the boundary between modules, so a CI job can label the PR, and status --check only exits 1 when the state, the blueprint or a module text is STALE or a quote drifted.

The package is glue. The logic lives in internal/. model holds the writers and the precedence table that picks which claim shows, identity reconciles IDs, evidence checks quotes, topology answers queries and diffs, screen renders, store owns the on-disk format, gitx reads git, extract parses the script's JSON, bootstrap folds in the supplement, and group places a crowded level's units in the directories their code lives in. cmd/abbd parses argv against a declarative command table, decides which writer each record speaks for, wires those packages together in a fixed order, and prints results line by line. After every verb that writes, run calls publish, which re-renders .abbd/blueprint/index.html and then graph.json.

A usage error exits 64 and a failed verb exits 1.

A refusal names up to five of them. Overview

internal/evidence decides, deterministically, whether the working tree still holds the code a reader cited. The extraction script cannot see some facts, such as a coupling through a convention or a unit nothing in the code declares. A pstack reader adds such a fact through the setup supplement or abbd record, with a model.Evidence that names a path, an optional line range and a verbatim quote. This package only finds that text again and gives the item a status: live, drifted or dead. It never judges whether the coupling is real and never writes a file. The same tree always gets the same answer.

The package is one file, evidence.go, and it imports only internal/model. An item's scope is the file it names, and a quote never follows into another file. Checker.Check tests one item. It takes the occurrence nearest the cited lines within Slack, so two places of one quote cited a line or two apart each keep their own, and otherwise the quote's only occurrence anywhere in the file. A quote found twice with neither near the cited lines is not found. Checker.Status turns that answer into the item's next status. Checker.Apply checks every item of every present unit: a semantic unit's own evidence, and the evidence of every parent claim and every relation claim, shown or hidden. A present semantic unit whose evidence is all dead goes absent with the reason evidence-dead. Each relation claim with evidence gets a fresh Digest, and each live item that names lines moves them to where the quote is now, so edits above it never add up to a false removal. Apply ends with model.Resolve, so a dead claim stops showing and the next claim shows. syncActual in cmd/abbd/main.go runs Apply at the sync revision right after identity.Reconcile. save in cmd/abbd/record.go runs it with no revision on the one unit that record relation, record parent, record evidence or retract changes. abbd evidence calls Status with no revision to print each item of the claims that show. abbd record calls Check to refuse a quote its file does not hold now, and abbd migrate calls it to mark every item but the script's that is not live as dead. store.ModuleDigest calls Around to hash the lines near each quote of a file a module only quotes.

Key Concepts

  • Checker (evidence.go): a project root and a cache of each file loaded, with nil for a file that is missing. New(root) makes one per command, so it is a snapshot of the tree.
  • Normalized file (evidence.go): the raw lines, plus norm (the text with all whitespace removed), line (the line of each byte of norm) and gap (whether whitespace stood before that byte). Reformatting never kills a quote.
  • Word boundary (evidence.go): a quote that ends in a word character must end where the code's word ends, and the same holds at its start. So charges does not live on in charges_archive.

The central idea is the working-tree fingerprint. Snapshot stages the whole working tree into a throwaway index, untracked files included and the exclude path left out, then runs git write-tree. A submodule enters as the commit the superproject's index records, not the one checked out, so a clean clone of a synced commit snapshots the same tree. The package has one source file, identity.go, and Reconcile is pure. It does no I/O. It clones the stored claims before it edits them, and it sorts its input by kind and anchor list and its candidate pairs by rank, so input order never changes the outcome. It first applies git renames to stored anchors and evidence paths. It then pairs supplement units by their stored supplement key, and assigns the other pairs globally, best match first. It also decides what the run may overwrite. The Writers the extraction speaks for lose their claims on each reported unit and get the claims it makes, and every other writer's claims stay. So setup replaces the supplement's claims and keeps what abbd record wrote. Reconcile ends with model.Resolve, which picks each edge's shown claim and each unit's parent. Overview

internal/model is ABBD's vocabulary. It holds the Go types for everything stored under .abbd/architecture/ and .abbd/features/, the rules that decide which values are legal, and the table that decides which writer's claim shows. It imports only the standard library. model.go holds origins, kinds, IDs, units, facts, evidence, relations and edges. claims.go holds writers, evidence status, the precedence table, parent claims, masks and Resolve. Every other internal package but gitx imports it (bootstrap, evidence, extract, group, identity, screen, store, topology), and so does cmd/abbd. It does no I/O, runs no git and renders nothing.

The package exists to keep provenance honest. Every fact, relation and parent claim stores the Writer that made it, and its origin follows from the writer and is never stored. script and group are EXTRACTED, supplement and reader are INFERRED, and human is USER_STATED. A value with an unknown or empty writer fails validation, so no empty value can mean EXTRACTED. Unit.Validate enforces the consequences. A human's fact, parent, relation or mask needs a Source, and no other writer may carry one. A why-field is never the script's or the group's. A unit whose name a reader or the supplement wrote needs evidence, and so does an INFERRED parent or relation, while an EXTRACTED parent cites none. Only contracts carry a Signature, a parent must be another module or feature, and a unit holds at most one parent claim per writer and one relation claim per writer, kind and end. An absent unit needs a known reason, and a present one has none. RelationKind.Joins checks that an edge joins legal kinds. ParseEvidence and ParseEdge read what abbd record and abbd retract get on the command line. Resolve derives the read model every other package uses. Downstream code branches on small predicates. Relation.Counts is true for an EXTRACTED or USER_STATED claim that is not dead, and only topology.Compare calls it, to decide which relations between modules abbd diff --check sees. Its comment says a reader's coupling is listed instead of drawn, but internal/screen draws INFERRED edges that are not dead too. Present drops absent units and sorts by ID.

Key Concepts

  • Unit (model.go): one design unit. It has an ID, a Kind, a Name fact and at least one Anchor. It may have a SupplementKey, the Parents claims of each writer, its own Evidence, the why-fields Purpose and Responsibility, a contract Signature and Digest, the shown Relations, the Hidden claims, Masks, and Absent with an AbsentReason (not-reported, withdrawn, evidence-dead, retracted or unneeded). The derived Parent, ParentOrigin and ParentWriter and the user-owned Notes stay out of the YAML. SetAbsent sets or clears both absence fields. Claims lists shown and hidden relation claims together. EachEvidence visits every stored item with its claim's writer, and EachShownEvidence only the unit's own, the winning parent's and the shown relations' items. ShownParent returns the parent claim that won. Semantic reports an INFERRED name.
  • Kind (model.go): MOD, the contract kinds IF, EVT, DATA and CFG (IsContract), and FEAT. Dir() sends features to features and the rest to architecture. Validate rejects the reserved DOM, STATE, TRN and INV and any unknown kind. Holds() is true for MOD and FEAT, the two kinds that may contain others.
  • ID (model.go): KIND-NNNN, such as MOD-0007. FormatID pads to four digits and ParseID accepts four or more.
  • Fact (model.go): a Value, its Writer, and a Source for a human only. Origin is derived by Writer.Origin() (claims.go), which is empty for a writer ABBD does not know. Said and Stated build one, and Guess reports an INFERRED value.
  • Anchor (model.go): the Path and optional Symbol a unit's identity hangs on. Key() is path#symbol, and SortAnchors dedups and sorts by it. Evidence.Anchor turns an item into one.
  • Evidence (model.go): a verbatim Quote at a Path, with optional Lines and Symbol, and the Status, Since and Reason that sync stores and the JSON never sets. A status is live (empty), drifted or dead, and a dead item needs a reason. Same compares path and quote only. Span parses Lines, and Validate accepts only a range such as 120 or 120-134 that starts at 1 or later. Validate also refuses paths under .abbd/ or .git/, because those files repeat the quote. StatusOf (claims.go) makes a claim live while any item is live, else drifted while any is drifted, else dead, and a claim with no items is live.
  • Relation (model.go): one writer's claim on an edge from the unit that holds it, with To, Kind, Writer, Source, Via, Evidence and Digest. Origin and Dead are derived, and Dead means it has evidence and all of it is dead. Status, Drifted, Semantic (it has evidence), Guess (it is INFERRED) and Counts read it. SortRelations orders claims by end and then kind.
  • Relation grammar (model.go): depends_on joins any two kinds, consumes ends at a contract, and provides runs from a module or feature to a contract. Via is empty or one of import, trait, callback, macro, config, build-feature, data, convention or call.
  • Edge (model.go): From, Kind and To, printed as the shell-safe MOD-0001.depends_on.MOD-0002 and read back by ParseEdge. Edge.Joins checks the kinds its IDs name.
  • Precedence (claims.go): one table of the writers that may claim each field, highest first. Name and signature take script, reader, supplement. Purpose and responsibility take human, reader, supplement. A relation takes script, human, reader, supplement, and a parent takes human, group, script, reader, supplement. Outranks compares two writers on a field, and a writer missing from a row ranks below all of it. On a relation or a parent, order puts live claims before drifted ones before dead ones, whatever the writer, and the table decides within a status.
  • ParentClaim (claims.go): one writer's claim on the unit's container, with To, Writer, Source and Evidence. A human's claim also stores Over, the script's parent when the human stated it, and ParentConflicts lists each present unit whose script parent has moved off it to a parent other than the human's. Claim reads a writer's claim, PutParent replaces it and keeps the claims in table order, and DropParents removes the claims of the given writers.
  • Mask (claims.go): a reader's or a human's retraction of one Target (unit, parent, purpose, responsibility, signature, or KIND.TO from RelationTarget), with a Reason. It is bound to the hidden claim's content by Digest, the first 16 hex digits of a SHA-256. RelationDigest hashes kind, end and via, ParentDigest the parent, and FactDigest the value. Hides lets a reader's mask hide the supplement's claims and a human's hide the reader's and the supplement's. Masked tests a claim, and PutMask adds a mask only once. A claim whose content changes no longer matches and shows again.
  • Resolve (claims.go): derives the read model in place. A masked why-field or signature is cleared, and a present unit whose name is masked goes absent as retracted. On each edge the claims sort by order with masked claims last, the first shows unless it is masked, and the rest go to Hidden. PutRelation and DropRelations re-run this per unit after each edit. Each present unit takes its first parent claim that is not dead, not masked, points at a present module or feature and closes no cycle. Claims are accepted tier by tier, script and group first, then human, reader and supplement, each tier in unit ID order. When a claim is refused for closing a cycle, acceptance starts again from the first tier, so the unit's next claim is weighed before any lower tier. An absent unit shows its first stored claim. A skipped claim stays stored. ParentCycle names a present unit whose parents loop, and the tests of model, identity and group use it to check that the result is a tree.

The overview draws each top-level module and feature as a box, and a top-level contract no module provides as a loose box. A blue contract line runs from a user's chip on the bottom edge to the provider's chip on the top edge. One chip stands for the contracts that line carries, named when it is one and counted when it is more, and the contracts no line reaches fold into one +N 계약 chip on the provider. A thick orange bypass line marks a module dependency no contract line already carries. Two modules that depend on each other that way share one mutual line with a head at each end. A relation from a unit at any depth is lifted to the top-level unit that contains it. INFERRED couplings are drawn too, because sync rechecks their quotes. Overview

internal/store is the only code that reads or writes the .abbd/ directory. A Store, built by Open(projectRoot) once per command, holds the path <project>/.abbd and a codebase, the project's code as that command reads it. Calls on .abbd/ go straight to disk. Its rule sits in the package comment. Markdown with YAML frontmatter is the source, and everything else derives from it. Each unit is one file named after its ID, such as architecture/MOD-0001.md. Beside the unit files sit state.yaml and candidates.yaml, which sync owns, project.yaml, the module texts under understanding/, and the rendered blueprint/index.html and blueprint/graph.json. UnitsAt also reads unit files at an older revision through gitx.Files and gitx.Show. The package imports gitx and model, and imports identity only for its Candidate type.

The store guards what it keeps. parseUnit and loadUnits refuse a file whose name does not match its ID, a kind in the wrong directory, a duplicate ID and any unit model.Unit.Validate rejects. Every load ends in model.Resolve, so callers get each value's origin, each edge's shown claim and each unit's parent. SaveUnits resolves and validates each unit before writing it, so the file always splits shown and hidden claims the way a load would. writeFile skips a write when the bytes are unchanged. Otherwise it writes a .tmp file and renames it over the old one. The store reads two unit formats. legacy.go converts an old-format file on load and stays for good, because abbd diff reads states committed at older revisions. Every command that changes units, except abbd migrate, loads them through Writable, which refuses the old format. The store also computes the fingerprints that mark derived views out of date. Its only cache is the codebase, and it has no lock. Matching lives in internal/identity, evidence checks in internal/evidence and rendering in internal/screen. Its callers are cmd/abbd, for nearly every command, and screen.Load, which gathers what the blueprint shows.

Key Concepts

  • Unit file (store.go): <kind dir>/<ID>.md. It holds YAML frontmatter with a model.Unit, a writer on every value, a generated body with a # Name heading and the anchor list, then an optional ## Notes section the user owns and the store carries through untouched.
  • Writable (store.go): LoadUnits for a command that will write. It returns ErrOldFormat, which points at abbd migrate, when any unit file is in the old format. LoadUnits reads either format, and Legacy also names the units still in the old format, for abbd migrate.
  • Old format (legacy.go): a unit whose name has an origin and no writer, with one parent slot and a dead flag on relations. convert maps EXTRACTED to script, USER_STATED to human and INFERRED to supplement, and gives a directory group's name to group. It marks a dead relation's items dead with DeadBeforeMigration, and gives an absent unit unneeded, evidence-dead or not-reported. regroup gives the group writer each script parent claim that points at a group or sits on one. A human's parent comes out with no over, and abbd migrate fills it from the extraction.
  • UnitsAt (store.go): the unit files as committed at a revision, in either format, which abbd diff compares with the current ones. A revision without .abbd/ has no units.
  • State (store.go): state.yaml, the sync watermark. Revision is the commit where this tree was first synced, and a drifted item dies at a sync of a later one. Fingerprint is the gitx.Snapshot tree, MDHash hashes the unit files, and HighWater holds the last number minted per kind.
  • NextID (store.go): mints the next number of a kind and saves it to state.yaml at once. abbd record unit uses it.
  • InputsHash (store.go): a SHA-256 over every file under .abbd/ except blueprint/, including the extractor and the understanding texts. It reads CRLF as LF, so a Windows checkout that converts line endings hashes the same. The blueprint carries it as a watermark, and screen calls the blueprint STALE when the two differ.
  • MDHash (store.go): the same hash over the unit files alone. Sync records it in State, and no code compares it today.
  • Understanding (understanding.go): pstack how's Overview and Key Concepts for one module, with Unit, Origin, Digest, Format and Code, the hash of each anchor and quote the digest read when the text was written, in frontmatter and the text as the body. abbd understand writes it as INFERRED, and only for a top-level module. SaveUnderstanding refuses a text with an empty digest, which would read current whatever the code did. CleanText strips a leading byte order mark and gives every text LF line endings and no trailing blanks, on save, on load and before abbd understand compares a new text with the stored one.
  • codebase (understanding.go): one command's read of the project's code. It lists gitx.WorkingFiles and gitx.Gitlinks once, .abbd/ left out, or walks the disk outside a repository. git lists an untracked repository inside the project as its directory, with a trailing slash, and list walks that directory instead. walk skips a .git directory and leaves out a .git file, the gitfile of a worktree or submodule checkout, while still walking the files beside it. It hashes each path once, so status, sync and the blueprint read each file once however many texts they check. read gives a file with LF endings and a submodule as submodule <commit> from the index, so an edit inside a submodule counts once it is committed there and staged.
  • moduleCode (understanding.go): the code a module's text describes. It collects the module and every present unit under it at any depth, and takes each anchor once. A file anchor reads the file. A directory anchor reads the paths git lists under it, a submodule as one path. When git lists nothing there, under falls back to the enclosing submodule's pin or, for an ignored directory, to the files on disk, and marks the anchor fallback. An anchor that extraction derived from the unit's own evidence does not count as a whole file. The cited quotes count in files no anchor covers.
  • Stamp, ModuleDigest and Changed (understanding.go): Stamp returns the Code map and the digest over it. A file anchor maps to its file's hash, a directory anchor to one hash of every path and hash under it, and each place a quote is cited to the hash of evidence.Checker.Around, the quoted lines and 5 on each side wherever they sit now. quotes orders the places of one quote in a file by line, and the key is path#quote-<hash>, where the hash covers the quote and, from the second place on, which place it is. Counting places rather than lines keeps a key when code above the quote moves it down. An edit elsewhere in a shared file such as CLAUDE.md changes neither. The digest is the first 16 hex characters of a SHA-256 over the sorted map, so it reads exactly what Code records. ModuleDigest is that digest. A text whose Digest differs shows as STALE in abbd status, abbd explain and the blueprint. Changed lists what blocks abbd understand --restamp: an anchor or quote now whose hash differs from Code, naming a directory anchor as code under it, one missing from Code, and one in Code whose path is gone. One that left the module while its path still exists does not block it. A place's key counts its rank among the places cited, so when the unit citing an earlier place leaves, the place left takes that place's key. vouchedPlaces lets a place pass when its lines hash as a place of the same quote in Code did, each place in Code vouching for one place now, so an unchanged place that changed rank does not block a restamp and an edited one still does.
  • Digest upgrade (understanding.go): UpgradeUnderstandings, which syncActual runs, looks at each text not in CodeFormat. A text with no Code came from ABBD 0.6, and legacyModuleDigest recomputes its digest over the whole files cited by a module and its direct children. A format 1 text recorded a hash per file, and format1Digest recomputes its digest, where a directory git lists nothing under read nothing. A format 2 text recorded the hashes Stamp records now, except that quotesOnce kept one place of a quote cited at several, and stampQuotes recomputes its digest that way. When the old digest matches and read every file and every quoted place the new one reads, the text is stamped again in the current format and stays current. When it matches but the new digest reads more, such as a fallback directory or the second place of a quote cited twice, the text is returned as widened, keeps its stamp and reads STALE. A text the old digest called STALE stays STALE.
  • Project (store.go): project.yaml, the argv of the extraction script that abbd setup registers and abbd sync runs.

Overview

internal/topology is the read-only query layer over the stored topology. It takes the []model.Unit slice that internal/store loads, either from the working tree (LoadUnits) or from a git revision (UnitsAt). From ABBD it imports only internal/model. cmd/abbd calls it for its query commands. Find resolves what an agent has in hand to units, through env.find in cmd/abbd/query.go, which explain, path and impact share. A well-formed ID skips Find, and when nothing matches Nearest suggests the closest names. Explain serves abbd explain. Path and Weakest serve abbd path. ImpactOf serves abbd impact. Compare builds the Diff behind abbd diff between a base revision, the merge base by default, and the working tree, Diff.Lines and Diff.String print it, and Diff.Boundary drives its --check gate. The package never writes a unit and never opens the store.

Its other job is to keep the three origins apart. EXTRACTED means the script read the relation from code. USER_STATED means a human said it. INFERRED means a pstack reader quoted evidence for it. A relation whose evidence is all dead, or whose end is absent, is dropped everywhere. A live or drifted inferred one is still walked by ImpactOf and Path, but it carries an (inferred, via ...) label, which ends in drifted while its evidence has drifted. It sits apart in Explanation.Inferred and Diff.InferredAdded, and it never changes RelationsAdded or RelationsRemoved. A reader of the output can tell what the code vouches for from what a reader guessed.

Key Concepts

  • Find / Match / Tier (find.go): resolves a query best first. An exact ID returns one match (ByID), and an exact name returns every unit with that name (ByName), both ignoring case. Any other query also gets byPhrase matches, ranked by how many query words a unit holds and then by where, the name weighing most and a project file under its anchors least. Ties go to the deeper unit, then the smaller ID.
  • Match.Anchored (find.go): true when one of a unit's anchors is the queried path or a directory that holds it. abbd impact seeds the best match plus every other anchored match, so a path change reaches every unit anchored there. Symbol, evidence and phrase matches stay unanchored.
  • Nearest (find.go): the present units whose names are fewest Levenshtein edits from the query, ignoring case.
  • Link (impact.go): one relation between two present units that is not dead, a model.Edge plus Origin, Via, Evidence and Drifted. Label names its origin, its via and a drift. Links reads only shown relations and is the graph that Explain, ImpactOf and Path walk.

Overview

internal/narrative reads a module's text the way a human reader meets it on the blueprint: as sections, each describing the code as it is now. It has two checks. Long finds a section whose prose runs past MaxSection, 2000 characters. History finds a phrase that reads as the code's history rather than its present: a date, an issue or PR number, or a tag such as migrated from. The package only reads text and returns what it found. The abbd CLI prints the findings when abbd understand stores a text and when abbd status runs, and neither command refuses a text or fails a check on them, because a version number or a name can read as history.

Key Concepts

  • Section (narrative.go): the prose under one heading, up to the next heading of any level. A heading is a line that starts with #, the same rule the blueprint uses to draw one, so ### subsections split a long section for the counter and the reader alike. Prose before the first heading forms a section with an empty heading. Chars counts the runes of the section's non-blank lines, without the heading.
  • Long (narrative.go): each section over MaxSection. The threshold is a report line for the agent who writes the text, never a gate.
  • History marks (narrative.go): History runs an ordered table of patterns over each line outside a heading. Dates come first, then history tags, then issue and PR references from the most specific (PR #12, owner/repo#12) to a bare #12. A code span quotes code or an example, so History skips it. A span one pattern reports is taken, so a later pattern never reports it again. A Mark names its section, what it reads as, and the phrase. Version numbers, identifiers, anchors such as #overview, and words such as "no longer" or "old format" describe code as it is, and no pattern matches them.
