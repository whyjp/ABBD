Overview

cmd/abbd is the ABBD command line. It is one package main that dispatches seventeen verbs over the .abbd/ directory, where a repository keeps its architecture topology. Humans and assistants run it from a shell, and the block that abbd install writes into CLAUDE.md points assistants to the /abbd skill for how to use it. The usage text calls the CLI a lever. It registers the project's extraction script and proves it deterministic. It keeps unit IDs stable across runs and checks every quoted piece of evidence against the working tree. It records what readers infer and what humans state, refreshes and retracts those claims, and converts an old-format state once. It stores pstack how's module texts and answers explain, path and impact queries. It never judges, blocks, asks or records a decision. Even diff --check only exits 1 when a change reaches the boundary between modules, so a CI job can label the PR.

The package is glue. The logic lives in internal/. model holds the writers and the precedence table that picks which claim shows, identity reconciles IDs, evidence checks quotes, topology answers queries and diffs, screen renders, store owns the on-disk format, gitx reads git, extract parses the script's JSON, bootstrap folds in the supplement, and group adds directory groups when a view gets crowded. cmd/abbd parses argv against a declarative command table, decides which writer each record speaks for, wires those packages together in a fixed order, and prints results line by line. Overview

internal/evidence decides, deterministically, whether the working tree still holds the code a reader cited. The extraction script cannot see some facts, such as a coupling through a convention or a unit nothing in the code declares. A pstack reader adds such a fact through the setup supplement or abbd record, with a model.Evidence that names a path, an optional line range and a verbatim quote. This package only finds that text again and gives the item a status: live, drifted or dead. It never judges whether the coupling is real and never writes a file. The same tree always gets the same answer.

The package is one file, evidence.go, and it imports only internal/model. An item's scope is the file it names, and a quote never follows into another file. Checker.Check tests one item. It looks first within the cited lines plus Slack, then takes the quote's only occurrence anywhere in the file. A quote found twice with neither near the cited lines is not found. Checker.Status turns that answer into the item's next status. Checker.Apply checks every item of every present unit: a semantic unit's own evidence, and the evidence of every parent claim and every relation claim, shown or hidden. A present semantic unit whose evidence is all dead goes absent with the reason evidence-dead. Each relation claim with evidence gets a fresh Digest, and each live item that names lines moves them to where the quote is now, so edits above it never add up to a false removal. Apply ends with model.Resolve, so a dead claim stops showing and the next claim shows. syncActual in cmd/abbd/main.go runs Apply at the sync revision right after identity.Reconcile. save in cmd/abbd/record.go runs it with no revision on the one unit that record relation, record parent, record evidence or retract changes. abbd evidence calls Status with no revision to print each item of the claims that show. abbd record calls Check to refuse a quote its file does not hold now, and abbd migrate calls it to mark every item but the script's that is not live as dead.

Key Concepts

  • Checker (evidence.go): a project root and a cache of each file loaded, with nil for a file that is missing. New(root) makes one per command, so it is a snapshot of the tree.
  • Normalized file (evidence.go): the raw lines, plus norm (the text with all whitespace removed), line (the line of each byte of norm) and gap (whether whitespace stood before that byte). Reformatting never kills a quote.
  • Word boundary (evidence.go): a quote that ends in a word character must end where the code's word ends, and the same holds at its start. So charges does not live on in charges_archive.
  • Slack (evidence.go): 3 lines of tolerance around the cited range. A quote with no Lines is unbounded and takes its first occurrence in the file.
  • Result (evidence.go): Live, Gone (the file does not exist), At (where the quote was found, such as 4-5) and Digest (the first 8 bytes of a SHA-256 of the matched raw lines, in hex).
  • Status rules (evidence.go): a found quote makes the item live and clears Since and Reason. A missing file makes it dead with the reason PATH is gone. A file without the quote makes it drifted, with Since set to the sync's revision. A sync at a later revision that still finds it drifted makes it dead with the reason drifted since REV and not refreshed. Status returns a dead item unchecked, so dead is terminal.   • Claim status (evidence.go, claims.go): all checks a claim's items in order. model.StatusOf makes the claim live while any item is live, else drifted while any is drifted, else dead. Overview

internal/identity decides which design unit is which across extraction runs. On every abbd sync and abbd setup, the extraction reports units with anchors and keys but no IDs. For setup, bootstrap.Overlay has already folded in the reader's supplement. Reconcile pairs those units with the ones stored in .abbd/. A matched unit keeps its ID. An unmatched one gets the next number above a per-kind high-water mark, so a deleted number never returns. Reconcile never drops a unit. A stored unit that the extraction's writers no longer report is marked absent with a reason, and an overlap that did not become a match is recorded as a merge candidate for a human.

The package is one file, identity.go, and Reconcile is pure. It does no I/O, and it sorts its input and its candidate pairs, so input order never changes the outcome. It first applies git renames to stored anchors and evidence paths. It then pairs supplement units by their stored supplement key, and assigns the other pairs globally, best match first. It also decides what the run may overwrite. The Writers the extraction speaks for lose their claims on each reported unit and get the claims it makes, and every other writer's claims stay. So setup replaces the supplement's claims and keeps what abbd record wrote. Reconcile ends with model.Resolve, which picks each edge's shown claim and each unit's parent. The caller is syncActual in cmd/abbd/main.go. It loads units, candidates, high-water marks and renames, calls Reconcile, then passes the units through evidence.Checker.Apply and group.Fallback before saving. abbd migrate calls Reconcile only to pair the supplement's units with stored ones. internal/store imports the package only for Candidate.

  • Match rule (identity.go): a supplement unit takes over the stored unit of the same kind with the same SupplementKey first. Identical sets are the only way a one-anchor unit matches. Pairs rank by identical sets, then larger overlap, then smaller symmetric difference.
  • Anchor (model.go): a Path and Symbol, compared by Key(). extract.parseUnits and abbd record unit add a semantic unit's evidence locations as anchors.
  • High-water mark (identity.go): the largest number minted per kind. Reconcile raises it past any stored ID, mints from it and returns it in Result.HighWater.
  • Writers (identity.go): Sync is the script alone, for abbd sync. Setup is the script and the supplement, for abbd setup. An unreported unit goes absent only when one of these writers wrote its name, as not-reported for the script's and withdrawn for the supplement's. A reader's unit stays, and its evidence decides.
  • Held by a human (identity.go): under Setup, an unreported supplement unit stays present when it carries a human's fact or parent claim, or when a human's relation starts or ends at it. heldByHuman collects these units, and their IDs land in Result.Stated.
  • merge (identity.go): folds an extracted unit into the stored unit it took over. The extraction sets the anchors and the code Digest. A name, purpose, responsibility or signature is replaced when its writer is one the extraction speaks for, or when the offered writer outranks it in model.Precedence. An empty field takes what the extraction offers. The unit's evidence goes with its name.
  • Parent and relation claims (identity.go): setParents and setRelations work on each reported unit. They drop the claims of the writers the extraction speaks for and add the claims it makes: the script's parent, the supplement's Placed parents, and each extracted or supplement relation. Overview

internal/model is ABBD's vocabulary. It holds the Go types for everything stored under .abbd/architecture/ and .abbd/features/, the rules that decide which values are legal, and the table that decides which writer's claim shows. It imports only the standard library. model.go holds units, facts, evidence and relations, and claims.go holds writers, the precedence table, parent claims, masks and Resolve. Every other internal package but gitx uses it (extract, bootstrap, identity, evidence, store, topology, screen, group), and so does cmd/abbd. It does no I/O, runs no git and renders nothing.

The package exists to keep provenance honest. Every fact, relation and parent claim stores the Writer that made it, and its origin follows from the writer and is never stored. script and group are EXTRACTED, supplement and reader are INFERRED, and human is USER_STATED. A value with an unknown or empty writer fails validation, so no empty value can mean EXTRACTED. Unit.Validate enforces the consequences. A human's fact, parent or relation needs a Source, and no other writer may carry one. A why-field is never the script's or the group's. A unit whose name a reader or the supplement wrote needs evidence, and so does an INFERRED parent or relation. Only contracts carry a Signature, and a parent must be another module or feature. RelationKind.Joins checks that an edge joins legal kinds. ParseEvidence and ParseEdge read what abbd record gets on the command line. Resolve derives the read model every other package uses: each value's origin, each edge's shown claim and each unit's parent. Downstream code branches on small predicates. Relation.Counts is true for an EXTRACTED or USER_STATED claim that is not dead, and topology.Compare uses it to decide which relations between modules abbd diff --check sees. Its comment says a reader's coupling is not drawn, but the blueprint's overview draws INFERRED edges that are not dead too. Present drops absent units.

Key Concepts

  • Unit (model.go): one design unit. It has an ID, a Kind, a Name fact and at least one Anchor. It may have a SupplementKey, the Parents claims of each writer, its own Evidence, the why-fields Purpose and Responsibility, a contract Signature and Digest, the shown Relations, the Hidden claims, Masks, and Absent with an AbsentReason (not-reported, withdrawn, evidence-dead, retracted or unneeded). The derived Parent, ParentOrigin and ParentWriter and the user-owned Notes stay out of the YAML. ShownParent returns the parent claim that won, and EachShownEvidence visits its items. Semantic reports an INFERRED name.
  • Kind (model.go): MOD, the contract kinds IF, EVT, DATA and CFG, and FEAT. Dir() sends features to features and the rest to architecture. DOM, STATE, TRN and INV are reserved and rejected. Holds() is true for MOD and FEAT, the two kinds that may contain others. A module holds its units, and a feature holds its parts, such as a skill's steps.
  • ID (model.go): KIND-NNNN, such as MOD-0007. FormatID pads to four digits and ParseID accepts four or more.
  • Fact (model.go): a Value, its Writer, and a Source for a human only. Origin is derived by Writer.Origin() (claims.go), which is empty for a writer ABBD does not know. Said and Stated build one, and Guess reports an INFERRED value.
  • Anchor (model.go): the Path and optional Symbol a unit's identity hangs on. Key() is path#symbol, and SortAnchors dedups and sorts by it.
  • Evidence (model.go): a verbatim Quote at a Path, with optional Lines and Symbol, and the Status, Since and Reason that sync stores and the JSON never sets. A status is live (empty), drifted or dead, and a dead item needs a reason. Same compares path and quote, since the symbol only says where in the file to look. Span parses Lines. Validate refuses paths under .abbd/ or .git/, because those files repeat the quote. StatusOf (claims.go) makes a claim live while any item is live, else drifted while any is drifted, else dead.
  • Relation (model.go): one writer's claim on an edge from the unit that holds it, with To, Kind, Writer, Source, Via, Evidence and Digest. Origin and Dead are derived, and Dead means it has evidence and all of it is dead. Drifted, Semantic (it has evidence), Guess (it is INFERRED) and Counts read it.
  • Relation grammar (model.go): depends_on joins any two kinds, consumes ends at a contract, and provides runs from a module or feature to a contract. Via is one of import, trait, callback, macro, config, build-feature, data, convention or call.
  • Edge (model.go): From, Kind and To, printed as the shell-safe MOD-0001.depends_on.MOD-0002 and read back by ParseEdge.
  • Precedence (claims.go): one table of the writers that may claim each field, highest first. Name and signature take script, reader, supplement. Purpose and responsibility take human, reader, supplement. A relation takes script, human, reader, supplement, and a parent takes human, group, script, reader, supplement. Outranks compares two writers on a field. On a relation or a parent, order puts live claims before drifted ones before dead ones, whatever the writer, and the table decides within a status. A claim without evidence is live.
  • ParentClaim (claims.go): one writer's claim on the unit's container, with To, Writer, Source and Evidence. A human's claim also stores Over, the script's parent when the human stated it, and ParentConflicts lists each unit whose script parent has moved off it to a parent other than the human's. A unit holds at most one claim per writer.
  • Mask (claims.go): a reader's or a human's retraction of one Target, bound by Digest to the hidden claim's content, with a Reason. Hides lets a reader's mask hide the supplement's claims and a human's hide the reader's and the supplement's. A claim whose content changes no longer matches and shows again.
  • Resolve (claims.go): derives the read model in place. A masked why-field or signature is cleared, and a unit whose name is masked goes absent as retracted. Each edge shows its first unmasked claim in table order, and the rest go to Hidden. Each present unit takes its first parent claim that is not dead, not masked, points at a present module or feature and closes no cycle. Claims are accepted tier by tier, script and group first, then human, reader and supplement, each tier in unit ID order. When a claim is refused for closing a cycle, acceptance starts again from the first tier, so the unit's next claim is weighed before any lower tier. A skipped claim stays stored.

Overview

internal/screen turns the .abbd/ store into the blueprint a human reads. Load reads the store, Build derives a Model, and Files renders two files. index.html is one static page with no script. graph.json is the same data for tools. The CLI's publish (cmd/abbd/screen.go) saves them after every command marked writes (setup, sync, record relation|unit|parent|fact|evidence, retract, migrate, understand). abbd status reuses Load for its freshness verdicts. The package never writes the topology, and the fold boxes it invents never reach the store.

The overview draws each top-level module and feature as a box. A blue line runs from a user's chip on the bottom edge to the provider's chip on the top edge. One chip stands for the contracts that line carries, named when it is one and counted when it is more, and the contracts no line reaches fold into one +N 계약 chip on the provider, and a thick orange bypass line marks a module dependency no contract carries. Two modules that depend on each other that way share one mutual line with a head at each end. A relation from a unit at any depth is lifted to the top-level unit that contains it. INFERRED couplings are drawn too, because sync rechecks their quotes. Only dead ones are dropped, and a drifted one is drawn like a live one. A small circle at a line's start marks a reader's or a human's relation, and a dashed line runs against the reading direction. Every top-level module and every unit that holds others has its own view. An overview box links to its view only when viewOf names one, and Build makes a view for exactly the units viewOf names, so no link opens a missing section. A feature with no parts has none, so its box carries no link and its title offers no click. Everything is sorted before it is placed, so the same store always draws the same picture. docs/blueprint-svg.md states the drawing rules. legible_test.go measures them per line and channel, and trace_test.go traces every relation along the drawn ink for bends, crossings, phantom paths, unmarked splits and counts that belong to no single line.

  • route (route.go): orthogonal routing on that grid. A line crosses each gap on its own track and passes rows down its chain, or between two boxes or beside the row where it has none. Lines of one kind that leave one box share a departure trunk through every row two of them still pass. Lines of one kind that reach one box share an arrival bus, and boxes side by side in one row share one only when exactly the same places reach them. Each trunk runs down the chain of its lead line, with its stub or drop right over it. A line that changes buses steps between them where no reader can follow other lines the wrong way: viaX keeps a step off a departure track between the two trunks, and stepX finds a step onto an arrival track the nearest x no other line uses. Lines that leave and reach one box edge share its slots. Each bus is drawn once with its line count. place then sizes each gap, with room beside each stub or drop that carries a count.
  • junctions / anchor (ink.go): what the routed paths look like to a reader. junctions puts a Dot wherever ink of one colour goes three or more ways, and where a line crosses onto a trunk of its own kind that runs past it. anchor sets each ×N beside its own stub or drop, on the side where the nearest other ink is farthest.
  • Inside (inside.go): one view built by (*overview).inside. Its frame carries the contracts of the module or feature it opens and dashed ports for the modules it meets without one. It also holds Units with one sentence each, Unwired contracts kept off the frame, Inferred couplings with their quotes, Up and Trail, and the Understanding.
  • Focus (focus.go): a view derived from a dense one, which draws more than two relations per box. Overview

internal/store is the only code that reads or writes the .abbd/ directory. A Store, built by Open(projectRoot), holds nothing but the path <project>/.abbd, and every call goes straight to disk. Its rule sits in the package comment. Markdown with YAML frontmatter is the source, and everything else derives from it. Each unit is one file named after its ID, such as architecture/MOD-0001.md. Beside the unit files sit state.yaml and candidates.yaml, which sync owns, project.yaml, the module texts under understanding/, and the rendered blueprint/index.html and blueprint/graph.json. UnitsAt also reads unit files at an older revision through gitx.Files and gitx.Show. The package imports gitx and model, and imports identity only for its Candidate type.

The store guards what it keeps. parseUnit and loadUnits refuse a file whose name does not match its ID, a kind in the wrong directory, a duplicate ID and any unit model.Unit.Validate rejects. Every load ends in model.Resolve, so callers get each value's origin, each edge's shown claim and each unit's parent. SaveUnits resolves and validates each unit before writing it, so the file always splits shown and hidden claims the way a load would. writeFile skips a write when the bytes are unchanged. Otherwise it writes a .tmp file and renames it over the old one. The store reads two unit formats. legacy.go converts an old-format file on load and stays for good, because abbd diff reads states committed at older revisions. Every command that changes units, except abbd migrate, loads them through Writable, which refuses the old format. The store also computes the fingerprints that mark derived views out of date. It has no cache and no lock. Matching lives in internal/identity, evidence checks in internal/evidence and rendering in internal/screen. Its callers are cmd/abbd, for nearly every command, and screen.Load, which gathers what the blueprint shows.

Key Concepts

  • Unit file (store.go): <kind dir>/<ID>.md. It holds YAML frontmatter with a model.Unit, a writer on every value, a generated body with a # Name heading and the anchor list, then an optional ## Notes section the user owns and the store carries through untouched.
  • Writable (store.go): LoadUnits for a command that will write. It returns ErrOldFormat, which points at abbd migrate, when any unit file is in the old format. LoadUnits reads either format, and Legacy also names the units still in the old format, for abbd migrate.
  • Old format (legacy.go): a unit whose name has an origin and no writer, with one parent slot and a dead flag on relations. convert maps EXTRACTED to script, USER_STATED to human and INFERRED to supplement, and gives a directory group's name to group. A human's parent comes out with no over, and abbd migrate fills it from the extraction.
  • UnitsAt (store.go): the unit files as committed at a revision, in either format, which abbd diff compares with the current ones. A revision without .abbd/ has no units.

  • Understanding (understanding.go): pstack how's Overview and Key Concepts for one module, with Unit, Origin and Digest in frontmatter and the text as the body. abbd understand writes it as INFERRED, and only for a top-level module.
  • ModuleDigest (understanding.go): the first 16 hex characters of a SHA-256 over the files cited by the anchors and evidence of a module and of its direct children, with absent units left out. A missing file hashes as missing. A child's citations count, so internal/store's text goes STALE when internal/identity/identity.go, which the merge candidates file unit cites, changes. A text whose Digest differs shows as STALE in abbd status, abbd explain and the blueprint.

Overview

internal/topology is the read-only query layer over the stored topology. It takes the []model.Unit slice that internal/store loads, either from the working tree (LoadUnits) or from a git revision (UnitsAt). From ABBD it imports only internal/model. cmd/abbd calls it for its query commands. Find resolves what an agent has in hand to units, and Nearest suggests names when nothing matches. Explain serves abbd explain. Path and Weakest serve abbd path. ImpactOf serves abbd impact. Compare builds the Diff behind abbd diff, and Diff.Boundary drives its --check gate. The package never writes a unit and never opens the store.

Its other job is to keep the three origins apart. EXTRACTED means the script read the relation from code. USER_STATED means a human said it. INFERRED means a pstack reader quoted evidence for it. A relation whose evidence is all dead is dropped everywhere. A live or drifted inferred one is still walked by ImpactOf and Path, but it carries an (inferred, via ...) label, which ends in drifted while its evidence has drifted. It sits apart in Explanation.Inferred and Diff.InferredAdded, and it never changes RelationsAdded or RelationsRemoved. A reader of the output can tell what the code vouches for from what a reader guessed.

Key Concepts

  • Find / Match / Tier (find.go): resolves a query best first. An exact ID or name returns at once (ByID, ByName). Otherwise byCode reads the query as a symbol or a path, dropping a :12-30 suffix. It ranks the units whose anchors or evidence hold it, the most specific anchor first. A query with /, \ or . that matched code stops there. Any other query also gets byPhrase matches, scored by the query words a unit's name, descriptions, quotes and files hold.
  • Match.Anchored (find.go): true when one of a unit's anchors is the queried path or a directory that holds it. abbd impact seeds the best match plus every other anchored match, so a path change reaches every unit anchored there. Evidence and phrase matches stay unanchored.
  • Link (impact.go): one relation between two present units that is not dead, a model.Edge plus Origin, Via, Evidence and Drifted. Label names its origin, its via and a drift. Links is the graph that Explain, ImpactOf and Path walk.
  • ImpactOf / Impact (impact.go): a breadth-first walk from the seeds and the units inside them. It follows what depends on or consumes an impacted unit, and the contracts that unit provides. A contract's provider, and what a seed itself uses, are listed but not followed. Direct holds the seeds, their neighbours and the consumers of a neighbouring contract. Far holds the rest.
  • Path / Hop (path.go): a cheapest-first walk over Links plus nesting, a Contains link from parent to child, each walked either way. Cost compares joints first, then hops, nesting hops and the weakest origin. A joint is two users of one unit meeting through it. markJoints records a joint that remains in Hop.Shares and Hop.Provider.
  • strength (query.go): EXTRACTED 2, USER_STATED 1, INFERRED 0. It breaks Path's last tie and drives Weakest. It also gives a contains hop the weaker of the unit's name origin and its ParentOrigin.
  • Lifting (diff.go): a relation of an inside unit counts as its enclosing unit's. Compare lifts to the top-level unit (top, between). Explain lifts to the unit being explained (own in query.go).
  • Diff (diff.go): units added and removed, changed contract Signatures, contracts whose Code changed under the same signature, drawn top-level relations added or removed, and InferredAdded. Boundary ignores code-only changes.
