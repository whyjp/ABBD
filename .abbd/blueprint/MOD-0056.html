Overview

internal/narrative reads a module's text the way a human reader meets it on the blueprint: as sections, each describing the code as it is now. It has two checks. Long finds a section whose prose runs past MaxSection, 2000 characters. History finds a phrase that reads as the code's history rather than its present: a date, an issue or PR number, or a tag such as migrated from. The package only reads text and returns what it found. Lines is how both checks and the blueprint read a text line by line, so they split it at the same headings and treat the same lines as code. The abbd CLI prints the findings when abbd understand stores a text and when abbd status runs, and neither command refuses a text or fails a check on them, because a version number or a name can read as history.

Key Concepts

  • Lines (narrative.go): each line of a text with its LineKind: Prose, Heading, Fence or Code. A line starting with three or more backticks or tildes is a Fence that opens a code block, and a line of only as many or more of the same closes it. After a run of backticks the rest of the line may hold no backtick, as CommonMark has it, so a line that starts with an inline code span stays Prose. An unclosed block runs to the text's end. Every line inside is Code, kept with its indentation, so a # comment or #include there is no heading. Outside a block, a line that starts with # is a Heading, holding the heading's words. screen.blocks reads the same Lines.
  • Section (narrative.go): the lines under one heading, up to the next heading of any level. A heading is a Heading line from Lines, the same rule the blueprint uses to draw one, so ### subsections split a long section for the counter and the reader alike. Prose before the first heading forms a section with an empty heading. Chars counts the runes of the section's non-blank lines, code and fences included, without the heading.
  • Long (narrative.go): each section over MaxSection. The threshold is a report line for the agent who writes the text, never a gate.
  • History marks (narrative.go): History runs an ordered table of patterns over each Prose line, so a code block is never read. Dates come first, then history tags, then issue and PR references from the most specific (PR #12, owner/repo#12) to a bare #12. quoted marks each code span and each URL, a scheme followed by :// up to the next blank, and History skips them, so a fragment such as https://x.com/a#12 is not an issue number. A span one pattern reports is taken, so a later pattern never reports it again. A Mark names its section, what it reads as, and the phrase. Version numbers, identifiers, anchors such as #overview, and words such as "no longer" or "old format" describe code as it is, and no pattern matches them.
