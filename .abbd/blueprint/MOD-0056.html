판독 리더가 쓴 설명 · pstack poteto-mode 0.15.36

Overview

internal/narrative는 모듈 텍스트를 사람이 blueprint에서 만나는 방식대로 읽는다. 텍스트는 섹션으로 나뉘고, 각 섹션은 지금의 코드를 설명해야 한다. 검사는 세 가지다. Long은 산문이 MaxSection(2000자)을 넘는 섹션을 찾는다. status는 그런 섹션을 모두 보고하고, abbd understand는 첫 섹션, 곧 페이지가 먼저 보여 주는 요약이 넘을 때만 텍스트를 거부한다. History는 날짜, 이슈나 PR 번호, migrated from 같은 태그처럼 지금이 아니라 코드의 과거로 읽히는 구절을 찾는다. Share와 ReadsIn은 텍스트의 산문이 주어진 문자 체계로 쓰였는지 잰다. 패키지는 텍스트를 읽고 찾은 것을 돌려줄 뿐이다. Lines는 세 검사와 blueprint가 텍스트를 줄 단위로 읽는 공통 방법이라, 모두 같은 제목에서 나누고 같은 줄을 코드로 본다. abbd CLI는 abbd understand가 텍스트를 저장할 때와 abbd status가 돌 때 결과를 출력한다. 버전 번호나 이름도 과거처럼 읽힐 수 있으므로 어느 명령도 History 결과로 텍스트를 거부하거나 검사를 실패시키지 않는다.

나머지 설명

Key Concepts

  • Lines (narrative.go): 텍스트의 각 줄을 LineKind(Prose, Heading, Fence, Code)와 함께 담은 Line으로 돌려준다. 백틱이나 물결표 세 개 이상으로 시작하는 줄은 코드 블록을 여는 Fence이고, 같은 문자만 그만큼 이상 있는 줄이 닫는다. CommonMark처럼 백틱 묶음 뒤에 백틱이 또 있으면 안 되므로, 인라인 코드로 시작하는 줄은 Prose로 남는다. 닫히지 않은 블록은 텍스트 끝까지 이어진다. 블록 안의 줄은 들여쓰기를 지킨 Code라서 그 안의 # comment나 #include는 제목이 아니다. 블록 밖에서 #으로 시작하는 줄은 제목의 단어를 담은 Heading이다. screen.blocks도 같은 Lines를 읽는다.
  • Section (narrative.go): Sections가 나눈, 한 제목 아래부터 다음 제목(수준 무관)까지의 줄이다. 제목은 blueprint가 제목을 그리는 규칙과 같은 Lines의 Heading이므로, ### 하위 섹션은 세는 쪽과 읽는 쪽 모두에게 긴 섹션을 나눈다. 첫 제목 앞의 산문은 빈 제목의 섹션이 된다. Chars는 제목을 빼고 섹션의 비어 있지 않은 줄의 rune을 코드와 fence까지 포함해 센다.
  • Long (narrative.go): MaxSection을 넘는 각 섹션이다. 이 기준은 텍스트를 쓰는 에이전트에게 주는 보고일 뿐 관문이 아니다.
  • History marks (narrative.go): History는 순서가 정해진 패턴 표를 각 Prose 줄에 돌리므로 코드 블록은 읽지 않는다. 날짜가 먼저, 다음은 과거를 뜻하는 태그, 그다음 이슈와 PR 참조를 가장 구체적인 것(PR #12, owner/repo#12)부터 맨 #12까지 본다. quoted는 각 code 구간과 URL(스킴 뒤 ://부터 다음 공백까지)을 표시하고 History는 그것을 건너뛰므로 https://x.com/a#12의 조각은 이슈 번호가 아니다. 한 패턴이 보고한 구간은 차지된 것이라 뒤 패턴이 다시 보고하지 않는다. Mark는 섹션, 무엇으로 읽히는지, 구절을 담는다. 버전 번호, 식별자, #overview 같은 앵커, "no longer"나 "old format" 같은 말은 지금의 코드를 설명하므로 어느 패턴에도 걸리지 않는다.
  • 언어 판정 (language.go): ProseText는 어느 언어로 쓰든 그대로 두는 것을 뺀 산문이다. Lines가 코드와 제목으로 읽은 줄, 인라인 코드, 큰따옴표와 꺾쇠 따옴표 안의 인용, 그리고 경로나 호출 기호, 숫자, 밑줄을 품거나 camelCase이거나 대문자 두 자 이상인 단어를 뺀다. 숫자는 Latin 글자와 함께 있거나 글자 없이 홀로 있을 때만 코드로 보므로 3개 같은 한국어 수량 표현은 산문에 남는다. Share는 글자를 하나라도 가진 산문 단어 중 주어진 문자 체계(model.Language의 Script)의 글자를 하나라도 가진 단어의 비율과 단어 수를 돌려준다. 그래서 store는처럼 조사가 붙은 영어 용어는 한국어 단어로 세고, 명사가 많은 짧은 한국어 줄도 통과한다. 단어가 없거나 문자 체계가 nil이면 1이다. ReadsIn은 그 비율이 Threshold 0.3 이상인지 본다. 한국어 산문은 영어 용어를 자유롭게 섞으므로 기준이 낮고, 다른 언어의 산문은 0에 가깝다. 패키지는 이 결과로 아무것도 거부하지 않는다. CLI의 lint가 project.yaml이 정한 언어에 대해 관문으로 쓴다.

이 패키지에는 상태, 스레드, 실패 경로가 없다. 문자열을 받아 결과를 돌려주는 순수 함수뿐이다.

안의 단위가 아직 없습니다.
