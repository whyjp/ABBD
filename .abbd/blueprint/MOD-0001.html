Overview

cmd/abbd is the ABBD command line. It is one package main that dispatches the verbs of its command table over the .abbd/ directory, where a repository keeps its architecture topology. Humans and assistants run it from a shell, and the block that abbd install writes into CLAUDE.md points assistants to the /abbd skill for how to use it. The usage text calls the CLI a lever. It registers the project's extraction script and proves it deterministic. It keeps unit IDs stable across runs and checks every quoted piece of evidence against the working tree. It records what readers infer and what humans state, refreshes and retracts those claims, and converts an old-format state once. It stores pstack how's module texts, the notes in their slots, and the flows, stacks and tables readers draw, and answers explain, path and impact queries. It never judges, blocks, asks or records a decision. Even diff --check only exits 1 when a change reaches the boundary between modules, so a CI job can label the PR, and status --check only exits 1 when the state, the blueprint, a module text, a note, a flow's step, a stack's layer or a table's row is STALE or a quote drifted.

The package is glue. The logic lives in internal/. model holds the writers and the precedence table that picks which claim shows, identity reconciles IDs, evidence checks quotes, topology answers queries and diffs, screen renders, store owns the on-disk format, gitx reads git, extract parses the script's JSON, bootstrap folds in the supplement, and group places a crowded level's units in the directories their code lives in. cmd/abbd parses argv against a declarative command table, decides which writer each record speaks for, wires those packages together in a fixed order, and prints results line by line. After every verb that writes, run calls publish, which renders every page of .abbd/blueprint/ and graph.json through screen.Files, hands them to store.SaveBlueprint in one call, which removes any other file there, then records in the state's Blueprint the inputs hash it rendered them from and in Rendered the store.HashRender of the files it wrote. The tests read the blueprint through blueprint() in helpers_test.go, every page joined, so a check passes whichever page shows what it asks for. A check that a figure is linked asks for its own page, such as href="flow-charge.html", and graph() reads graph.json, which holds the data and no drawing.

Key Concepts

  • Command table (main.go): the commands map. Each verb names its flags from flagDefs, its allowed positional counts, whether it takes -- ARGV, and whether it writes. parse joins the first two words to find verbs like record unit, and parseInterspersed accepts flags anywhere on the line. A usage error exits 64 and a failed verb exits 1.
  • Sync pipeline (main.go): syncActual loads the stored units through store.Writable, which refuses an old-format state, then the candidates and the state. It snapshots the tree, reads git renames since the last fingerprint, and runs identity.Reconcile. It then runs evidence.Checker.Apply and group.Fallback, and saves units, candidates and state. It refuses an extraction with no units when units are already stored. After sync and setup, attention prints the drifted and dead evidence counts and each parent conflict.
  • Sync revision (main.go): the revision a drifted item counts from. It stays state.Revision while the tree's fingerprint is unchanged, so committing .abbd/ is no later revision, and becomes gitx.Head once the tree changes.
  • Writers (main.go, setup.go): sync passes identity.Sync, so only the script's claims are replaced. setup passes identity.Setup, so the supplement's claims are replaced too and what abbd record wrote stays. A supplement unit that setup no longer reports stays when a human stated something about it, and setup prints it as kept.
  • Determinism proof (setup.go): deterministic runs the script three times and demands identical output. The third run sets new PYTHONHASHSEED and PERL_HASH_SEED values. A mismatch reports the first differing line, and nothing is saved.
  • Record writer (record.go): writer is human when --source is given and reader otherwise. Each writer's claim on an edge or a parent sits beside the others. recordRelation refuses a reader's claim on an edge a human stated, and one on an edge the script already claims. With --phrase on an edge that already shows, whoever's claim shows there, it stores only the writer's phrase note, which labels the line and is never a claim, and leaves every claim's evidence, via and origin as they were. On an edge that does not show yet it records the claim and the note. It refuses a reader's note that a human's mask hides, and a reader's claim on an edge a human's mask stands on, whatever its via, through Unit.RelationMasked, so neither a phrase nor a new via brings back a retracted coupling. It checks the phrase against the via of every claim on the edge, so a phrase on the script's edge cannot restate the script's via. model.ValidatePhrase checks the phrase at the command line. recordParent refuses a directory group that sync made and a placement that makes a unit its own ancestor. A human's parent stores the script's parent as over. When a higher claim still wins, recordParent prints where the unit stays.
  • Live citation (record.go): citations parses each PATH:LINES:QUOTE, normalizes it with extract.NormalizeEvidence, and refuses a quote the file it names does not hold now. A unit from record unit has a reader's name and stays present until its evidence is dead. Its --parent must be a present module or feature, and becomes the reader's parent claim on the unit's own evidence.
  • Refresh and retract (record.go): refresh serves record evidence on a unit, ID.parent or an edge. It replaces the evidence of the reader's claim there. When only the supplement's claim is there, it adds a reader's claim above it, and a supplement unit becomes the reader's. A refreshed unit that is absent comes back unless it was retracted. retract removes the writer's own claim on the target and masks each lower INFERRED claim on it, bound to that claim's content. On an edge that still shows after it, because the script's or a higher writer's claim holds it, it saves what it took, returns a partial error that says so, as in retracted the phrase on X. The edge is the script's and stays, and exits 1, and run still renders the blueprint for a partial. A run that can change nothing, including one on a target with no claim left, says the target is already retracted and succeeds. It fails only when the claim left is one it may not hide, such as the script's.
  • Migrate (migrate.go): converts an old-format state once, with the supplement setup used (default .abbd/extractor/supplement.json) folded onto a fresh extraction. An INFERRED claim becomes the reader's when the supplement makes no claim on the same target, and a parent claim stays the supplement's only when the supplement places the unit in the same parent. A human's parent takes the extraction's script parent as its over, which the old format never stored. Every item but the script's that is not live now becomes dead with the reason dead before migration. A unit paired with a supplement unit keeps that unit's ref as supplement_ref, by which a later setup pairs it again. ref_test.go pins that a unit stored under the older supplement_key still pairs, and that a unit file spelling both with different refs fails status. It writes nothing when the present units, their parents, or the shown relations with their origins would change.
  • Query resolution (query.go): find takes a unit ID, a name, a file, a directory, a symbol or a phrase through topology.Find. sync state DATA-0006

의미 판독

state.yaml says which code the stored units were synced from. fingerprint is a git tree object of the working tree as gitx.Snapshot writes it into a scratch index. It holds every file git add -A would stage, untracked files included, with .abbd/ left out. A submodule counts as the commit the superproject's index records, not the one checked out, so every clone of a commit fingerprints the same tree. A nested repository with no commit yet, which git add refuses, counts by its files on disk that neither repository ignores, as an untracked directory does.

The state is CURRENT exactly when the fingerprint of the tree now equals the stored one and no merge left two syncs in the file. Any edit to code, staged or not, makes it STALE until abbd sync runs. Committing changes nothing, because a commit moves HEAD and not the tree. revision only names where that tree was first synced, and blueprint is the inputs hash the blueprint was rendered from, for the blueprint's own check. Neither decides whether the state is current.

    판독 리더가 쓴 설명

    Overview

    The query commands module answers architecture questions from the stored state without writing to it. It resolves what a query names (a unit ID, an exact or near name, a file, a symbol or a phrase) to a unit, then prints the results of explain, path and impact with each fact's name and origin, and a module's stored text marked CURRENT or STALE.

    It consumes DATA-0008 module understanding to show that text, depends on MOD-0047 internal/topology for the explain, path and impact computations, and relies on MOD-0006 record writers for the digest that decides staleness. It does not change the state; recording texts, relations and notes belongs to the writers.

    Key Concepts

    • Unit resolution (resolve in cmd/abbd/query.go): returns the one unit a query names, taking the best match from find. A bare ID or name resolves directly; other matches are printed best first with the reason each matched.
    • Match listing (find in cmd/abbd/query.go): lists the units a query names, best first. It errors when the query names nothing, printing the nearest units, or when one name belongs to several units, asking for the ID.
    • Explain (explain in cmd/abbd/query.go): prints one unit at a glance: responsibility, purpose, entries, evidence, inside units, provided and consumed contracts, dependencies, users and inferred couplings. Evidence that drifted or died is marked.
    • Reader text display (explainHow in cmd/abbd/query.go): prints a module's stored text with its reader and origin. It compares the stored digest with the module's current digest and marks the text STALE when the code moved.
    • Slot notes display (explainNotes in cmd/abbd/query.go): prints each known note of a unit that holds notes, with its reader, marked CURRENT or STALE with the places that changed, plus its why, reread and cited evidence.
    • Path (path in cmd/abbd/query.go): prints the shortest chain of relations between two units hop by hop, notes where two units share a provider without a direct relation, and reports the weakest origin among the hops.
    • Impact (impact in cmd/abbd/impact.go): turns comma-separated queries into seed units, adding every unit anchored at a changed path, and prints the direct tier closely and the far tier briefly.
    • Impact by feature (byFeature in cmd/abbd/impact.go): with the features option, groups the impact under each feature with the contracts and entries it uses, then lists what no feature holds.
