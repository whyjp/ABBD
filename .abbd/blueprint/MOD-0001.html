Overview

cmd/abbd is the ABBD command line. It is one package main that dispatches the verbs of its command table over the .abbd/ directory, where a repository keeps its architecture topology. Humans and assistants run it from a shell, and the block that abbd install writes into CLAUDE.md points assistants to the /abbd skill for how to use it. The usage text calls the CLI a lever. It registers the project's extraction script and proves it deterministic. It keeps unit IDs stable across runs and checks every quoted piece of evidence against the working tree. It records what readers infer and what humans state, refreshes and retracts those claims, and converts an old-format state once. It stores pstack how's module texts, the notes in their slots, and the flows, stacks and tables readers draw, and answers explain, path and impact queries. It never judges, blocks, asks or records a decision. Even diff --check only exits 1 when a change reaches the boundary between modules, so a CI job can label the PR, and status --check only exits 1 when the state, the blueprint, a module text, a note, a flow's step, a stack's layer or a table's row is STALE or a quote drifted.

The package is glue. The logic lives in internal/. model holds the writers and the precedence table that picks which claim shows, identity reconciles IDs, evidence checks quotes, topology answers queries and diffs, screen renders, store owns the on-disk format, gitx reads git, extract parses the script's JSON, bootstrap folds in the supplement, and group places a crowded level's units in the directories their code lives in. cmd/abbd parses argv against a declarative command table, decides which writer each record speaks for, wires those packages together in a fixed order, and prints results line by line. After every verb that writes, run calls publish, which renders every page of .abbd/blueprint/ and graph.json through screen.Files, hands them to store.SaveBlueprint in one call, which removes any other file there, then records in the state's Blueprint the inputs hash it rendered them from and in Rendered the store.HashRender of the files it wrote. The tests read the blueprint through blueprint() in helpers_test.go, every page joined, so a check passes whichever page shows what it asks for.

Key Concepts

  • Command table (main.go): the commands map. Each verb names its flags from flagDefs, its allowed positional counts, whether it takes -- ARGV, and whether it writes. parse joins the first two words to find verbs like record unit, and parseInterspersed accepts flags anywhere on the line. A usage error exits 64 and a failed verb exits 1.
  • Sync pipeline (main.go): syncActual loads the stored units through store.Writable, which refuses an old-format state, then the candidates and the state. It snapshots the tree, reads git renames since the last fingerprint, and runs identity.Reconcile. It then runs evidence.Checker.Apply and group.Fallback, and saves units, candidates and state. It refuses an extraction with no units when units are already stored. After sync and setup, attention prints the drifted and dead evidence counts and each parent conflict.
  • Sync revision (main.go): the revision a drifted item counts from. It stays state.Revision while the tree's fingerprint is unchanged, so committing .abbd/ is no later revision, and becomes gitx.Head once the tree changes.
  • Writers (main.go, setup.go): sync passes identity.Sync, so only the script's claims are replaced. setup passes identity.Setup, so the supplement's claims are replaced too and what abbd record wrote stays. A supplement unit that setup no longer reports stays when a human stated something about it, and setup prints it as kept.
  • Determinism proof (setup.go): deterministic runs the script three times and demands identical output. The third run sets new PYTHONHASHSEED and PERL_HASH_SEED values. A mismatch reports the first differing line, and nothing is saved.
  • Record writer (record.go): writer is human when --source is given and reader otherwise. Each writer's claim on an edge or a parent sits beside the others. recordRelation refuses an edge the script already claims and a reader's claim on an edge a human stated. recordParent refuses a directory group that sync made and a placement that makes a unit its own ancestor. A human's parent stores the script's parent as over. When a higher claim still wins, recordParent prints where the unit stays.
  • Live citation (record.go): citations parses each PATH:LINES:QUOTE, normalizes it with extract.NormalizeEvidence, and refuses a quote the file it names does not hold now. A unit from record unit has a reader's name and stays present until its evidence is dead. Its --parent must be a present module or feature, and becomes the reader's parent claim on the unit's own evidence.
  • Refresh and retract (record.go): refresh serves record evidence on a unit, ID.parent or an edge. It replaces the evidence of the reader's claim there. When only the supplement's claim is there, it adds a reader's claim above it, and a supplement unit becomes the reader's. A refreshed unit that is absent comes back unless it was retracted. retract removes the writer's own claim on the target and masks each lower INFERRED claim on it, bound to that claim's content. A run that can change nothing, including one on a target with no claim left, says the target is already retracted and succeeds. It fails only when the claim left is one it may not hide, such as the script's.
  • Migrate (migrate.go): converts an old-format state once, with the supplement setup used (default .abbd/extractor/supplement.json) folded onto a fresh extraction. An INFERRED claim becomes the reader's when the supplement makes no claim on the same target, and a parent claim stays the supplement's only when the supplement places the unit in the same parent. A human's parent takes the extraction's script parent as its over, which the old format never stored. Every item but the script's that is not live now becomes dead with the reason dead before migration. A unit paired with a supplement unit keeps that unit's ref as supplement_ref, by which a later setup pairs it again. ref_test.go pins that a unit stored under the older supplement_key still pairs, and that a unit file spelling both with different refs fails status. It writes nothing when the present units, their parents, or the shown relations with their origins would change.
  • Query resolution (query.go): find takes a unit ID, a name, a file, a directory, a symbol or a phrase through topology.Find. A match that is not exact prints the best five with reasons. explain lists every parent claim when a unit has more than one, and marks each drifted or dead item. For a contract with entries it prints each entry's key, name, shape and need, with the units whose relations use it. entries_test.go and fields_test.go drive entries through run on a scratch repository, the second for a table's fields with their types, need, writers and readers: how sync stores them, the diff lines and the --check verdict for each kind of entry change, an entry's note and its row on the page, and the extraction's refusals. impact also seeds every other unit anchored at a queried path, and with --features prints topology.ByFeature: each feature the change reaches, what it holds that is reached, and the reached contracts it uses with the entries it names, then what no feature holds. explain names the entries each drawn link it lists uses, so a page's contracts read with the endpoints it calls; byfeature_test.go drives both, including a part of a page whose whole use of a contract keeps the page's use whole.
  • Evidence and status (evidence.go): abbd evidence checks the items of the claims that show, the parent's through Unit.ShownParent, and prints each as live, drifted or dead. It never writes, so a drifted item stays drifted. abbd status prints whether the state and the blueprint are current, and names a state a merge left with two syncs STALE until abbd sync on the merged tree. It prints the unit, relation and module-text counts, the drifted and dead items, every mask and every parent conflict. With --check it returns an error naming each thing that is behind: a STALE state, blueprint or module text, or drifted evidence. An UNKNOWN state or blueprint fails it too, and the error names the cause: no git work tree, a git error, or a blueprint/ with no files or a state that does not say what was rendered. Dead evidence and orphaned texts, whose module textModule no longer accepts, are reported and never fail it. readTexts reports the readability of the texts that show beside a module, and skips the orphans.
  • Uncovered modules (uncovered.go, main.go): attention, which sync and setup run after they write, prints uncovered: for each manifest in the working tree, such as go.mod or package.json, under whose directory no present unit holds an anchor and which no unit holds by a directory anchor over it, so an Android build.gradle inside a module anchored on its directory stays quiet. It skips the root's manifest and any under testdata, node_modules or vendor. The line is a warning, and status --check never fails on it. It catches a module that an extraction script listing modules by hand does not know. uncovered_test.go drives it on a scratch repository.
  • Fingerprint (install.go): a git tree object of the working tree minus .abbd/, saved in the state at sync. A nested repository with no commit yet counts by its files on disk that neither repository ignores, as an untracked directory does. status reports STALE when it no longer matches the tree. keepingCurrent moves it along when install edits CLAUDE.md while the state is current, and leaves a merged state for sync.
  • Understanding (understand.go): how's text for any module, at any depth, stored INFERRED with the digest, store.CodeFormat and the per-anchor and per-quote hashes of store.Stamp. textModule decides which modules take a text, for understand, explainHow and the orphan count in status: any present module. A module's digest reads its whole subtree, so a text on a module inside another describes that module's code, and the text of the module above it describes it too. understand cleans the text with store.CleanText first, so a byte order mark, line endings and trailing blanks do not count, and refuses to store the same text again on changed code. After it stores a text, readText prints each section over narrative.MaxSection characters and each phrase that reads as history, and never refuses the text for them. explainHow shows it as CURRENT or STALE. --restamp stamps the stored text again without a new one, after the extraction moved what the module holds. mayRestamp refuses a text stored in an older format, and otherwise allows a restamp only when store.Changed finds nothing: every anchor and quote of the module now is one the text was written against, its code unchanged, and none of those is gone. A retract that moves a place of a quote up a rank changes that place's hash, so it blocks a restamp until a fresh text is stored. A refusal names up to five of them. A restamp keeps the text's hashes. syncActual runs store.UpgradeUnderstandings after it saves the units, and prints each old text that stays current and each one that goes STALE because the new digest reads code the old one never read, such as the second place of a quote cited twice in one file.
  • Notes (understand.go, record.go, evidence.go, query.go): abbd understand ID.SLOT[.KEY] FILE --evidence ... parses the address with model.ParseNoteRef, takes only live quotes through citations, and stores a store.Note stamped by store.NoteStamp over those quotes alone. It refuses a quote its file holds more than once, since sync never moves a note's lines. It also refuses the same words, however spaced (sameWords), on the same set of quotes, in any order (sameCitations), once their code moved, and it keeps a stored Why only when the decision cites the same set of quotes; on other quotes it drops the Why and says so, since the human spoke about other code. record fact ID.decisions.KEY writes that Why as a human's, with its source, and leaves the stamp alone. understand ID.SLOT[.KEY] --reread-by WHO (reread) takes neither a FILE nor quotes: it stamps a STALE note again on the quotes it already cites, keeps its words and Why, and records a store.Reread of who, the date and the places that had moved. It refuses a current note, an empty WHO, a note whose quote its file no longer holds exactly once, and a note whose stored Code keys differ from the ones NoteStamp gives its Evidence, since a hand edit of its quotes left words written about other code. It moves each quote's lines to where the quote sits now. A note stored with new words drops that record. noteUnit holds the check, shared with storing a note, that the unit takes notes and lists the entry. forget ID.SLOT[.KEY] finds the note whose file that name gives (Note.FileRef), across every unit since a misfiled note is listed under the unit its frontmatter says, removes it with store.RemoveNote, and prints whether it was CURRENT, STALE, orphaned or misfiled and the Why that went with it. status counts the notes, names each STALE one with the quotes whose code changed and how to store it again, stamp it again once reread, or forget it, and fails --check on it. It skips orphans, naming each file as it sits and the forget that removes it, including a file not at the path its frontmatter names. A file whose directory is no unit ID has no FileRef, so dropNote names the file to delete instead. It warns about each markdown file there with no frontmatter, and lints notes beside the module texts. understand refuses an entries note whose key names no entry of the contract, and status counts one whose entry the contract no longer lists as orphaned. explain prints each note with its state and who reread it. notes_test.go and forget_test.go drive all of it through run on a scratch repository, including where the blueprint puts a contract's notes. extractor_test.go runs this repository's own extraction script and reads each unit it prints by its ref. coupling_test.go runs setup with a supplement whose coupling joins two script units by their refs, refuses one whose two refs name the same unit, and warns when a supplement ref shadows the script's.
  • Figures (figure.go, flow.go, stack.go, table.go, evidence.go): abbd flow KEY FILE, abbd stack KEY FILE and abbd table KEY FILE store a figure from a draft, and abbd flow KEY, abbd stack KEY and abbd table KEY print the stored one as a draft. Their handlers, flow, stack and table, each run figure[C], for a flow's steps, a stack's layers or a table's rows, so every rule here holds for every kind and its messages take the kind's nouns. checkFigure refuses a draft without one question on one line, with fewer or more parts or columns than the kind allows, with a column model.ValidateColumns refuses, with a quote the code does not hold exactly once, with a part whose Gaps the state shows, or with parts the kind's whole check refuses, such as a unit two layers hold. It moves each quote's lines to where the quote sits now. A quote's symbol is not checked. Each part records its writer: with --source it is a human's, USER_STATED, else a reader's. retire carries the stored figure's Retired parts forward with each stored part that is STALE. It keeps each one as its claim's Retire gives it, so a retired step keeps no calls. It forgets one whose code is back as written, one of whose own units left the state, or whose files are all gone. It refuses a reader's draft part that says a retired part's words, in any case or spacing and on any unit, and cites a file whose code changed under that part, however many stores ago it left the figure. A human's store is not refused and clears the retired parts it says again. It cannot tell a reworded part from a re-read one. A human replaces any part. A reader may change a figure with a human's parts only once one is open, which means STALE on its own or named by a gap of the whole figure, such as two layers that hold one unit after it moved under another. Each other human part must come back as written and in its order, so it keeps the human's word. An open part that comes back as written keeps it too, and the question, the column head and the caption must come back as written (mayReplace). The command prints which human parts it kept and which it replaced, and warns on the kind's Long field past 80 characters, a step's does, a layer's role or any cell of a row. statusFigures prints each STALE part with why and says to read that code and store the figure again, and each stray with its reason and how to clear it, and status --check fails while a part is STALE. A stack also says how many breaches it holds when it is stored, and statusBreaches lists each with its ends, their layers and its origin. A breach never fails the check. A table says how many cells under a unit's column model.Readings finds unbacked or unsaid when it is stored, and statusCells lists each with its row, its ends and the relation's origin. Neither fails the check, since only a reader of the code can say whether the cell or the graph is wrong.

sync state DATA-0006

의미 판독

state.yaml says which code the stored units were synced from. fingerprint is a git tree object of the working tree as gitx.Snapshot writes it into a scratch index. It holds every file git add -A would stage, untracked files included, with .abbd/ left out. A submodule counts as the commit the superproject's index records, not the one checked out, so every clone of a commit fingerprints the same tree. A nested repository with no commit yet, which git add refuses, counts by its files on disk that neither repository ignores, as an untracked directory does.

The state is CURRENT exactly when the fingerprint of the tree now equals the stored one and no merge left two syncs in the file. Any edit to code, staged or not, makes it STALE until abbd sync runs. Committing changes nothing, because a commit moves HEAD and not the tree. revision only names where that tree was first synced, and blueprint is the inputs hash the blueprint was rendered from, for the blueprint's own check. Neither decides whether the state is current.

revision stays the commit where a tree was first synced. A sync whose tree matches the stored fingerprint keeps the stored revision, and only a new tree, or a state without a revision, takes HEAD.
