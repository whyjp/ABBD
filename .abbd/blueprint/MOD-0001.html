Overview

abbd CLI는 .abbd 상태를 읽고 쓰는 프로그램이다. 명령줄 하나를 동사 하나로 바꿔 실행하고, 쓰기 동사가 성공하거나 retract가 일부만 거부되면 블루프린트를 다시 그린다. 쓰기 동사는 setup, sync, migrate, record relation·unit·parent·fact·evidence, retract, understand, forget, flow, stack, table, overview다. 읽기 동사는 extract, relate, explain, brief, path, impact, diff, review, evidence, status, lint다. abbd status는 종류별 개수에 실행 맥락(EXEC)도 세고, abbd diff는 더해지고 빠진 실행 시점 관계를 따로 센다. 다만 install은 CLAUDE.md를 쓰고, scope는 커밋하지 않는 scope 파일을 쓰며, lint --record는 .abbd/lint-debt.yaml을 쓴다. 모든 동사는 abbd exit codes를 지킨다. 성공하면 0, 명령이 실패하면 1, 명령줄을 해석하지 못하면 64다.

이 모듈은 sync state, module understanding, slot notes, 그리고 abbd install이 쓰는 CLAUDE.md abbd block을 제공한다. project.yaml의 추출 argv와 language, 그 스크립트가 내는 extraction JSON, unit files, blueprint files, relation key, evidence citation을 쓴다. 저장된 산문은 project.yaml이 정한 언어로 읽혀야 한다. brief가 그 언어를 먼저 알리고, 저장 명령은 다른 언어로 읽히는 글에 language: 줄을 찍고, lint는 그런 글을 실패로 잡는다. 각 동사 아래 일은 이웃 모듈이 맡는다. ID 조정, 증거 확인, git 질의, 토폴로지, 렌더링, 저장소가 그렇다. CLI는 스스로 결정을 내리거나 기록하지 않는다. 결정의 이유는 사람의 --source가 있어야 저장되고, 틀린 코드 사실은 여기서 철회하지 않고 추출기에서 고친다. 테스트 바이너리는 추출 스크립트를 겸한다. 인자 없이 실행하면 그 저장소 옆에 ROOT.extraction.json을 출력하므로, 테스트는 환경 변수를 나누지 않고 병렬로 돈다.

나머지 설명

Key Concepts

명령 실행과 sync

  • argv parsing and dispatch (cmd/abbd/main.go): run과 parse가 command 표를 훑어 record relation 같은 두 단어 동사를 잇고, 위치 인자 사이의 플래그를 받으며, -- 분리는 setup에만 허용한다. 플래그는 opts에, 저장소와 출력은 env에 담긴다. 해석 오류는 사용법을 찍고 64로 끝나지만, --help, -h, help는 사용법을 찍고 0으로 끝난다. 쓰기 동사가 성공하면 publish를 부르고, partial인 retract도 그린 뒤 1로 끝난다. 그 밖의 실패는 그리지 않고 1을 낸다. 스레드나 타이머는 없고, 해제할 자원도 없다.
  • sync pipeline (syncActual): project.yaml이 지정한 스크립트를 exec.Command로 띄우고(타임아웃 없음, runScript), argv의 첫 낱말이 abbd이면 PATH의 다른 abbd가 아니라 지금 도는 바이너리를 띄우며 그 경로를 ABBD_BIN으로 알린다. 그다음 JSON을 파싱하고, git 이름 변경을 따라 ID를 조정하고, 증거를 적용하고, 디렉터리 그룹을 더하고, 문장을 찍은 뒤 유닛, 후보, state.yaml을 저장한다. 리비전은 트리 지문이 바뀌었거나 저장된 리비전이 없을 때만 움직인다. 유닛이 저장된 상태에서 유닛 0개짜리 추출은 거부한다. 스크립트 실패는 그 stderr를 담아 실패하고, 재시도하지 않는다. 추출이 더는 보고하지 않는 유닛은 unmatched로 찍고, 그 유닛이 어디에도 그려지지 않고 검사에도 걸리지 않으며 지울 명령도 필요도 없다고 한 줄로 밝힌다.

setup

  • setup determinism proof and supplement fold (cmd/abbd/setup.go): 추출을 세 번 돌리되 마지막은 PYTHONHASHSEED와 PERL_HASH_SEED를 바꿔 돌리고, 어긋나면 처음 다른 줄을 짚는다. --supplement를 루트 기준으로 읽어 스크립트 출력 위에 접고, 묶음 module은 구성원이 둘 이상일 때만 받고, 증명 뒤에야 argv를 저장하며, setup으로 sync한다. 저장할 때 portable은 argv 머리나 -- 뒤에서 abbd 바이너리를 경로로 가리킨 낱말을 맨 abbd로 바꾼다. 그래서 project.yaml과 페이지 꼬리말에 로컬 경로가 남지 않는다. --가 없으면 저장된 argv를 다시 쓴다. migrate(cmd/abbd/migrate.go)는 옛 형식 상태를 한 번 바꾼다. supplement가 쓴 주장(claims)을 supplement나 reader에게 나눠 주고, 그래프가 바뀌면 전체를 거부한다.
  • bundled front-ends (cmd/abbd/extract.go): abbd extract cargo|cmake[=DIR]는 bundled front-end(MOD-0058)가 빌드 시스템의 모델에서 읽은 extraction JSON을 찍고, 설정한 빌드 트리는 저장소 밖 $ABBD_CACHE_DIR나 사용자 캐시 디렉터리에 둔다. 상태는 읽지도 쓰지도 않으므로, 등록하면 abbd setup -- abbd extract cargo처럼 추출 스크립트가 된다. -DNAME=VALUE 인자는 abbd 플래그가 아니라 CMake 캐시 옵션이어서 parse가 extract에서만 따로 떼어 ExtractWith로 configure에 넘긴다.
  • CLAUDE.md abbd block (cmd/abbd/install.go): 어시스턴트에게 블루프린트를 먼저 묻고, sync하고, diff를 남기고, .abbd를 커밋하라고 이르는 표시된 글이다. 표시는 혼자 한 줄에 있고 펜스 밖에 있을 때만 센다. 짝 없는 표시는 오류이고, install은 줄바꿈과 파일의 나머지를 지킨다.
  • blueprint publish (cmd/abbd/screen.go): 트리 스냅숏과 함께 화면 입력을 읽어 블루프린트 파일을 쓰고, 입력과 렌더 해시를 상태에 남긴다. 유닛이 없으면 아무것도 하지 않는다.

코드 수준 관계

  • bundled relaters (cmd/abbd/relate.go): abbd relate go|rust[=DIR]는 -- 뒤 명령이 찍는 extraction JSON을, 명령이 없으면 표준 입력의 것을 읽어, bundled relater(MOD-0060)가 코드에서 읽은 unit 사이 관계를 더해 같은 JSON으로 다시 찍는다. 아는 필드만 받아 extract.Doc으로 읽는다. relate.Relate가 relater마다 Unread를 돌려주면, relater 이름과 읽지 못한 파일 수와 이유를 표준 오류에 한 줄로 밝히고 그 파일 경로를 줄마다 나열한다. 읽지 못한 파일은 go에서는 빌드 제약이 뺀 파일이고, rust에서는 어느 설정으로도 컴파일되지 않은 파일이다. 상태는 읽지도 쓰지도 않으므로, 등록하면 abbd setup -- abbd relate go -- 추출 argv처럼 추출 스크립트를 감싼다. RELATER[=DIR] 인자는 front-end와 같은 frontend.SpecOf로 읽는다. 사용법 글이 rust의 Cargo.toml과 $ABBD_LSP_RUST나 PATH의 rust-analyzer를 알린다.

읽기와 기록

  • query commands (cmd/abbd/query.go): 유닛을 ID, 이름, 파일, 심볼, 문구로 찾고 가까운 후보를 나열한 뒤 explain, path, impact를 찍는다. path는 한 실행 맥락 위에서 도는 두 유닛을 그 맥락을 함께 쓸 뿐인 사이로 이른다. explain은 코드 다이제스트에 견줘 모듈 글을 CURRENT나 STALE로 보이고, impact는 파일에 걸린 유닛을 모두 씨앗으로 삼아 --features로 기능별로 묶는다.
  • review commands (cmd/abbd/diff.go, cmd/abbd/review.go): diff는 기준 리비전의 유닛과 지금을 비교하고, --check에서는 경계 변경만이 실패가 된다. diff는 words.go가 기준과 지금의 상태에서 각각 읽은 written을 견줘, 기준 이후 생기거나 사라지거나 바뀐 모듈 글, 노트, flow step도 잃은 문장과 얻은 문장과 함께 이른다. 모듈 글은 모듈 ID를 키로 삼으므로 이름이 바뀌어도 이어지고, flow step은 먼저 맞춰 세우므로(aligned) 넣거나 뺀 step은 변경 하나다. 텍스트 출력은 방향마다 문장을 넷까지 보이고, --json은 모두 보인다. 기준의 글은 CheckoutAt이 풀어 놓은 기준 체크아웃에서 읽고, --page는 같은 체크아웃에서 기준의 페이지를 pagesAt으로 다시 그린다. abbd scope IDS --why TEXT가 손댈 유닛을 선언하면 review가 변경을 그 옆에 둔다. 범위 밖 유닛과 손대지 않은 선언 유닛을 짚고, STALE인 constraints 노트를 다시 읽을 제약으로 이른다. evidence와 status(cmd/abbd/evidence.go)는 checkEvidence로 생존과 신선도를 쓰지 않고 보고한다.
  • record writers (cmd/abbd/record.go): record relation, unit, parent, fact, evidence와 retract다. 받는 인용은 모두 지금 트리에 있어야 하고, 적은 줄에서 세 줄을 넘게 떨어진 곳에 있으면 인용이 있는 줄을 알리며 거부하고(citations와 misplaced), 관계에서는 EXTRACTED가 USER_STATED를, USER_STATED가 INFERRED를 이긴다. 같은 코드의 중복 유닛은 거부한다. target은 record evidence와 retract가 다루는 유닛, 필드, 엣지, .phrase, .when이고, partial은 retract가 일부만 거부됐음을 뜻한다. record fact는 사람이 말한 purpose와 responsibility, decision 이유 외에 실행 맥락이 어떻게 도는지(EXEC-ID.run)도 받는데, 그 값은 model.ParseRun이 읽은 정규형으로 저장한다. reader의 문구가 프로젝트 언어로 읽히지 않으면 language: 줄을 찍는다.

글, 노트, 그림

  • texts and notes (cmd/abbd/understand.go, cmd/abbd/brief.go): understand는 모듈 글을 코드 다이제스트로 찍어 저장하고, TODO 줄, 다른 섹션, 바뀐 코드에 바뀌지 않은 글은 거부한다. 긴 섹션, 역사 문구, 이름 없는 유닛, 다른 유닛의 경로를 보고한다. brief는 reader가 채울 뼈대를 찍고 ## Read first 첫 줄에 쓸 언어를 밝힌다. 읽을 파일 목록에서 테스트와 테스트 데이터는 빼고 몇 개를 뺐는지만 적는다. 그 아래에 fan-in 순 핵심 유닛(keyunits.go, 20초 제한의 git grep, 타입은 이름 뒤에 {나 struct 같은 선언 모양이 올 때만 세므로 도움말의 type names 같은 산문은 빠지고 소문자 타입은 남는다. 언어와 표준 라이브러리가 어디서나 쓰는 이름은 뺀다), 런타임 결합 줄(binding.go), doc 주석에서 뽑은 상자 초안(draft.go)을 덧붙인다. 노트는 한 번만 나오는 인용을 인용하고, flow, stack, table은 그림 작성기 하나를 나눠 쓴다. primary: true는 stack에만 붙는 표시로, 그 stack의 layer가 저장소의 주 흐름 단계가 된다(cmd/abbd/figure.go). 명령은 flow나 table에 붙은 표시와, 이미 다른 stack이 표시된 상태의 두 번째 표시를 거부한다. primary를 뺀 초안은 저장된 표시를 그대로 두고 그렇게 했다고 알리며, 사람이 말한 stack의 표시는 --source를 단 primary: false로만 지워진다. 병합으로 두 stack이 표시되면 status가 conflict: 줄을 내고 실패하고, 손으로 flow나 table에 남긴 표시는 warning: 줄로 이름만 댄다. 주 흐름 stack에는 breach를 세지 않으므로 stack 명령과 status는 그 stack의 거꾸로 쓰는 관계를 보고하지 않는다(cmd/abbd/stack.go). abbd overview FILE(cmd/abbd/overview.go)은 같은 파트 검사(checkParts)로 overview의 구역과 고른 선을 확인해 .abbd/overview.md에 저장한다. FILE 없는 abbd overview(cmd/abbd/overview_draft.go)는 저장된 구역과 선 위에 YAML 주석으로 쓸 거리를 찍는다. overview가 그리는 상자와 각 상자가 서는 단계, 주 흐름의 단계, stack 층과 폴더에서 온 구역 후보, 살아 있는 relation이 잇는 상자 쌍마다의 선 후보를 강한 순으로 relation 수와 인용과 함께 찍는다. 아래 relation이 코드를 인용하지 않는 후보에는 quoteFinder가 from 상자의 파일에서 relation이 가는 unit을 부르는 줄을 찾아 준다. 쓰는 entry, 앵커 심볼, 식별자로 쓴 이름, 앵커 파일 이름, 이어서 어느 언어에나 있는 자리 신호 순으로, 곧 앵커 디렉터리를 import 줄이 적는 대로(경로, 점, ::)와 마지막 디렉터리의 한정 사용(이름., 이름::)이다. 호출하는 줄을 먼저 보고, 테스트, fixture 디렉터리, 산문 파일, 주석 줄, 함수 정의 줄은 건너뛰며, 파일에 한 번만 있고 두 끝의 코드에 놓인 줄만 고르며, 이름으로 찾았다고 주석에 밝힌다. 출력 전체가 그대로 저장되는 FILE이다. 주 흐름은 그 파일에 따로 두지 않고 주 흐름 stack을 쓴다. status는 STALE 파트와 고칠 길(바뀐 코드를 다시 읽거나 지금 state로 다시 그리기)을, evidence는 그 인용을, explain은 유닛이 놓인 주 흐름 단계(그 stack의 layer)와 구역을 프로젝트 언어로 찍는다. 어느 단계도 이름 짓지 않은 상자는 안의 unit을 이름 짓는 첫 단계에 서므로, explain은 그 단계와 그 unit을 찍는다.

남은 unit

  • forget (cmd/abbd/understand.go): abbd forget ID는 sync가 unmatched로 남긴 unit을, 상태의 다른 파일이 그 ID를 이름 짓지 않을 때만 지운다. 번호는 다시 쓰이지 않는다.

언어와 lint

sync state DATA-0006

의미 판독

state.yaml says which code the stored units were synced from. fingerprint is a git tree object of the working tree as gitx.Snapshot writes it into a scratch index. It holds every file git add -A would stage, untracked files included, with .abbd/ left out, by an exclude pathspec unless .gitignore already ignores it, as a whitelist .gitignore does. A submodule counts as the commit the superproject's index records, not the one checked out, so every clone of a commit fingerprints the same tree. A nested repository with no commit yet, which git add refuses, counts by its files on disk that neither repository ignores, as an untracked directory does.

The state is CURRENT exactly when the fingerprint of the tree now equals the stored one and no merge left two syncs in the file. Any edit to code, staged or not, makes it STALE until abbd sync runs. Committing changes nothing, because a commit moves HEAD and not the tree. revision only names where that tree was first synced, and blueprint is the inputs hash the blueprint was rendered from, for the blueprint's own check. Neither decides whether the state is current.

결정 revision-stays 판독

revision stays the commit where a tree was first synced. A sync whose tree matches the stored fingerprint keeps the stored revision, and only a new tree, or a state without a revision, takes HEAD. Committing .abbd/ after a sync moves HEAD without changing the tree, so the next sync writes the same bytes and .abbd/ stays clean.     판독 리더가 쓴 설명

    Overview

    The query commands module answers architecture questions from the stored state without writing to it. It resolves what a query names (a unit ID, an exact or near name, a file, a symbol or a phrase) to a unit, then prints the results of explain, path and impact with each fact's name and origin, and a module's stored text marked CURRENT or STALE.

    It consumes DATA-0008 module understanding to show that text, depends on MOD-0047 internal/topology for the explain, path and impact computations, and relies on MOD-0006 record writers for the digest that decides staleness. It does not change the state; recording texts, relations and notes belongs to the writers.

    나머지 설명

    Key Concepts

    • Unit resolution (resolve in cmd/abbd/query.go): returns the one unit a query names, taking the best match from find. A bare ID or name resolves directly; other matches are printed best first with the reason each matched.
    • Match listing (find in cmd/abbd/query.go): lists the units a query names, best first. It errors when the query names nothing, printing the nearest units, or when one name belongs to several units, asking for the ID.
    • Explain (explain in cmd/abbd/query.go): prints one unit at a glance: responsibility, purpose, entries, evidence, inside units, provided and consumed contracts, dependencies, users and inferred couplings. Evidence that drifted or died is marked.
    • Reader text display (explainHow in cmd/abbd/query.go): prints a module's stored text with its reader and origin. It compares the stored digest with the module's current digest and marks the text STALE when the code moved.
    • Slot notes display (explainNotes in cmd/abbd/query.go): prints each known note of a unit that holds notes, with its reader, marked CURRENT or STALE with the places that changed, plus its why, reread and cited evidence.
    • Path (path in cmd/abbd/query.go): prints the shortest chain of relations between two units hop by hop, notes where two units share a provider without a direct relation, and reports the weakest origin among the hops.
    • Impact (impact in cmd/abbd/impact.go): turns comma-separated queries into seed units, adding every unit anchored at a changed path, and prints the direct tier closely and the far tier briefly.
    • Impact by feature (byFeature in cmd/abbd/impact.go): with the features option, groups the impact under each feature with the contracts and entries it uses, then lists what no feature holds.
    • Artifact (explain in cmd/abbd/query.go): explain prints a module's set of build artifacts with whoever said it, such as artifacts: shared, static (공유 라이브러리 · 정적 라이브러리; EXTRACTED), after its parent.

blueprintstring필수abbd CLIinternal/screen

The InputsHash of .abbd/ the blueprint was last rendered from, which publish writes after SaveBlueprint has written every page and graph.json. status calls the blueprint STALE when it differs from the hash now, and UNKNOWN when it is empty. While it matches and blueprint/ holds no files, as in a checkout that lacks the committed pages, status says the blueprint is NOT DRAWN and the check passes. InputsHash leaves state.yaml out, so writing this value does not change the hash it records.
