맡은 것 Owns the on-disk layout of .abbd: unit Markdown files, candidates, state, project config, module understandings and blueprint files, plus the fingerprints that tell when derived views are stale. 판독 STALE

왜 있는가 so every command reads and writes the .abbd directory through one place that keeps its files stable and diffable 판독 STALE

점선: 설계로만 이어진 관계
판독 리더가 쓴 설명 · pstack poteto-mode 0.15.36

Overview

store는 .abbd 디렉터리를 읽고 쓰는 유일한 패키지다. YAML frontmatter를 단 Markdown이 원본이고 나머지는 모두 거기서 파생된다. 이 패키지가 제공하는 계약은 unit files(architecture나 features 아래 unit마다 파일 하나), state.yaml의 sync state, project.yaml, module understanding 텍스트, slot notes, 그리고 저장된 flow, stack, table이다. Project는 등록된 추출 argv, 프로젝트의 Name과 Purpose, overview 밀도 컷을 켜는 OverviewCut(사람이 고르기 전에는 nil이라, 고른 false가 저장을 거쳐도 남는다), 그리고 사람이 저장된 산문을 읽는 언어 Language를 담는다. Language는 model.Language라서 BCP-47 태그가 아니면 load가 거부하고, Lang은 project.yaml에 언어가 없으면 OS 로캘의 언어를 돌려준다. 이름이 없으면 blueprint는 ABBD라고 쓰고, ProjectDir은 store가 놓인 프로젝트 루트를 가리킨다. merge candidates file, lint debt, 그려진 상태 옆에 커밋되는 blueprint 페이지, compare 뷰가 이전 상태로 읽는 .abbd 사본도 이 패키지가 맡는다.

텍스트, 노트, figure 파트를 그것이 설명하는 코드에 대해 stamp해서 상태를 읽는 쪽이 CURRENT와 STALE을 구분하게 하고, 자기 입력을 해시해서 blueprint가 오래됐는지 알게 한다. 리비전의 파일, 서브모듈 핀, 스냅숏은 git 질의로, 인용 주변 줄은 evidence 검사기로, unit, claim, evidence는 unit model로, 후보 모양은 identity에서 가져온다. 담고 있는 unit에 대해서는 아무것도 판단하지 않는다. ID를 맞추지 않고, 추출을 돌리지 않고, 텍스트 내용을 평가하지 않고, 코드를 쓰지 않는다.

나머지 설명

Key Concepts

Unit files and state

  • unit notes section (renderUnit): unit 파일은 frontmatter, 생성된 제목과 anchor 목록, 그리고 ## Notes 제목부터의 사람 몫으로 이루어진다. parseUnit이 읽을 때 그 부분을 떼어 두고 쓸 때 그대로 붙인다. diff가 오래전 커밋된 상태를 읽으므로 옛 형식 파일은 internal/store/legacy.go로 계속 읽힌다.
  • units at a revision (UnitsAt): 한 리비전에 커밋된 unit 파일을 gitx.FilesAt 한 번으로 읽어 파싱한다. .abbd가 없는 리비전에는 unit이 없다.
  • ID high-water mark와 ID high-water minting (NextID): state.yaml은 종류마다 마지막으로 발급한 번호를 기억해 번호가 다시 나오지 않게 한다. NextID는 손으로 기록한 unit을 위해 그 값을 올리고 상태를 저장한다. LoadState는 병합된 상태를 충돌 표시를 버리고 더 높은 high water를 남겨 읽는다.
  • blueprint pages (SaveBlueprint, CheckoutAt): SaveBlueprint는 한 번의 렌더가 만든 페이지를 쓰고 그곳의 다른 파일을 지운다. 예전 abbd가 페이지를 git에서 빼려고 쓴 * 외의 .gitignore는 남긴다(foreignIgnore). CheckoutAt은 한 리비전에 커밋된 .abbd를 페이지만 빼고 gitx.FilesAt 한 번으로 읽어 디렉터리에 풀고 store를 연다. 그래서 abbd diff가 기준의 글, 노트, flow를 거기서 읽고, --page가 기준 상태를 지금의 렌더러로 다시 그린다.
  • merge candidates file (LoadCandidates): candidates.yaml은 기존 unit과 anchor를 공유하는 새 unit을 나열하고, 없을 때도 빈 목록으로 쓴다.
  • lint debt (LoadLintDebt, SaveLintDebt): lint-debt.yaml은 뷰마다의 hard 위반 빚, 합계 상한, 페이지 한도, 유지하는 레벨의 이유, 그리고 ProseDebt를 담는다. ProseDebt는 아직 project.yaml의 언어로 쓰이지 않은 텍스트마다 lint가 보고하는 키에 그 글의 짧은 digest를 짝지어 Owed에 담고 이유를 붙이며, 같은 언어일 때만 효력이 있다. 그래서 부채는 키가 아니라 그때의 글을 지고, 같은 키에 다시 쓴 글은 부채가 아니다. SaveLintDebt는 YAML 앞에 lintDebtHead 주석을 붙인다. 이 머리글은 그림의 부채만 설명하고 prose 키는 ProseDebt의 Go 문서가 설명하므로, 모든 fixture가 기록한 부채 파일의 머리글은 그대로다.
  • no-op-aware atomic write (writeFile): 모든 쓰기는 바이트가 같은 파일을 건너뛰고, 아니면 .tmp 형제 파일에 쓴 뒤 rename한다. 그래서 같은 상태는 같은 바이트를 쓴다.

Staleness

  • store staleness hashes (InputsHash): 페이지가 그릴 수 있는 .abbd 파일을 모두 해시하되 blueprint, state, lint debt, compare 뷰는 뺀다. 페이지가 owner를 보여 주므로 owners.File이 찾은 CODEOWNERS도 입력으로 센다. abbd scope의 Scope는 git 밖의 scope.yaml에 LoadScope와 SaveScope로 읽고 쓴다. HashRender는 CRLF를 LF로 읽어 이름별로 해시하므로 줄 끝이 바뀐 체크아웃도 CURRENT로 남는다.
  • module code digest (internal/store/understanding.go): Stamp는 모듈과 그 아래 모든 unit의 anchor마다 해시 하나를, 디렉터리는 그 아래 경로 전체의 해시 하나를, 인용은 주변 줄의 해시를 기록하고 digest는 그것들을 묶어 해시한다. ModuleDigest가 저장된 텍스트와 비교하고 Changed가 움직인 곳을 나열하며, UpgradeUnderstandings는 코드가 그대로임이 보일 때만 옛 텍스트를 넘긴다.
  • slot notes and figures (internal/store/note.go): 노트나 figure 파트는 인용한 곳에 대해서만 stamp된다. 한 파일에 두 번 이상 있는 인용은 없는 것으로 세므로, 한 노트 근처의 수정은 그 노트만 STALE로 만든다. internal/store/figure.go는 flow, stack, table을 Part마다 쓴 사람과 stamp를 붙여 저장하고, figure의 Origin은 파트 중 가장 약한 origin이다. Figure.Primary는 frontmatter의 primary: true를 읽고 켜졌을 때만 쓰므로, 표시 없는 파일의 바이트는 그대로다. 초안이 이 키를 아예 적었는지는 MarkSaid가 기억하므로, 키를 뺀 초안은 저장된 표시를 지우지 않는다. Figures.Primary는 표시된 known stack이 정확히 하나일 때만 그것을 주고, Marked는 표시될 수 있는 종류(stack)에서만 표시된 키를 나열한다. Breaches는 stack이 거꾸로 쓰는 관계를 주되, 주 흐름으로 표시된 stack에는 아무것도 주지 않는다. 뒤 단계가 앞 단계를 쓰는 것은 흐름이 도는 방식이기 때문이다.

이 패키지에는 스레드, 풀, 타이머가 없다. 실패는 호출자에게 error로 돌려주고 재시도하지 않는다.
