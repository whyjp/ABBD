Overview

internal/model은 ABBD의 어휘다. .abbd/architecture/와 .abbd/features/ 아래 저장되는 모든 것의 Go 타입, 어떤 값이 합법인지 정하는 규칙, 어느 작성자의 주장이 보일지 정하는 표를 가진다. 표준 라이브러리만 import한다. model.go는 origin, kind, ID, unit, fact, evidence, relation, edge를, claims.go는 writer, evidence 상태, 우선순위 표, parent 주장, mask, Resolve를 가진다. figure.go는 모든 그림 종류가 공유하는 것을, flow.go, layer.go, table.go는 flow의 step, stack의 layer, table의 row를 가진다. slot.go는 slot과 note 주소를, entry.go는 계약의 항목을, language.go는 사람이 저장된 산문을 읽는 언어를, run.go는 실행 맥락이 일을 받는 방식과 개수를 가진다. gitx, narrative, owners를 뺀 모든 internal 패키지(bootstrap, evidence, extract, group, identity, screen, store, topology)와 cmd/abbd가 이것을 import한다. 제공하는 계약은 relation key(IF-0015)이고, 다른 모듈의 계약은 쓰지 않는다. 파일을 읽거나 쓰지 않고, git을 돌리지 않으며, 아무것도 그리지 않는다. 바깥과 닿는 곳은 DefaultLanguage가 환경 변수와 OS 로캘을 읽는 것뿐이다.

나머지 설명

패키지는 출처를 지키려고 있다

모든 fact, relation, parent 주장은 그것을 만든 Writer를 저장하고, origin은 writer에서 파생될 뿐 저장되지 않는다. script와 group은 EXTRACTED, supplement와 reader는 INFERRED, human은 USER_STATED다. writer가 모르는 값이거나 비어 있으면 검증에 실패하므로, 빈 값이 EXTRACTED를 뜻할 수 없다. Unit.Validate가 그 결과를 강제한다. human의 fact, parent, relation, mask에는 Source가 필요하고 다른 writer는 그것을 가질 수 없다. why-field는 script나 group의 것이 될 수 없다. reader나 supplement가 이름을 쓴 unit, INFERRED parent와 relation에는 evidence가 필요하고, EXTRACTED parent는 아무것도 인용하지 않는다. Signature는 계약만 가지고, parent는 다른 module이나 feature여야 한다. absent unit은 알려진 사유가 필요하고 present unit은 사유가 없다. ParseEvidence와 ParseEdge는 abbd record와 abbd retract가 명령줄에서 받는 것을 읽는다. 하위 코드는 작은 술어로 분기한다. Relation.Counts는 죽지 않은 EXTRACTED 또는 USER_STATED 주장에서 참이고, topology의 diff와 cmd/abbd의 review가 이를 부른다. internal/screen은 죽지 않은 INFERRED edge도 그린다. Present는 absent unit을 거른다.

Key Concepts

  • Unit과 Kind (internal/model/model.go): 설계 unit 하나로, ID, Kind, Name fact, 하나 이상의 Anchor를 가지고, Parents 주장, 자신의 Evidence, why-field인 Purpose와 Responsibility, 계약의 Signature, Entries, Digest, 실행 맥락만 가지는 Run fact, 보이는 Relations, Hidden 주장, Masks를 가질 수 있다. unit absent flag(DATA-0015)는 Absent와 AbsentReason(not-reported, withdrawn, evidence-dead, retracted, unneeded)이고, SetAbsent가 둘을 함께 바꾸며 Present로 걸러진다. Kind는 MOD, 계약 kind IF, EVT, DATA, CFG(IsContract), FEAT, 그리고 스레드, worker pool, event loop, async runtime 같은 실행 맥락 EXEC이고 예약어 DOM, STATE, TRN, INV를 거부한다. unit kind directories(DATA-0012)는 Dir()로, feature는 features, 나머지는 architecture에 둔다. unit ID format(IF-0016)은 KIND-NNNN이며 FormatID가 네 자리로 채우고 ParseID가 kind를 되읽는다. Semantic은 INFERRED 이름을 알린다.
  • Fact, Origin, Writer (internal/model/claims.go): Fact는 Value, Writer, human만 가지는 Source, Digest를 가진다. fact origins(MOD-0033)는 EXTRACTED, INFERRED, USER_STATED이고 Writer.Origin()이 writer에서 파생시키며, 모르는 writer에는 빈 값을 준다. Said와 Stated가 fact를 만들고 Guess는 INFERRED 값을 알린다. guess versus topology rule(MOD-0031)은 이름이 INFERRED면 unit이 semantic이고, relation은 살아 있고 EXTRACTED 또는 USER_STATED일 때만 topology로 센다는 규칙이다.

Evidence와 Anchor

  • Evidence와 Anchor (internal/model/model.go): evidence citation(IF-0017)은 Path의 원문 그대로인 Quote에 선택적 Lines와 Symbol을 더한 것으로, 명령줄에서 PATH:LINES:QUOTE로 쓰고 ParseEvidence가 읽는다. sync가 저장하는 Status, Since, Reason이 붙으며, 상태는 살아 있음(빈 값), drifted, dead이고 dead에는 사유가 필요하다. evidence line range text(DATA-0019)는 120이나 120-134 같은 형식으로 Span이 해석하고, Validate는 1 이상에서 시작하는 범위만 받는다. citable evidence paths(DATA-0020)는 .abbd/나 .git/ 아래 경로를 거부하는 규칙으로, 그 파일들이 인용문을 되풀이하기 때문이다. Same은 경로와 인용문만 비교한다. StatusOf는 항목이 하나라도 살아 있으면 live, 아니면 drifted가 있으면 drifted, 아니면 dead이고, 항목이 없는 주장은 live다. Anchor는 unit의 정체가 걸린 Path와 선택적 Symbol이고, Key()는 path#symbol, SortAnchors가 중복을 지우고 정렬한다. Closeness는 인용문이 놓인 코드를 anchor가 얼마나 가깝게 가리키는지 재며, symbol anchor, file anchor, 깊은 directory anchor 순으로 가깝고, .가 가장 멀다.

Relation과 Edge

  • Relation과 relation grammar (internal/model/model.go): Relation은 unit에서 나가는 edge에 대한 writer 하나의 주장으로 To, Kind, Writer, Source, Via, Evidence, Entries, When, Digest를 가진다. Dead는 evidence가 있고 모두 죽었다는 뜻이며 Status, Drifted, Semantic, Guess, Counts가 이를 읽는다. drawn versus listed relation rule(DATA-0010)이 Counts에 있다. relation grammar(MOD-0032)는 RelationKind.Joins로, depends_on은 아무 두 kind를, consumes는 계약에서 끝나며, provides는 module이나 feature에서 계약으로 간다. 실행 시점 관계 runs_on과 posts_to는 아래 실행 맥락에서 다룬다. Uses는 consumes와 depends_on에서만 참이다. Via는 비어 있거나 import, trait, callback, macro, config, build-feature, data, convention, call, load, spawn, link, queue, channel, signal, proxy 중 하나다. Via.Word는 청사진의 단어(예: 호출)를, Via.Plain은 선의 잉크가 이미 말하는 call과 import를 알린다. model.go의 "load" 줄은 via를 되풀이하는 구절을 막는 표일 뿐, 실행 시점 바인딩이 아니다. PhraseNote는 edge를 건너는 것을 PhraseMax자, PhraseWords단어 안에서 이름 짓는 주석으로, 주장이 아니어서 edge를 만들거나 지키지 못한다. ValidatePhrase는 via만 되풀이하는 구절을 거부하고 Dangling은 보이지 않는 edge를 가리키는 주석을 나열한다. When은 relation이 성립하는 조건으로 ValidateWhen이 검사하고, Scope는 PRIVATE, PUBLIC, INTERFACE 같은 link scope를 알리며, ConditionConflicts는 다른 조건을 가진 살아 있는 숨은 주장을 나열한다. relation key(IF-0015)는 Edge의 MOD-0001.depends_on.MOD-0002 형식으로, Edge.String이 쓰고 ParseEdge가 ID와 kind를 확인하며 읽는다. Edge.Joins가 그 kind를 검사한다.
  • Entry와 Artifact (internal/model/entry.go): Entry는 route, method, flag, field처럼 코드가 쓰는 계약의 한 부분이다. Key는 EntryKey가 소문자, 숫자, 하이픈으로 줄인 이름이고, ValidateEntries는 이름이 없거나 키로 줄지 않거나 키가 겹치는 항목을 거부한다. Artifact(model.go)는 build가 module에서 만드는 것의 집합으로 ArtifactSet이 정렬해 쓰고 Words가 청사진 단어로 준다.

실행 맥락

  • Run (internal/model/run.go): 실행 맥락이 일을 받는 Shape(tick, wait, ready, complete, steal, inline)와 몇 개가 도는지인 Count(1, N, pool)의 쌍이다. unit에는 tick 1처럼 저장되고 ParseRun이 읽으며, Words는 상자에 TICK · 1로 보인다. Unit.Validate는 EXEC가 아닌 unit의 run과 읽히지 않는 run을 거부하고, Ran은 읽히는 run만 돌려준다. Precedence에서 run은 why-field처럼 human, reader, supplement만 주장한다.
  • 실행 시점 관계 (internal/model/model.go): runs_on은 module, feature, EXEC의 코드가 EXEC 위에서 돈다는 뜻이고, posts_to는 module이나 EXEC가 EXEC에 일이나 데이터를 넘긴다는 뜻이다. RunTime이 이 둘을 알리고, Quoted는 posts_to가 생산자와 소비자를 함께 인용하도록 evidence를 2개 이상 요구한다. 맥락은 그 위에서 도는 코드를 부르고, 생산자가 넘기려고 부르는 코드는 따로 depends_on이나 consumes로 남으므로, 두 관계는 쓰임이 아니어서 layer를 어기지 않는다.

우선순위와 Resolve

  • Precedence, ParentClaim, Mask (internal/model/claims.go): Precedence는 각 field를 주장할 수 있는 writer를 높은 순으로 둔 하나의 표이고 Outranks가 비교한다. relation과 parent에서는 상태가 writer보다 먼저여서 live, drifted, dead 순으로 놓인다. ParentClaim은 writer 하나의 container 주장이고, human의 주장은 Over로 당시 script parent를 기억하며 ParentConflicts가 어긋남을 나열한다. Mask는 reader나 human이 Target 하나를 거두는 것으로, SHA-256 앞 16자리 Digest로 숨긴 주장의 내용에 묶인다. Hides에 따라 reader의 mask는 supplement를, human의 mask는 reader와 supplement를 숨긴다. human의 relation mask는 via와 무관하게 edge를 붙든다.
  • Resolve (internal/model/claims.go): 읽기 모델을 제자리에서 파생시킨다. mask된 why-field와 signature는 지우고, 이름이 mask된 present unit은 retracted로 absent가 된다. edge마다 주장을 정렬해 첫째만 보이고 나머지는 Hidden으로 간다. present unit마다 죽지 않고 mask되지 않고 present module이나 feature를 가리키며 순환을 닫지 않는 첫 parent 주장을 택하고, 순환으로 거부되면 첫 계층부터 다시 받는다. ParentCycle은 parent가 고리를 이루는 unit을 이름 짓는다. 이 패키지에는 생명주기, 스레드, 풀, 타이머가 없다. 함수는 호출자의 고루틴에서 돌고, 실패는 Validate 계열이 돌려주는 error이며 재시도하지 않는다.

Slot과 그림

  • Slot과 NoteRef (internal/model/slot.go): Slots는 module이나 계약이 가지는 slot의 단일 목록으로, 청사진이 보여 주는 순서와 한국어 제목(의미, 실패와 재시도 등)을 가진다. decisions, constraints, relations, entries는 키가 있어 키마다 note 하나를 가진다. ParseNoteRef는 ID.SLOT이나 ID.decisions.KEY를 읽고, 모르는 slot, 키 없는 keyed slot, 다른 slot의 키, 소문자·숫자·하이픈 밖의 키를 거부한다. NoteRef.Unheld는 unit이 나열하지 않는 entry를 가리키는 note를 알린다.
  • 그림 (internal/model/figure.go): FigureKind[C]는 그림 한 종류를 데이터로 담아 이름, .abbd 아래 디렉터리, part 수 범위, 열 수 범위, 경고할 단어 field, 전체 검사 Whole을 정한다. Claim[C]는 store와 명령이 모든 종류를 똑같이 다루도록 주장 타입이 구현하는 인터페이스다. state는 ID별 present unit을 가지고, under는 parent 사슬을 걷고, rests는 가장 가까운 anchor 규칙을, strongest는 provides, consumes, depends_on 순으로 가장 강한 살아 있는 relation을 찾는다. Step(flow.go)은 flow의 step으로 2개에서 FlowSteps개까지이고, 호출마다 strongest가 주는 relation이 없으면 gap을 낸다. Layer(layer.go)는 stack의 띠로 unit을 한 layer에만 두고, Breaches는 아래 layer의 unit이 위 layer의 unit을 쓰는 relation을 나열한다. Row(table.go)는 table의 행이고, Readings가 칸을 relation과 맞춰 Unbacked와 Unsaid를 찾는다.

Language

  • Language (internal/model/language.go): 사람이 저장된 산문을 읽는 언어로, ko, en-US, zh-Hant 같은 정규 대소문자의 BCP-47 태그이며 빈 값은 설정이 없다는 뜻이다. ParseLanguage는 공백을 자르고 _를 -로 바꾼 뒤 언어, 선택적 script, region, variant 형태를 검사해 정규 대소문자로 돌려주고, 맞지 않으면 error를 낸다. UnmarshalText도 같은 검사를 하므로 project.yaml의 나쁜 태그는 그것을 읽는 로드를 멈춘다. DefaultLanguage는 먼저 OS 로캘을 읽는다. Git for Windows 같은 POSIX 셸이 한국어 Windows에서도 LANG=en_US.UTF-8을 내보내므로 Windows 로캘이 LANG보다 앞선다. 그다음 LC_ALL, LC_MESSAGES, LANG 순으로 POSIX 로캘을 읽고(C와 POSIX는 언어가 없다고 본다), 마지막으로 FallbackLanguage(en)를 준다. OS 로캘은 osLocale로, Windows(language_windows.go)에서는 kernel32.dll을 이름으로 불러 GetUserDefaultLocaleName을 호출하고, 다른 OS(language_other.go)에서는 빈 문자열이다. Script는 script subtag가 가리키는 문자, 없으면 언어 subtag의 문자를 unicode.RangeTable로 준다. Latin 언어도 언어 subtag 표에 이름으로 올라 있고, 두 표 모두 모르는 언어(ka, hy, ta 등)는 nil이라 그 언어의 산문은 판정하지 않는다. 산문이 그 문자로 쓰였는지 재는 일은 이 패키지가 하지 않는다.

    키와 앵커DATA-0020 internal/model/model.go

  • evidence citation 인터페이스
    An evidence item is a path, optional lines such as 120 or 120-134, optional symbol and a verbatim quote, written PATH:LINES:QUOTE on the command line, and may not cite .abbd or .git files.
    키와 앵커IF-0017 internal/model/model.go ParseEvidence, internal/model/model.go Validate
  • guess versus topology rule 모듈
    A unit is semantic when its name is INFERRED; a relation counts as topology only when it is live and EXTRACTED or USER_STATED, and is a guess when INFERRED.
    키와 앵커MOD-0031 internal/model/model.go Counts, internal/model/model.go Semantic
  • relation grammar 모듈
    The table of which unit kinds each relation kind may join (a module or feature provides a contract, anything consumes a contract, anything depends_on any unit) and the list of allowed via values.
    키와 앵커MOD-0032 internal/model/model.go ends, internal/model/model.go vias
  • fact origins 모듈
    Defines the EXTRACTED, INFERRED and USER_STATED origins and enforces that a why-field is never EXTRACTED and that exactly the USER_STATED facts carry a source.
    키와 앵커MOD-0033 internal/model/model.go sourced, internal/model/model.go validate
