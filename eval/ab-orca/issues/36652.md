# [Feature]: Configurable separator between branch prefix and worktree name (#36652)

### Problem or use case

The branch prefix is always joined with a slash: `computeBranchName` in `src/main/ipc/worktree-branch-name.ts` returns `${prefix}/${sanitizedName}`. Teams whose convention uses a dash (`jd-feat-login-form` rather than `jd/feat-login-form`) cannot use the prefix setting, and have to edit the branch field by hand on every new workspace or pass `--branch` from the CLI.

### Proposed solution

Add a `branchPrefixSeparator` setting next to the custom prefix in Settings > Git, defaulting to `/` so existing setups are unchanged. With prefix `jd` and separator `-`, typing `feat: login form` produces the branch `jd-feat-login-form`.

The separator would go through the same check as the prefix (`getBranchPrefixIssue`), and `getConfiguredBranchPrefix` callers that strip an existing prefix to avoid double-prefixing would need to use it too.

### Alternatives or additional context

Including the separator in the custom prefix itself (`jd-`) would avoid a new setting, but `normalizeBranchPrefix` only trims slashes, and the join would still add one: `jd-/feat-login-form`.

Related: #18103 (per-project prefix), #5082 (folder template, whose branch token would inherit the separator)
