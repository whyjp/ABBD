# [Feature]: Expose agent and workspace status colors as plugin theme tokens (#36697)

### Problem or use case

A plugin app theme can set the public tokens in `docs/reference/plugin-theme-tokens.md`, but the agent and workspace status colors are not among them. `main.css` hard-codes `--agent-working` (yellow-500), `--agent-question` (orange), `--workspace-status-done/review/progress` and `--status-success/warning`, and the themes page says other variables cannot be set.

So a monochrome theme (ours is black and white with a single lime accent) still shows yellow and orange dots on every working or waiting workspace card, which is the most visible color in the sidebar.

### Proposed solution

Add these to the public theme tokens, with today's values as the fallback when a theme omits them:

- `--agent-working`, `--agent-question`, `--agent-question-text`
- `--workspace-status-done`, `--workspace-status-review`, `--workspace-status-progress`
- `--status-success`, `--status-warning` (their `-background`/`-border` tints are already derived with `color-mix`)

The existing opacity/contrast checks can apply as for the other tokens.

### Alternatives or additional context

A user `custom.css` (#21579) would also cover it, but plugin themes, with their token checks, are where teams ship a shared look.
