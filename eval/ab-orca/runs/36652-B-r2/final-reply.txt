A separate reviewer agent found no blocking problems. I applied one suggestion: auto-rename now looks up the git username only when the prefix comes from it, as workspace creation already does. That needed one shared test setup file to include `branchPrefix`, which real settings always have.

**Open decision**
The reviewer also found a limitation, written up in `PR.md`. With a non-slash separator, a branch like `jdoe-crab` is never auto-renamed in two cases:
- The git username lookup comes back empty at rename time.
- You change the prefix or separator after the branch was created.

The `/` separator isn't affected. Fixing the first case means retrying later instead of giving up, which changes how auto-rename retries in general. I left that for a follow-up. If you want it in this PR, I can add it.
